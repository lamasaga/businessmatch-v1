### 推荐开场模板

<!--
  每次开新会话时，用 2-3 句话主动告诉 AI 当前任务的范围。
  格式不固定，但应包含以下三要素：
    ① 做什么（任务描述）
    ② 属于哪个 Phase（A/B/C/D/E）
    ③ 涉及哪些域（arena / trading / career / identity / cybercore / opc …）

  示例 ──────────────────────────────────────────────────

  示例 1（小功能）:
  "正式赛结束后自动弹出排行榜弹窗。Phase A，涉及 arena + trading，
   前端 TradingGamePage + competitionStore，不新增路由。"

  示例 2（新赛制）:
  "新增投资人对决赛制 investor-duel。Phase A，走 CyberCore 标准流程：
   新建 game-configs/investor-duel.yaml + games/investor_duel/ engine。"

  示例 2b（练习/正式/地区配置）:
  "创想大赢家 · 美国正式赛配置包。Phase A，仅新增 techventure-official-us.yaml，
   engine 仍为 techventure；不改 practice_flow。见 02- §5.0。"

  示例 3（跨域功能）:
  "练习赛结束后往 career 域写入 XP。Phase A → B 交界，
   涉及 arena + career，调用 settle_match_rewards，不直接操作 users 表。"

  示例 4（纯前端）:
  "重构生涯页读取真实 XP 数据，替换 mock。Phase A，
   涉及 careerStore + 新增 /career API 路由，需先更新 08- §2.7。"

  示例 5（文档 / 规划）:
  "梳理 Phase B 的 Quest 系统设计方案，不写代码，只更新 03- 和 04-。"
-->

### 注意事项

<!--
  1. 规则是兜底护栏，开场声明是主动导航
     .cursor/rules/ 下的规则会自动注入，但 AI 不一定精确推断你的意图。
     主动声明 Phase + 域 比依赖 AI 自行推理可靠得多。

  2. 大任务先切片
     如果一次会话要跨 3 个以上域或改动 10+ 文件，建议先拆成
     "本次只做 XX 部分"，下一轮再做剩余。避免 AI 上下文过载导致遗漏。

  3. 不确定就问
     如果你不确定任务属于哪个 Phase 或涉及哪些域，可以直接问 AI：
     "帮我判断这个任务的 Phase 和域范围"。
     blueprint-coding.mdc §9 要求 AI 在有疑问时主动确认。

  4. Phase 推进时刷新规则
     当项目从 Phase A 进入 Phase B 时，提醒 AI 更新
     blueprint-coding.mdc §7 的"当前"标记，以及 §1 域表（如需新增域）。

  5. 探索性工作用 Plan 模式
     如果任务是"调研方案 / 设计架构 / 对比选型"，可以在开场时说
     "本次只做规划，不写代码"，AI 会切换到只读模式，避免过早产出代码。

  6. 推送前文档对齐是强制的
     参见 .cursor/rules/docs-align-before-push.mdc。
     大型更新后说"推送到 GitHub"时，AI 会自动先走文档对齐流程。

  7. 避免在会话中途大幅变更目标
     AI 的上下文窗口有限。如果上半场在修 trading bug，下半场突然要
     重构 career 域，建议开新会话，并在开场重新声明范围。

  8. 重大选型后写 ADR
     换技术方案、改域边界、推翻旧做法时，见 docs/decisions/README.md §二。
     不必记编号：让 AI「按 adr-writing 规则检查本次要不要写 ADR」即可。
     涉及已有决策时 @ 对应文件，如 docs/decisions/005-浮生记RTS调度器单写者.md
-->
