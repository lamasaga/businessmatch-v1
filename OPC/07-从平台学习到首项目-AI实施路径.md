## 一、总览：一条「首项目」漏斗

　　OPC 的核心不是「多一个聊天机器人」，而是让学生在**具备商业素养与实战手感之后**，以**管理者**身份运营「一人公司」，用 **AI 数字员工团队**完成真实或半真实的交付物，完成**人生第一个可展示、可验收、可迭代的项目**。

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    Career Hub（生涯中枢 · 统一档案）                      │
│         XP / 五维能力 / Persona / Athena 全局导师 / 解锁与认证            │
└───────────────────────────────────┬─────────────────────────────────────┘
                                    │
     ┌──────────────┬───────────────┼───────────────┬──────────────┐
     ▼              ▼               ▼               ▼              │
┌─────────┐  ┌─────────┐    ┌─────────┐    ┌─────────────────┐      │
│ ① 知识   │→ │ ② 商赛   │ →  │ ③ 解锁   │ →  │ ④ OPC 首项目     │      │
│  Atlas  │  │  Arena  │    │ Gateway │    │ IDEATE→…→BUILD  │      │
│ +Athena │  │+Demia/  │    │ +启航仪式│    │ AI Agency 交付  │      │
│         │  │ Rival   │    │         │    │                 │      │
└─────────┘  └─────────┘    └─────────┘    └─────────────────┘      │
     │              │               │               │                  │
     └──────────────┴───────────────┴───────────────┴──────────────────┘
                         事件总线 · MCP · 共享 user_id / career_id
```

### 1.1 「第一个项目」在 OPC 中的定义

| 维度 | 定义 |
|------|------|
| **产品形态** | 学生选定方向后的 **MVP**（可 Web 应用、服务包、内容产品、小程序等） |
| **教育目标** | 走完「想法 → 验证 → 做出能用的东西」，而非必须盈利 |
| **推荐终点（K12～高职）** | 至少完成 **IDEATE + VALIDATE + BUILD（内测版）**；LAUNCH 可选（真实流量/收入） |
| **交付物** | BMC、竞品报告、着陆页、可运行 Demo/仓库、用户反馈摘要、Gateway 评审通过记录 |
| **AI 角色** | 13 类 AI 员工分工产出；学生负责决策、验收、迭代；Athena/Cortex 负责教练与门禁 |

### 1.2 与三层「真实」递进

| 层级 | 平台模块 | 「真实」程度 |
|------|----------|--------------|
| 模拟层 | Atlas、Academy、多数商赛 | 概念与决策真实，结果虚拟 |
| 半真实层 | Rival 谈判、VALIDATE 用户访谈、BUILD 沙箱部署 | 接触真人或真实环境，低风险 |
| 真实层 | LAUNCH/SCALE、支付 MCP、真实收入 | 真实货币与真实用户（需 Gateway + 伦理审核） |

## 二、阶段一：知识学习（Atlas + Athena）

### 2.1 目标

　　建立商业语言与概念网络，为商赛决策和创业任务提供**共同知识底座**；AI 不替学生做题，而是**诊断薄弱点、推送路径、考后关联**。

### 2.2 学生活动

| 活动 | 平台域 | 产出 |
|------|--------|------|
| 学习概念卡 / Wiki | Atlas | `mastery` 掌握度 |
| 完成课程单元 | Academy | 单元成绩、素养标签 |
| 每日 Quest（概念应用题） | Quest | streak、轻反思 |
| 向 Athena 提问 | Athena | 学习记录（无直接给答案） |

### 2.3 AI 如何辅助（实施要点）

| AI 能力 | 实现方式 | 与 OPC 的衔接 |
|---------|----------|----------------|
| **个性化路径** | Mercury + `OPC-atlas.query_knowledge`：按薄弱节点推荐下一单元 | IDEATE 前自动推荐「创业相关」节点包 |
| **苏格拉底辅导** | Athena RAG（知识卡片 + 13- 规范） | 创业词汇、BMC 概念预习 |
| **掌握度门禁** | Atlas `unlock_node` 作为 AI 员工技能前提 | 例：未掌握「供需/定价」不解锁 FIN-01 L2 |
| **自动出题/测验** | 基于 YAML 卡片生成应用题（模板 + LLM 审核） | Quest 与课程测验共用题库 |

### 2.4 进入下一阶段的信号

- 五维能力均分 ≥ 70，或完成 `entrepreneurship_101` 等创业入门单元（见 `platform-integration/03-解锁与认证对接.md`）
- 关键图谱节点：供需、成本、商业模式画布、基础财务等达到阈值

## 三、阶段二：商赛练习（Arena + Demia/Rival + Athena）

### 3.1 目标

　　在**低风险、可复盘**环境中练习商业决策、谈判与多人/人机博弈；沉淀**决策日志与策略风格**，供 OPC 解锁与 AI 员工初始等级使用。

### 3.2 学生活动

| 活动 | 赛制示例 | AI 组件 |
|------|----------|---------|
| 回合制/宏观/ESG 等 | CyberCore 对局 | **Demia POP**（市场人群反应） |
| 产业链/拍卖/融资 | 练习模式 | **Rival** 多轮谈判 |
| 赛后 | 任意排位/教学局 | **Athena Debrief**（反思题 + 图谱链接） |

### 3.3 AI 如何辅助（实施要点）

| 场景 | AI 做什么 | 教育边界 |
|------|-----------|----------|
| **Demia** | 规则层算满意度；LLM 只写舆情叙事 | 排位局内不给最优数值建议 |
| **Rival** | 人格化对手 + 结构化 `deal_terms` | 练习榜与 ELO 分离 |
| **Athena 复盘** | 读 `decision_logs`，出事实层 + 3 道反思题 | 引用学生自己的理由 |
| **商赛 → OPC 迁移** | `arena.competition.ended` → 初始资源包 | 如 TECH 路线大师 → DEV-01 初始 L+1 |

### 3.4 进入 OPC 的触发（商赛路径）

- 在「创业生存战」「投资人对决」等赛制排名 **前 30%**
- 或满足能力/课程/徽章组合（**任一即可解锁**，见 `05-与现有平台融合路径.md`）

### 3.5 与「首项目」的关系

　　商赛**不是**第一个项目本身，而是**能力试炼场**：证明学生在不确定性下能做决策；真正「项目」从 OPC 的 IDEATE 开始产出可交付物。

## 四、阶段三：OPC 学习（AI 员工局 + 流水线）

### 4.1 目标

　　让学生掌握 **「管理者-执行者」** 交互模型（见 `ai-employee-design/04-人机交互协议.md`）：会写任务 brief、会验收、会迭代——而不是只会和 ChatGPT 聊天。

### 4.2 核心机制（OPC 专属 AI）

| 机制 | 说明 |
|------|------|
| **AI 员工局（Agency）** | 13 个角色（BA-01、CP-01、DEV-01…）+ Cortex 战略大脑 |
| **任务生命周期** | pending → in_progress → review → approved（`task-engine/01`） |
| **LangGraph 工作流** | 单员工任务流 / 多员工协作流（`code-skeleton/04`） |
| **MCP 工具层** | memory / atlas / sandbox / deploy / ethos / report |
| **Gateway 评审** | AI 委员会 + 可选教师 L1 终审，阶段门禁 |

### 4.3 OPC「学习」阶段学什么（_META 技能）

　　在做出公司之前，平台可提供 **OPC 教程线**（短周期，约 1～2 周）：

| 模块 | 内容 | AI 辅助方式 |
|------|------|-------------|
| M1 雇佣与分工 | 人才市场、岗位说明 | 模拟雇佣 1 个 BA-01，完成微型任务 |
| M2 写任务 brief | YAML 任务模板 | Cortex 把自然语言解析为结构化需求 |
| M3 验收与评分 | 交付物检查清单 | Athena 教「如何给可执行反馈」 |
| M4 伦理与安全 | 沙箱、Ethos | OPC-ethos 拦截违规内容与高风险创业方向 |
| M5 模拟公司 Sprint | 全程模拟币 | 走完 IDEATE 缩略版（3 天） |

　　完成后发放 **「OPC 见习创始人」** 徽章，再进入正式「第一家公司」。

### 4.4 与全局 Athena 的分工

| 角色 | 职责 | 何时介入 |
|------|------|----------|
| **Athena** | 生涯教练、跨域复盘、解锁仪式、周计划 | 全局；不代管员工日常执行 |
| **Cortex** | 公司内战略拆解、阶段目标、任务计划 | OPC 公司创建后 |
| **各 AI 员工** | 执行具体交付物 | 学生指派任务后异步执行 |

## 五、阶段四：孵化第一个项目（IDEATE→BUILD 主线）

### 5.1 推荐主线（学期内可完成）

　　以 `03-创业孵化流水线.md` 为准，**首项目**建议默认打包到 **BUILD 结束**（含内测），LAUNCH 作为进阶选修。

| 阶段 | 周期（参考） | 学生「第一个项目」累积产出 | 主力 AI 员工 |
|------|--------------|---------------------------|--------------|
| **IDEATE** | 1～2 周 | BMC、竞品矩阵、品牌方案 v1 | BA-01、CP-01、Scout |
| **VALIDATE** | 2～3 周 | 着陆页、假门/预约数据、访谈摘要 | COPY-01、DES-01、GRW-01、Scout |
| **BUILD** | 3～5 周 | **MVP 仓库/可访问 URL**、README、内测反馈 | DEV-01、DES-01、QA-01 |
| LAUNCH（可选） | 2+ 周 | 首批真实用户、收入 0→1 | GRW-01、FIN-01 + OPC-deploy |

### 5.2 每个阶段的 AI 闭环（实施模板）

```
学生定目标（含在阶段 Brief 里）
    → Cortex 拆任务 → 学生指派给员工
    → LangGraph 执行（LLM + MCP：atlas/memory/sandbox…）
    → OPC-ethos 审核输出 → 交付物入库
    → 学生验收（评分 + 文字反馈）→ 员工迭代（≤N 轮）
    → Gateway 评审（AI + 可选教师）
    → 通过则 OPC.stage.completed → Career +XP / 徽章
    → Athena 阶段复盘 + 推荐下一阶段任务
```

### 5.3 「第一个项目」最低验收标准（建议）

| 序号 | 交付物 | 验收方式 |
|------|--------|----------|
| 1 | 完整 BMC（9 宫格无空） | Gateway 1 自动检查 + AI 差异化评分 |
| 2 | 验证数据（≥50 次着陆页访问或 ≥10 份有效反馈） | 数据看板 + Scout 摘要 |
| 3 | 可运行 MVP | OPC-sandbox 测试通过 + OPC-deploy 预览链接 |
| 4 | 学生复盘报告 | Athena 引导模板 + 自主撰写 |
| 5 | 展示包 | 一键导出 PDF/作品集（OPC-report） |

　　通过后写入 Credenti：**「一人公司 · 首项目完成」** 微证书，并反哺 Career 雷达「创业力」维度。

### 5.4 商赛与 OPC 在同一项目上的分工（避免重复）

| 能力 | 在商赛练什么 | 在 OPC 首项目练什么 |
|------|-------------|---------------------|
| 定价/市场 | 回合内数字决策 | 真实/半真实着陆页转化 |
| 团队协作 | 多人队伍角色 | 管理 AI 团队分工 |
| 财务 | 模拟报表 | 简易真实成本账（BUILD+） |
| 谈判 | Rival 对话 | 供应商/用户访谈脚本 |
| 产出物 | 排名与复盘 | **仓库、网页、文档** |

## 七、技术实施：AI 如何落地

### 7.1 推荐技术栈（与 OPC 文档一致）

| 层级 | 选型 | 用于 |
|------|------|------|
| 编排 | **LangGraph** | 任务状态机、中断恢复、人机协同暂停 |
| 多角色原型 | CrewAI / 自研角色配置 | 早期验证；生产以 LangGraph + MCP 为主 |
| 工具协议 | **MCP**（FastMCP） | OPC-memory / atlas / sandbox / deploy / ethos |
| 模型路由 | **LiteLLM** | 多模型、配额、按校计费 |
| 记忆 | Mem0 或 pgvector + `OPC-memory` | 员工级记忆 |
| 沙箱 | OpenSandbox / gVisor | DEV 员工代码执行 |
| 队列 | Celery + Redis | 异步任务、Debrief、Gateway |
| 事件 | CloudEvents（`OPC.*`） | 与 Career/Arena 同步 |

### 7.2 三条关键数据流

**流 A：学习 → 解锁 OPC**

```
Atlas.mastery + Academy.progress + Arena.logs
    → OPCUnlockEngine.check_eligibility()
    → career.OPC.unlocked
    → Athena 启航对话 + 创建 one_company（模拟/实战模式）
```

**流 B：学生派任务 → AI 交付**

```
POST /opc/tasks → OPC.task.created
    → LangGraph execute_task()
    → MCP 调用 + OPC-ethos 审核
    → OPC.task.completed → 学生 review → OPC.task.reviewed
    → OPC.stage.* / career.xp.awarded
```

**流 C：商赛沉淀 → OPC 初始资源**

```
arena.match.finished → 解析策略标签
    → 映射员工初始等级/模拟资金包
    → 写入 company.legacy_json
```

### 7.3 AI 成本与校内可运营策略

| 策略 | 说明 |
|------|------|
| 分层模型 | 草稿用便宜模型，Gateway/终稿用强模型 |
| 异步优先 | 员工任务默认队列，避免课堂同时触发数千次同步 LLM |
| 校额配额 | 每 `organization_id` 月 Token 上限 |
| 模板化 | Gateway 检查项 70% 规则化，30% LLM |
| 教师开关 | 可关闭 Demia 叙事、限制 LAUNCH 真实支付 |

## 九、分阶段实施建议（可执行）

### Phase A（4～6 周）：打通「学习 → 商赛 → 解锁 → IDEATE」

1. Career 真实表 + `OPCUnlockEngine`（任一条件解锁）  
2. Athena：解锁仪式对话 + 阶段复盘 API  
3. 创建 `one_company` 时从 Career 拉 Persona / mastery 预填  
4. IDEATE 任务模板 + 仅开放 BA-01、CP-01、Scout  
5. Gateway 1 规则化检查（BMC 完整性）  
6. 事件 `OPC.company.created` → Career +100 XP  

### Phase B（6～10 周）：首项目 MVP（VALIDATE + BUILD）

1. 接入 `OPC-atlas`、`OPC-memory` MCP（读平台图谱）  
2. LangGraph 单员工任务流 + Celery  
3. `OPC-sandbox` / `OPC-deploy` 最小闭环（预览 URL）  
4. VALIDATE 着陆页任务链（COPY + DES）  
5. BUILD：DEV-01 代码任务 + 学生验收 UI  
6. OPC-report 导出「首项目展示包」  

### Phase C（10～16 周）：商赛联动 + 教师看板

1. Arena 成绩 → 初始资源包映射  
2. 「一人公司挑战赛」赛制 YAML（12 周联赛）  
3. 教师 OPC Tab（风险列表 + Gateway 批量审阅）  
4. OPC-ethos 全量接入 + 可选 LAUNCH 真实支付 MCP

## 十、给产品/教研的一句话总结

　　**知识学习**用 Athena + Atlas 打底；**商赛练习**用 Demia/Rival 练决策与谈判并产出日志；达到条件后 **OPC 解锁**，学生在 AI 员工局里以管理者身份走完 IDEATE→VALIDATE→BUILD，**第一个项目** = 可验证 BMC + 验证数据 + 可运行 MVP + 评审与证书；全程由 **LangGraph + MCP + 事件总线** 实施，与 Career 成长体系同一账户、同一叙事。
