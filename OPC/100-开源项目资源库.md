## 一、AI Agent / Multi-Agent 框架

### 1.1 LangGraph ⭐ 核心推荐

| 属性 | 详情 |
|------|------|
| **仓库** | `langchain-ai/langgraph` |
| **Stars** | 16,000+ |
| **License** | MIT |
| **语言** | Python / TypeScript |
| **官网** | https://langchain-ai.github.io/langgraph/ |

**核心能力**：
- 图状态机编排：显式节点 + 条件边，支持循环、分支、Human-in-the-Loop
- 内置检查点（checkpointing）：状态持久化，支持崩溃恢复和"时间旅行"调试
- 流式支持：per-node token streaming
- LangSmith 原生集成：生产级可观测性

**与 OPC 的关联**：OPC 已选定 LangGraph 作为核心工作流引擎。可直接复用其状态管理、中断恢复、流式输出能力。

**建议用法**：
- AI 员工任务执行工作流（`04-LangGraph工作流骨架.py` 可直接对接）
- 多智能体协作流（Cortex 作为 Manager 节点调度各 AI 员工）
- 学生审核中断点（`interrupt` 节点实现 Human-in-the-Loop）

## 三、沙箱 / 安全代码执行

### 3.1 OpenSandbox ⭐ 重点推荐

| 属性 | 详情 |
|------|------|
| **仓库** | `alibaba/OpenSandbox` |
| **Stars** | 7,873（2025-12 创建，增长迅速） |
| **License** | Apache-2.0 |
| **语言** | Python（服务端）+ 多语言 SDK |
| **发起方** | 阿里巴巴 |

**核心能力**：
- 通用 AI 沙箱平台：代码执行、浏览器自动化、GUI Agent、RL 训练
- 多语言 SDK：Python、Java/Kotlin、TypeScript、C#/.NET、Go
- 统一沙箱生命周期 API：创建、暂停、恢复、快照、删除
- 多种隔离后端：**gVisor**、Kata Containers、**Firecracker** microVM
- 网络策略：每沙箱独立的 egress 控制
- **内置 MCP Server**：暴露沙箱创建、命令执行、文件操作给 MCP Client

**与 OPC 的关联**：与 OPC 的 `OPC-sandbox` MCP Server 需求**几乎完全重合**！且支持 gVisor/Firecracker（OPC 文档中已选型）。

**建议用法**：
- **强烈推荐评估**：OpenSandbox 可作为 OPC-sandbox 的底层基础设施，避免从零搭建 Firecracker/gVisor 集群
- 其 MCP Server 实现可直接参考或复用
- 注意：2025-12 才开源，生态较新，需评估社区活跃度

|------|------|-------|----------|--------|----------|

- **高安全需求**：Firecracker via Kata Containers（硬件隔离 + K8s API）
