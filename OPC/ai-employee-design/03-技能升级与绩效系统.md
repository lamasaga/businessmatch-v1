## 一、系统设计总则

### 1.1 设计哲学

AI 员工的升级系统遵循三个核心原则：

1. **教育映射**：升级路径映射真实职场成长轨迹，让学生在"管理 AI"的过程中学习"如何管理团队"。
2. **投入对等**：AI 员工的成长需要学生的持续投入（反馈、授权、挑战性任务），模拟真实管理中"培养下属"的体验。
3. **可见进步**：成长过程必须是可见、可感知、可回顾的，学生能清晰看到"我的团队变强了"。

### 1.2 核心概念

| 概念 | 定义 | 类比 |
|------|------|------|
| **经验值（XP）** | 完成任务、获得好评、达成里程碑时积累的数值 | 真实员工的工龄+项目经验 |
| **技能点（SP）** | 用于提升具体技能等级的资源 | 培训预算、学习时间 |
| **绩效分（PS）** | 基于交付质量和学生满意度的综合评分 | 年度绩效考核 |
| **等级（L1-L5）** | 综合 XP、SP、PS 后的职级认定 | 实习生→专员→资深→专家→合伙人 |
| **技能树** | 每个角色的技能分支结构与升级路径 | 职业发展路径图 |

## 三、经验值（XP）获取规则

### 3.1 XP 来源矩阵

| XP 来源 | 基础值 | 乘数条件 | 上限/周期 |
|---------|--------|----------|-----------|
| **完成任务** | 50-500 XP | 任务难度 × 交付质量 | 无上限 |
| **学生好评** | 100 XP/⭐ | 5⭐ = 500 XP | 每任务 1 次 |
| **里程碑达成** | 1000-5000 XP | 阶段权重 | 每里程碑 1 次 |
| **技能使用** | 10 XP/次 | 新技能首次使用 ×3 | 每日 100 XP |
| **知识分享** | 200 XP | 生成可复用模板/文档 | 每周 1000 XP |
| **学生反馈采纳** | 150 XP | 学生明确标注"采纳建议" | 每任务 3 次 |
| **跨角色协作** | 50 XP/次 | 主动发起协作 ×2 | 每日 200 XP |
| **失败学习** | 100 XP | 任务失败后输出复盘文档 | 每失败 1 次 |

### 3.2 任务难度分级与 XP

```yaml
task_difficulty_xp:
  trivial:     # 简单任务（< 1小时）
    base_xp: 50
    examples: ["修改按钮文案", "调整配色"]
  
  easy:        # 标准任务（1-4小时）
    base_xp: 150

  medium:      # 复杂任务（4-8小时）
```

### 3.3 交付质量乘数

| 质量评级 | 乘数 | 判定标准 |
|----------|------|----------|
| S（卓越） | ×1.5 | 超出预期，学生主动表扬，可复用为模板 |
| A（优秀） | ×1.2 | 完全符合要求，无需修改直接验收 |
| B（良好） | ×1.0 | 基本符合，有小修改 |
| C（合格） | ×0.7 | 需要明显修改，方向正确但执行有偏差 |
| D（不合格） | ×0.3 | 需要重做，方向错误或严重遗漏 |
| F（失败） | 0 | 未交付或完全不可用 |

### 3.4 里程碑 XP 奖励

| 里程碑 | 基础 XP | 阶段权重 | 备注 |
|--------|---------|----------|------|
| Gateway 1（创意评审通过） | 2000 | ×1.0 | IDEATE 阶段 |
| Gateway 2（需求验证通过） | 3000 | ×1.2 | VALIDATE 阶段 |
| Gateway 3（MVP 技术验收） | 4000 | ×1.5 | BUILD 阶段 |
| Gateway 4（首笔收入） | 5000 | ×2.0 | LAUNCH 阶段 |
| Gateway 5（毕业认证） | 10000 | ×3.0 | SCALE 阶段 |

**团队加成**：里程碑达成时，所有参与的 AI 员工获得同等 XP，激活中的角色额外获得 20% 团队加成。

## 四、等级提升条件

### 4.1 等级门槛总览

| 等级 | 名称 | 所需累计 XP | 所需技能点 SP | 绩效要求 | 特殊条件 |
|------|------|------------|--------------|----------|----------|
| L1 | 实习生 | 0 | 0 | — | 默认解锁 |
| L2 | 专员 | 2,000 | 3 | 平均分 ≥ 3.0 | 完成 5 个任务验收 |
| L3 | 资深 | 8,000 | 8 | 平均分 ≥ 4.0 | 完成 20 个任务，满意度 > 4.5 |
| L4 | 专家 | 25,000 | 15 | 平均分 ≥ 4.5 | 完成 50 个任务，主导 1 个里程碑 |
| L5 | 合伙人 | 60,000 | 25 | 平均分 ≥ 4.8 | 项目月收入 > 5000 元 或 等效毕业标准 |

### 4.2 升级流程

```yaml
level_up_process:
  step_1: 系统检测是否满足等级门槛
  step_2: 触发"升级评估任务"——学生需为该 AI 员工指派一个"挑战性任务"
  step_3: AI 员工完成挑战任务，进入学生评审
  step_4: 评审通过（≥4.0分）→ 升级成功
  step_5: 评审未通过 → 保留当前等级，30天后可再次申请
  
  special_mechanics:
    learning_resources: "学生可将知识图谱中的节点'授权'给员工学习（消耗模拟币，提升技能升级速度）"
    mentor_bonus: "如果人类导师在评审中给出推荐，升级所需 XP 减少 10%"
    peer_review: "L4→L5 需要另一位 L4+ AI 员工的'同行评议'"
```

| 维度 | 权重 | 定义 | 评分标准 |
|------|------|------|----------|
| **交付质量** | 30% | 交付物的完整性、准确性、专业性 | 5⭐ = 可直接使用；3⭐ = 需要修改；1⭐ = 方向错误 |
| **时效性** | 20% | 是否按时或提前完成 | 5⭐ = 提前完成；3⭐ = 按时；1⭐ = 严重超时 |
| **创新性** | 15% | 是否提出超出预期的见解或方案 | 5⭐ = 令人惊喜；3⭐ = 符合预期；1⭐ = 机械执行 |
| **学生满意度** | 25% | 整体主观满意度 | 5⭐ = 非常满意；3⭐ = 基本满意；1⭐ = 不满意 |
| **协作性** | 10% | 与其他 AI 员工的配合度 | 5⭐ = 主动协作；3⭐ = 配合良好；1⭐ = 产生冲突 |

### 5.2 绩效计算公式

```python
def calculate_performance_score(ratings, task_difficulty):
    """
    ratings: dict with keys: quality, timeliness, innovation, satisfaction, collaboration
    task_difficulty: 'trivial' | 'easy' | 'medium' | 'hard' | 'epic'
    """
    weights = {
        'quality': 0.30,
        'timeliness': 0.20,
        'innovation': 0.15,
        'satisfaction': 0.25,
        'collaboration': 0.10
    }
    
    base_score = sum(ratings[k] * weights[k] for k in weights)
    
    # 难度加成：困难任务的高分更有价值
    difficulty_bonus = {
        'trivial': 0,
        'easy': 0.1,
        'medium': 0.2,
        'hard': 0.3,
        'epic': 0.5
    }
    
    # 只有基础分 ≥ 4.0 时才应用难度加成
    if base_score >= 4.0:
        final_score = min(5.0, base_score + difficulty_bonus[task_difficulty])
    else:
        final_score = base_score
    
    return round(final_score, 2)
```

```yaml
    - trigger: "连续 4 个任务 < 3.0"

    - trigger: "连续 5 个任务 < 3.0"

```

### 6.2 降级流程

```
连续低绩效 → 预警通知 → 改进计划 → probation（30天）
    ↓
改善达标 → 恢复正常
    ↓
未改善 → 降级（L2→L1 或 L3→L2）
    ↓
连续降级到 L1 且仍无改善 → 冻结
```

### 6.3 冻结机制

| 冻结类型 | 触发条件 | 后果 | 解冻条件 |
|----------|----------|------|----------|
| **学生主动冻结** | 学生手动选择 | 该员工暂停接任务，不消耗资源 | 学生手动解冻 |
| **系统冻结** | L1 连续 5 个任务 < 2.0 | 强制暂停，需完成"再培训任务" | 再培训任务通过评审 |
| **安全冻结** | 触发安全红线（如生成违规内容） | 立即停止，通知平台运营 | 安全委员会审核通过 |
| **资源冻结** | 学生超出同时管理上限（12人） | 新解锁员工无法激活 | 冻结其他员工释放名额 |

```sql
AFTER INSERT ON PerformanceReview
FOR EACH ROW
BEGIN
  -- 如果该员工最近任务表现优秀，检查 XP 和 SP 是否达标
  IF NEW.overall_score >= 4.0 THEN
    CALL evaluate_level_eligibility(NEW.agent_id);
```
