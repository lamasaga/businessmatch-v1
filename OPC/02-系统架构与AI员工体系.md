### 1.2 核心子系统定义

| 子系统 | 代号 | 核心职责 | 关键特性 |
|--------|------|----------|----------|
| **AI员工局** | Agency | 管理学生的AI数字员工团队 | MCP标准、角色定义、任务分配、成果验收 |
| **战略大脑** | Cortex | 高阶规划与决策支持 | 目标拆解、策略生成、风险预警 |
| **执行员工** | Worker | 具体任务的自动化执行 | 代码生成、文案撰写、设计产出、数据分析 |
| **专业顾问** | Advisor | 领域专家级咨询 | 法律、财务、营销、技术的深度建议 |
| **市场探员** | Scout | 市场情报与用户反馈收集 | 竞品监控、趋势分析、用户调研 |
| **创业流水线** | Pipeline | 从创意到运营的完整流程 | 阶段门禁、里程碑评审、资源匹配 |
| **连接器** | Connector | 对接外部真实世界服务 | API集成、支付、部署、社媒 |
| **MCP路由** | Router | AI Agent与工具的协议层 | 标准化工具调用、安全隔离、权限管理 |
| **记忆系统** | Memory | AI员工的长期记忆 | 向量存储、对话历史、项目上下文 |

## 二、AI 员工体系：核心创新

### 2.1 设计哲学：从 NPC 到 Employee

现有平台中的 AI（Athena、Demia、Rival）本质上是**教学辅助角色**——它们对话、提示、模拟，但不**执行**。

OPC 的 AI 员工是**真正的协作者**——它们有岗位、有 KPI、有交付物、有记忆，学生是它们的「管理者」而非「对话者」。

```
传统教育AI                      OPC AI员工
┌─────────────────┐            ┌─────────────────┐
│ 你问我答        │            │ 你派活我交付    │
│ 给你建议        │     →→→    │ 给我验收        │
│ 模拟对手        │            │ 并肩作战        │
│ 课后复盘        │            │ 实时执行        │
└─────────────────┘            └─────────────────┘
```

### 2.4 AI 员工的能力边界与升级机制

**能力等级**：

| 等级 | 名称 | 特征 | 解锁条件 |
|------|------|------|----------|
| L1 | 实习生 | 可执行简单任务，需频繁确认 | 默认解锁 |
| L2 | 专员 | 可独立完成标准任务 | 完成5个任务验收 |
| L3 | 资深 | 可主动优化方案，提出改进建议 | 完成20个任务，满意度>4.5 |
| L4 | 专家 | 可跨领域协作，承担项目管理 | 完成50个任务，项目上线 |
| L5 | 合伙人 | 可自主制定策略，相当于联合创始 | 公司月收入>5000元 |

**升级不是自动的**——学生需要像管理真实员工一样：
- 给予明确反馈（验收时写评审意见）
- 提供学习资源（将知识图谱中的相关节点「授权」给员工学习）
- 设定挑战性任务（超出当前等级的任务尝试）

## 三、MCP（Model Context Protocol）集成架构

### 3.1 为什么用 MCP

MCP 是连接 AI Agent 与外部工具的**开放标准协议**，类比为「AI 的 USB-C」。

在教育场景中使用 MCP 的核心价值：
1. **标准化**：不同 AI 员工使用同一套工具调用协议，降低系统复杂度
2. **可扩展**：新增工具只需实现 MCP Server，无需改动 Agent 逻辑
3. **安全性**：通过 MCP 的权限模型，学生只能访问被授权的工具
4. **真实感**：学生管理的 AI 员工调用的是**真实世界的工具**（GitHub、Stripe、Twitter API等）

### 3.2 OPC 的 MCP Server 清单

#### 内部 MCP Servers（平台自建）

| Server | 功能 | 对应AI员工 |
|--------|------|-----------|
| `OPC-memory` | 向量记忆检索，跨任务上下文 | 所有员工 |
| `OPC-atlas` | 知识图谱查询，商业概念检索 | Advisor类 |
| `OPC-pipeline` | 创业流水线状态管理 | Cortex |
| `OPC-ethos` | 伦理审计与合规检查 | 所有员工 |
| `OPC-sandbox` | 沙箱代码执行环境 | DEV类 |
| `OPC-report` | 成果报告生成与归档 | 所有员工 |

#### 外部 MCP Servers（第三方集成）

| Server | 功能 | 对应业务场景 |
|--------|------|-------------|
| `github` | 代码仓库管理 | MVP开发 |
| `vercel` | 前端部署与域名 | 产品上线 |
| `stripe` | 支付与订阅管理 | 商业化 |
| `twitter/x` | 社媒内容发布 | 营销推广 |
| `resend` | 邮件发送服务 | 用户沟通 |
| `supabase` | 数据库与认证 | 后端服务 |
| `figma` | 设计稿协作 | UI设计 |
| `notion` | 文档与知识库 | 团队Wiki |
| `google-search` | 网络搜索 | 市场调研 |

### 3.4 安全与隔离机制

**学生级隔离**：
- 每个学生的 AI 员工运行在独立的「工作空间」中
- MCP 工具的调用权限由平台根据学生等级动态分配
- 涉及真实资金的操作（Stripe支付）需要学生二次确认

**沙箱执行**：
- AI 生成的代码在隔离容器中执行，防止恶意代码
- 网络访问受限白名单，文件系统只读或临时写
- 执行结果经过 Ethos 审计后再呈现给学生
