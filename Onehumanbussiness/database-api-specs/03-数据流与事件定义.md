## 一、核心业务流程数据流

### 1.1 任务全生命周期数据流

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│   学生创建   │     │   系统/学生  │     │   AI 员工    │     │   学生验收   │     │   归档/复盘  │
│   任务      │ ──▶ │   分配任务   │ ──▶ │   执行任务   │ ──▶ │   交付物    │ ──▶ │   完成闭环   │
└─────────────┘     └─────────────┘     └─────────────┘     └─────────────┘     └─────────────┘
       │                   │                   │                   │                   │
       ▼                   ▼                   ▼                   ▼                   ▼
  DB: ai_tasks        DB: ai_tasks        DB: ai_tasks        DB: ai_tasks        DB: ai_tasks
  status: pending     status: in_progress  status: review      status: completed   status: completed
  created_at          started_at           completed_at        reviewed_at         (final)
       │                   │                   │                   │                   │
       ▼                   ▼                   ▼                   ▼                   ▼
  Event:           Event:              Event:              Event:              Event:
  task.created     task.assigned       task.completed      task.reviewed       task.archived
       │                   │                   │                   │                   │
       ▼                   ▼                   ▼                   ▼                   ▼
  订阅方:           订阅方:             订阅方:             订阅方:             订阅方:
  - 通知服务        - 通知服务          - 通知服务          - 通知服务          - 生涯系统
  - 仪表盘更新      - WebSocket推送     - WebSocket推送     - 财务系统          - 报告生成器
  - 日志系统        - 调度器            - 交付物存储        - 员工绩效更新       - 日志系统
```

**详细数据流说明**：

| 阶段 | 数据变更 | 触发事件 | 下游动作 |
|------|---------|---------|---------|
| **1. 任务创建** | `ai_tasks` 插入，status=`pending` | `ohb.task.created` | ① 仪表盘任务计数+1；② 如设置了 auto_assign，触发分配流程 |
| **2. 任务分配** | `employee_id` 更新，status=`in_progress`，员工 status=`busy` | `ohb.task.assigned` | ① 向员工 WS 推送任务；② 启动 LangGraph 工作流 |
| **3. 执行中** | `execution_logs` 追加，MCP 调用记录写入 | `ohb.task.progress` (多次) | ① 实时进度推送到学生端；② MCP 日志写入 |
| **4. 提交审核** | status=`review`，`deliverables` 写入 | `ohb.task.completed` | ① 通知学生验收；② 生成交付物摘要 |
| **5. 学生验收** | `student_rating`/`review_decision` 更新 | `ohb.task.reviewed` | ① 更新员工绩效；② 如 approved，触发财务记账 |
| **6. 归档** | 无状态变更（逻辑完成） | `ohb.task.archived` | ① 更新 Sprint 统计；② 如关联里程碑，检查里程碑进度 |

## 二、事件总线规范

### 2.1 CloudEvents 格式标准

所有 OHB 事件遵循 CloudEvents 1.0 规范：

```json
{
  "specversion": "1.0",
  "type": "ohb.task.created",
  "source": "ohb.api/v1",
  "id": "evt_a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "time": "2026-05-17T10:30:00.000Z",
  "datacontenttype": "application/json",
  "data": {
    "company_id": "...",
    "task_id": "...",
    "employee_id": "...",
    "...": "..."
  },
  "ohb_meta": {
    "version": "1.0",
    "priority": "normal",
    "trace_id": "trace_xyz789",
    "retry_count": 0
  }
}
```

**标准属性说明**：

| 属性 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `specversion` | string | 是 | CloudEvents 版本，固定 `"1.0"` |
| `type` | string | 是 | 事件类型，格式 `ohb.{domain}.{action}` |
| `source` | string | 是 | 事件源，如 `ohb.api/v1`、`ohb.worker`、`ohb.mcp` |
| `id` | string | 是 | 全局唯一事件 ID，UUID v4 |
| `time` | string | 是 | ISO 8601 时间戳 |
| `datacontenttype` | string | 是 | 固定 `application/json` |
| `data` | object | 是 | 事件载荷（见下文各事件定义） |
| `ohb_meta.version` | string | 是 | OHB 事件 schema 版本 |
| `ohb_meta.priority` | string | 是 | `high`/`normal`/`low`，影响队列优先级 |
| `ohb_meta.trace_id` | string | 是 | 分布式追踪 ID |
| `ohb_meta.retry_count` | integer | 是 | 重试次数 |

### 2.2 事件优先级与队列

| 优先级 | 事件类型示例 | 队列 | SLA |
|--------|------------|------|-----|
| **HIGH** | 财务交易、评审完成、里程碑达成 | RabbitMQ priority queue | 100ms 内投递 |
| **NORMAL** | 任务状态变更、员工状态变更、交付物就绪 | RabbitMQ default queue | 500ms 内投递 |
| **LOW** | 日志写入、分析报告生成、情报收集完成 | Celery deferred queue | 5s 内投递 |
| **REALTIME** | WebSocket 推送、执行进度 | Redis pub/sub | 即时 |

## 三、完整事件定义

### 3.1 公司域事件 (`ohb.company.*`)

#### `ohb.company.created` — 公司创建

```json
{
  "specversion": "1.0",
  "type": "ohb.company.created",
  "source": "ohb.api/v1",
  "id": "evt_...",
  "time": "2026-05-17T10:00:00Z",
  "datacontenttype": "application/json",
  "data": {
    "company_id": "comp_12345678-1234-1234-1234-123456789abc",
    "career_id": "career_...",
    "owner_user_id": "user_...",
    "name": "绿洲科技",
    "slug": "oasis-tech",
    "stage": "IDEATE",
    "mode": "simulation",
    "created_at": "2026-05-17T10:00:00Z"
  },
  "ohb_meta": {
    "version": "1.0",
    "priority": "high",
    "trace_id": "trace_abc123",
    "retry_count": 0
  }
}
```

**发布方**：`POST /api/v1/ohb/companies` 处理完成后  
**订阅方**：
- `career-service`：+XP，更新能力雷达
- `credenti-service`：解锁「创业公司创始人」徽章条件
- `notification-service`：发送欢迎通知
- `analytics-service`：记录创业启动漏斗

---

#### `ohb.company.updated` — 公司信息更新

```json
{
  "type": "ohb.company.updated",
  "source": "ohb.api/v1",
  "data": {
    "company_id": "comp_...",
    "changed_fields": ["business_model_canvas", "stage"],
    "old_values": { "stage": "IDEATE" },
    "new_values": { "stage": "VALIDATE" },
    "updated_at": "2026-05-17T10:00:00Z"
  }
}
```

**发布方**：`PATCH /api/v1/ohb/companies/{id}`  
**订阅方**：`analytics-service`、`log-service`

---

#### `ohb.company.stage_changed` — 公司阶段推进

```json
{
  "type": "ohb.company.stage_changed",
  "source": "ohb.api/v1",
  "data": {
    "company_id": "comp_...",
    "old_stage": "IDEATE",
    "new_stage": "VALIDATE",
    "gateway_review_id": "gw_...",
    "decision": "pass",
    "changed_at": "2026-05-17T10:00:00Z"
  }
}
```

**发布方**：Gateway Review 通过后自动触发  
**订阅方**：
- `career-service`：+XP（大量），解锁新能力维度
- `credenti-service`：发放阶段徽章（如「通过创意验证」）
- `notification-service`：推送阶段晋升通知
- `athena-service`：触发 Athena 专属祝贺对话

---

#### `ohb.company.archived` — 公司归档

```json
{
  "type": "ohb.company.archived",

  "data": {
    "company_id": "comp_...",
```

```python
# OHB 事件生产者示例：统一封装，确保兼容性
from datetime import datetime, timezone
import uuid

def build_event(
    event_type: str,
    source: str,
    data: dict,
    priority: str = "normal"
) -> dict:
    """构建符合 CloudEvents 规范的事件"""
    return {
        "specversion": "1.0",
        "type": event_type,
        "source": source,
        "id": f"evt_{uuid.uuid4()}",
        "time": datetime.now(timezone.utc).isoformat(),

        "data": data,
        "ohb_meta": {
            "version": "1.0",
            "priority": priority,
            "trace_id": str(uuid.uuid4()),
            "retry_count": 0
        },
        # 兼容性字段：现有平台可能需要的字段
        "legacy": {
            "domain": "ohb",
            "action": event_type.split(".")[-1],
            "timestamp_ms": int(datetime.now(timezone.utc).timestamp() * 1000)
```

### 5.3 WebSocket 连接管理

```python
# FastAPI WebSocket 管理器示例
from fastapi import WebSocket
from typing import Dict, Set
import json

class OHBWebSocketManager:
    def __init__(self):
        # company_id -> Set[WebSocket]
        self.company_connections: Dict[str, Set[WebSocket]] = {}
        # employee_id -> Set[WebSocket]
        self.employee_connections: Dict[str, Set[WebSocket]] = {}
    
    async def connect_company(self, company_id: str, websocket: WebSocket):
        await websocket.accept()
        if company_id not in self.company_connections:
            self.company_connections[company_id] = set()
        self.company_connections[company_id].add(websocket)
        await websocket.send_json({
            "type": "connected",
            "channel": f"company:{company_id}",
            "timestamp": datetime.now(timezone.utc).isoformat()
        })
    
    async def connect_employee(self, employee_id: str, websocket: WebSocket):
        await websocket.accept()
        if employee_id not in self.employee_connections:
            self.employee_connections[employee_id] = set()
        self.employee_connections[employee_id].add(websocket)
        await websocket.send_json({
            "type": "connected",
            "channel": f"employee:{employee_id}",
            "timestamp": datetime.now(timezone.utc).isoformat()
        })
    
    async def broadcast_to_company(self, company_id: str, message: dict):
        if company_id in self.company_connections:
            disconnected = set()
            for ws in self.company_connections[company_id]:
                try:
                    await ws.send_json(message)
                except:
                    disconnected.add(ws)
            self.company_connections[company_id] -= disconnected
    
    async def broadcast_to_employee(self, employee_id: str, message: dict):
        if employee_id in self.employee_connections:
            disconnected = set()
            for ws in self.employee_connections[employee_id]:
                try:
                    await ws.send_json(message)
                except:
                    disconnected.add(ws)
            self.employee_connections[employee_id] -= disconnected
    
    async def disconnect(self, websocket: WebSocket):
        for conns in self.company_connections.values():
            conns.discard(websocket)
        for conns in self.employee_connections.values():
            conns.discard(websocket)

# 全局管理器实例
ws_manager = OHBWebSocketManager()
```

## 七、事件可靠性保障

### 7.1 投递保证

| 事件类型 | 投递保证 | 机制 |
|---------|---------|------|
| 财务事件 | **Exactly Once** | 幂等 ID + 数据库唯一约束 |
| 任务状态变更 | **At Least Once** | 消息确认 + 重试队列 |
| WebSocket 推送 | **Best Effort** | 无持久化，断线不补发 |
| 日志事件 | **At Most Once** | 异步写入，允许丢失 |
