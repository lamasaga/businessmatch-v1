> **文档定位**：市场验证期（第15-28天）的逐日操作手册，核心目标是用最小成本验证用户需求。
>
> **最后更新**：2026-05-17

---

## 一、阶段目标

在14天内，验证核心假设：「目标用户真的需要我的解决方案」

**关键产出**：
- ✅ 着陆页（Live）

- ✅ 假门测试数据
- ✅ 邮件列表（≥50人）或预约名单

## 二、核心方法论：冒烟测试

### 2.1 什么是冒烟测试

不开发产品，先用「假装有产品」的方式测试需求：

```
真实产品          冒烟测试
┌─────────┐      ┌─────────┐
│ 开发产品 │  →→  │ 做 landing page │
│ 等几个月 │      │ 说"即将上线"    │
│ 上线发现 │      │ 看有没有人感兴趣 │
│ 没人要  │      │ 没兴趣就换方向   │
└─────────┘      └─────────┘
```

### 2.2 四种验证方法

| 方法 | 成本 | 速度 | 可信度 | 适用场景 |
|------|------|------|--------|----------|
| 着陆页+假门 | 低 | 快 | 中 | 大多数产品 |
| 人工Concierge | 极低 | 快 | 高 | 服务类产品 |
| 众筹/预售 | 低 | 中 | 高 | 硬件/创意产品 |
| 社媒内容测试 | 极低 | 快 | 低 | 内容类产品 |

### Day 21-24: 用户访谈

**Day 21: 访谈准备**
- [ ] UR-01 生成访谈提纲
- [ ] 确定访谈对象（朋友、同学、社群成员）
- [ ] 准备奖励（奶茶/小礼品/未来产品折扣）

**用户访谈提纲模板**：
```markdown
# 用户访谈提纲

## 开场（2分钟）
- 自我介绍，说明目的
- 强调「没有正确答案，请诚实表达」
- 征求录音/笔记同意

## 背景了解（5分钟）
1. 请描述你最近一次[相关场景]的经历
2. 你通常如何解决[相关问题]？
3. 你为此花了多少钱/时间？

## 痛点挖掘（10分钟）
4. 现有方案有什么让你不满意的地方？
5. 如果能改变一点，你最希望改变什么？
6. 这个问题对你有多重要？（1-10分）

## 方案验证（10分钟）
7. 如果我告诉你有一个产品可以[解决方案]，你会感兴趣吗？
8. 你愿意为此付多少钱？
9. 你会在哪里/如何发现这个产品？

## 结束（3分钟）
10. 还有什么我没问到但你想分享的吗？
11. 是否愿意在产品上线时成为早期用户？
```

## 四、Gateway 2 评审标准

| 评审项 | 权重 | 通过标准 |
|--------|------|----------|
| 着陆页质量 | 15% | 专业、信息完整、无错别字 |
| 访问数据 | 20% | ≥50次访问 |
| 转化率 | 25% | 注册/预约率 ≥5% |
| 访谈质量 | 20% | ≥10人，有详细记录 |
| 洞察深度 | 15% | 有超出假设的新发现 |
| 迭代意愿 | 5% | 对反馈持开放态度 |

## 五、常见问题

| 问题 | 解决 |
|------|------|
| 没人访问我的页面 | 检查内容分发渠道是否匹配目标用户；尝试更精准的小社群 |
| 转化率很低 | 检查CTA是否清晰；价值主张是否具体；是否有社会证明 |
| 访谈对象不好找 | 从身边开始；用小额奖励激励；加入相关社群 |
| 数据不够好 | 不要伪造数据；诚实呈现，分析原因，提出改进计划 |
