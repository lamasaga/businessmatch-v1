## 一、状态机总览

```
                    ┌─────────────┐
                    │   CANCELLED │
                    │    (已取消)  │
                    └──────▲──────┘
                           │
    ┌──────────┐    cancel│
    │  PENDING  │──────────┘
    │  (待开始) │
    └─────┬────┘
          │ start / auto-start
          ▼
    ┌──────────┐    pause    ┌──────────┐
    │ IN_PROGRESS│──────────▶│  PAUSED  │
    │ (执行中)  │◀──────────│ (已暂停) │
    └─────┬────┘   resume    └──────────┘
          │
          │ complete / error
          ▼
    ┌──────────┐    reject    ┌──────────┐
    │ COMPLETED │───────────▶│ REJECTED │
    │ (待验收)  │◀───────────│ (已拒绝) │
    └─────┬────┘   no action  └──────────┘
          │ review
          ▼
    ┌──────────┐    accept    ┌──────────┐
    │  REVIEWED │───────────▶│  ACCEPTED│
    │ (已评审)  │◀───────────│ (已通过) │
    └─────┬────┘   modify     └──────────┘
          │ request_modification
          ▼
    ┌──────────┐
    │MODIFYING  │───────────▶ (回到IN_PROGRESS)
    │(修改中)   │
    └──────────┘
```

## 二、状态定义

| 状态 | 代码 | 说明 | 允许的操作 |
|------|------|------|------------|
| **PENDING** | `pending` | 任务已创建，等待AI员工开始 | 取消、修改需求、手动开始 |
| **IN_PROGRESS** | `in_progress` | AI员工正在执行任务 | 暂停、取消、查看进度 |
| **PAUSED** | `paused` | 任务被暂停 | 恢复、取消 |
| **COMPLETED** | `completed` | AI员工完成工作，提交交付物 | 验收、拒绝、要求修改 |
| **REJECTED** | `rejected` | 学生拒绝验收 | 重新派发、归档 |
| **REVIEWED** | `reviewed` | 学生已完成评审 | （中间状态，自动流转） |
| **ACCEPTED** | `accepted` | 验收通过，任务完成 | 查看历史、复用模板 |
| **MODIFYING** | `modifying` | 根据反馈修改中 | 查看进度、取消修改 |
| **CANCELLED** | `cancelled` | 任务被取消 | 查看历史、重新创建 |

## 三、状态转换规则

### 3.1 转换矩阵

| 从 \ 到 | pending | in_progress | paused | completed | rejected | accepted | modifying | cancelled |
|---------|---------|-------------|--------|-----------|----------|----------|-----------|-----------|
| **pending** | — | ✅自动/手动 | — | — | — | — | — | ✅ |
| **in_progress** | — | — | ✅ | ✅完成/错误 | — | — | — | ✅ |
| **paused** | — | ✅恢复 | — | — | — | — | — | ✅ |
| **completed** | — | — | — | — | ✅拒绝 | ✅通过 | ✅修改 | — |
| **rejected** | — | — | — | — | — | — | — | — |
| **accepted** | — | — | — | — | — | — | — | — |
| **modifying** | — | ✅ | — | ✅ | — | — | — | ✅ |
| **cancelled** | — | — | — | — | — | — | — | — |

### 3.2 转换条件详解

#### PENDING → IN_PROGRESS

```yaml
transition:
  name: "任务开始"
  triggers:
    - type: "auto"
      condition: "AI员工处于idle状态且任务优先级最高"
      delay: "0秒"
    - type: "manual"
      actor: "student"
      action: "点击'开始任务'"
    - type: "scheduled"
      condition: "到达任务设定的开始时间"
  
  pre_conditions:
    - "AI员工状态为idle或当前任务已完成"
    - "任务所需工具权限已授权"
    - "没有更高优先级的排队任务"
  
  side_effects:
    - "更新AI员工状态为busy"
    - "记录任务开始时间"
    - "发送WebSocket事件: task.started"
    - "创建任务执行checkpoint"
```

#### IN_PROGRESS → COMPLETED

```yaml
transition:
  name: "任务完成"
  triggers:
    - type: "auto"
      condition: "AI员工执行完所有步骤并生成交付物"
  
  pre_conditions:
    - "所有执行步骤状态为success或warning"
    - "交付物已生成且非空"
    - "通过Ethos基础审计（无BLOCK级别问题）"
  
  post_actions:
    - "AI员工状态更新为idle"
    - "任务状态更新为completed"
    - "触发任务完成通知"
    - "发送WebSocket事件: task.completed"
    - "计算并暂存预估XP"
```

#### COMPLETED → ACCEPTED

```yaml
transition:
  name: "验收通过"
  triggers:
    - type: "manual"
      actor: "student"
      action: "提交评审表单，decision=accept"
  
  pre_conditions:
    - "学生已填写完整评审表单"
    - "overall_rating ≥ 1"
  
  post_actions:
    - "任务状态更新为accepted"
    - "发放XP到AI员工账户"
    - "更新AI员工绩效统计"
    - "记录学生反馈到学习档案"
    - "触发关联知识图谱节点点亮"
    - "发送WebSocket事件: task.reviewed"
    - "触发Career XP增加事件"
```

#### COMPLETED → MODIFYING

```yaml
transition:
  name: "要求修改"
  triggers:
    - type: "manual"
      actor: "student"
      action: "提交评审表单，decision=accept_with_modifications"
  
  pre_conditions:
    - "学生已填写修改要求"
    - "modifications_requested非空"
  
  post_actions:
    - "任务状态更新为modifying"
    - "解析修改要求为结构化change requests"
    - "AI员工状态更新为busy"
    - "发送WebSocket事件: task.modification_requested"

    note: "超过3轮修改仍未通过，Cortex建议重新创建任务"
```

## 四、超时处理

### 4.1 各状态超时规则

| 状态 | 超时时间 | 超时后动作 | 通知方式 |
|------|----------|------------|----------|
| PENDING | 24小时 | 自动取消 | 通知学生 |
| IN_PROGRESS | 2倍预估时间 | 标记为stuck，Cortex介入 | 通知学生+导师 |
| PAUSED | 48小时 | 自动取消 | 通知学生 |
| COMPLETED | 72小时 | 自动标记为accepted（默认好评） | 通知学生 |
| MODIFYING | 1.5倍预估时间 | 标记为stuck | 通知学生 |

### 4.2 超时处理实现

```python
# Celery定时任务
@celery_app.task
def check_task_timeouts():
    now = datetime.utcnow()
    
    # 1. 检查PENDING超时
    stale_pending = db.query(AITask).filter(
        AITask.status == 'pending',
        AITask.created_at < now - timedelta(hours=24)
    ).all()
    
    for task in stale_pending:
        task.status = 'cancelled'
        task.cancel_reason = 'timeout'
        notify_student(task.company.student_id, 
                      f"任务'{task.title}'因超时未开始已自动取消")
    
    # 2. 检查IN_PROGRESS卡住
    stuck_tasks = db.query(AITask).filter(
        AITask.status == 'in_progress',
        AITask.started_at < now - timedelta(hours=2),
        AITask.expected_duration != None,
        AITask.started_at < now - timedelta(minutes=AITask.expected_duration * 2)
    ).all()
    
    for task in stuck_tasks:
        task.is_stuck = True
        # Cortex介入诊断
        cortex_diagnose_task.delay(task.id)
        notify_student(task.company.student_id,
                      f"任务'{task.title}'执行时间异常，Cortex正在诊断")
    
    # 3. 检查COMPLETED未验收
    stale_completed = db.query(AITask).filter(
        AITask.status == 'completed',
        AITask.completed_at < now - timedelta(hours=72)
    ).all()
    
    for task in stale_completed:
        # 自动验收（默认好评）
        auto_accept_task(task.id)
    
    db.commit()
```

### 5.2 任务优先级队列

```python
class TaskQueue:
    def get_next_task(self, employee_id: str) -> Optional[AITask]:
        employee = get_employee(employee_id)
        
        # 1. 检查当前负载
        current_tasks = db.query(AITask).filter(
            AITask.assignee_id == employee_id,
            AITask.status == 'in_progress'
        ).count()
        
        if current_tasks >= employee.max_parallel_tasks:
            return None
        
        # 2. 优先级排序
        # 优先级: urgent > high > normal > low
        # 同优先级: 截止时间早的优先
        # 同截止时间: 创建时间早的优先
        
        next_task = db.query(AITask).filter(
            AITask.assignee_id == employee_id,
            AITask.status == 'pending'
        ).order_by(
            case(
                (AITask.priority == 'urgent', 1),
                (AITask.priority == 'high', 2),
                (AITask.priority == 'normal', 3),
                (AITask.priority == 'low', 4),
                else_=5
            ),
            AITask.deadline.asc().nullslast(),
            AITask.created_at.asc()
        ).first()
        
        return next_task
```

## 六、异常处理

### 6.1 异常类型与处理

| 异常类型 | 场景 | 自动处理 | 学生通知 |
|----------|------|----------|----------|
| AI服务超时 | LLM API无响应 | 重试3次→降级到模板模式 | 是 |
| MCP工具失败 | 外部API错误 | 标记步骤为error→暂停任务 | 是 |
| 代码执行错误 | 沙箱内代码崩溃 | 捕获错误→记录日志→暂停 | 是 |
| 内存/CPU超限 | 资源使用超限 | 终止任务→提示简化需求 | 是 |
| 内容安全告警 | Ethos检测到风险 | 阻断输出→等待人工确认 | 是 |
| 学生需求矛盾 | 同一任务中需求自相矛盾 | 标记→发起澄清请求 | 是 |

### 6.2 错误恢复流程

```
[执行中遇到错误]
    │
    ▼
[记录错误详情到执行日志]
    │
    ├── 可恢复错误（如API临时失败）
    │   → 自动重试（指数退避）
    │   → 重试成功 → 继续执行
    │   → 重试失败 → 暂停任务，通知学生
    │
    └── 不可恢复错误（如需求矛盾）
        → 立即暂停任务
        → 生成错误报告
        → 通知学生
        → 等待学生决策（继续/修改/取消）
```
