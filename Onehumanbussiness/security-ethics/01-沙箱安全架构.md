# 沙箱安全架构

> **文档定位**：定义AI生成代码的安全执行环境，防止恶意代码逃逸和系统损害。
>
> **最后更新**：2026-05-17

---

## 一、威胁模型

| 威胁 | 风险等级 | 场景 |
|------|----------|------|
| 恶意代码执行 | 🔴 高 | AI生成包含病毒/木马的代码 |
| 资源耗尽攻击 | 🔴 高 | 无限循环、内存泄漏导致服务器崩溃 |
| 数据泄露 | 🔴 高 | 代码读取其他学生的数据 |
| 网络滥用 | 🟡 中 | 代码用于DDoS、爬虫、发送垃圾邮件 |
| 文件系统破坏 | 🟡 中 | 删除/篡改系统文件 |
| 加密货币挖矿 | 🟡 中 | 利用服务器资源挖矿 |

## 二、沙箱技术选型

### 2.1 方案对比

| 方案 | 隔离级别 | 启动速度 | 资源开销 | 复杂度 | 推荐度 |
|------|----------|----------|----------|--------|--------|
| **gVisor** | 进程级+系统调用拦截 | 快 | 低 | 中 | ⭐⭐⭐⭐⭐ |
| **Firecracker** | 轻量级VM | 较快 | 中 | 中 | ⭐⭐⭐⭐ |
| **Docker** | 容器 | 快 | 低 | 低 | ⭐⭐⭐ |
| **nsjail** | 命名空间隔离 | 快 | 低 | 中 | ⭐⭐⭐⭐ |
| **原生限制** | 仅资源限制 | 最快 | 最低 | 低 | ⭐⭐ |

### 2.2 推荐方案：gVisor

```
gVisor 架构
┌─────────────────────────────────────┐
│  应用进程 (Node.js / Python)        │
├─────────────────────────────────────┤
│  gVisor Sentry (用户空间内核)        │
├─────────────────────────────────────┤
│  Host Kernel (宿主内核，受保护)      │
└─────────────────────────────────────┘

优势：
- 系统调用拦截：恶意调用被阻断
- 文件系统虚拟化：只看到沙箱内文件
- 网络栈虚拟化：可控的网络访问
- 轻量：不需要完整VM
```

## 三、沙箱配置

### 3.1 资源限制

```yaml
sandbox_limits:
  cpu:
    cores: 1              # 最多1核
    time_limit: 300       # 单次执行最多5分钟
  
  memory:
    max: 512MB            # 最大内存
    swap: 0               # 禁止swap
  
  disk:
    max_size: 100MB       # 临时文件最大100MB
    persistent: false     # 不持久化
  
  network:
    mode: "restricted"    # 限制模式
    allowed_hosts:        # 白名单
      - "*.vercel.app"
      - "*.supabase.co"
      - "api.github.com"
      - "api.stripe.com"
    blocked_ports:        # 禁止端口
      - 22    # SSH
      - 25    # SMTP（防垃圾邮件）
      - 465   # SMTPS
      - 3306  # MySQL
      - 5432  # PostgreSQL（外部）
    max_connections: 10   # 最大并发连接
    bandwidth: "10Mbps"   # 带宽限制
  
  processes:
    max: 20               # 最大进程数
    max_threads: 50       # 最大线程数
  
  filesystem:
    root: "/tmp/sandbox/{session_id}"  # 根目录
    read_only_paths:      # 只读路径
      - "/usr/lib"
      - "/usr/local/lib"
    writable_paths:       # 可写路径
      - "/tmp/sandbox/{session_id}/workspace"
      - "/tmp/sandbox/{session_id}/output"
    blocked_paths:        # 禁止访问
      - "/etc/passwd"
      - "/etc/shadow"
      - "/proc"
      - "/sys"
      - "/dev"
      - ".."              # 禁止目录遍历
```

### 3.2 Docker + gVisor 运行时配置

```dockerfile
# Dockerfile.sandbox
FROM python:3.11-slim

# 安装基础依赖
RUN pip install --no-cache-dir \
    pytest \
    black \
    flake8

# 创建沙箱用户（非root）
RUN useradd -m -u 1000 sandbox
USER sandbox
WORKDIR /home/sandbox/workspace

# 默认命令
CMD ["python"]
```


## 四、代码安全扫描

### 4.1 静态分析规则

```python
# 扫描AI生成的代码

dangerous_patterns = [
    # 执行系统命令
    {
        'pattern': r'os\.system\(|subprocess\.call\(|subprocess\.run\(',
        'severity': 'BLOCK',
        'reason': '禁止执行系统命令'
    },
    # 文件删除
    {
        'pattern': r'os\.remove\(|shutil\.rmtree\(',
        'severity': 'BLOCK',
        'reason': '禁止删除文件'
    },
    # 网络请求（非白名单）
    {
        'pattern': r'requests\.(get|post)\(',
        'severity': 'WARNING',
        'reason': '需检查目标域名是否在白名单'
    },
    # 敏感信息
    {
        'pattern': r'(password|secret|key|token)\s*=\s*["\']',
        'severity': 'WARNING',
        'reason': '可能的硬编码密钥'
    },
    # 无限循环
    {
        'pattern': r'while\s+True\s*:',
        'severity': 'WARNING',
        'reason': '可能的无限循环'
    },
    # 加密/挖矿相关
    {
        'pattern': r'(hashlib\.sha256|crypto|mining|bitcoin)',
        'severity': 'BLOCK',
        'reason': '可能的恶意计算'
    },
]
```

### 4.2 动态监控

```python
class SandboxMonitor:
    """监控沙箱内进程行为"""
    
    def __init__(self, pid: int):
        self.pid = pid
        self.start_time = time.time()
    
    async def monitor(self):
        while True:
            # 检查CPU使用率
            cpu_percent = get_cpu_percent(self.pid)
            if cpu_percent > 90:
                await self.alert("CPU使用率过高")
            
            # 检查内存使用
            memory_mb = get_memory_mb(self.pid)
            if memory_mb > 400:  # 接近限制
                await self.alert("内存使用接近上限")
            
            # 检查网络连接
            connections = get_network_connections(self.pid)
            for conn in connections:
                if not is_allowed_host(conn.remote_host):
                    await self.block_connection(conn)
            
            # 检查执行时间
            if time.time() - self.start_time > 300:  # 5分钟
                await self.terminate("执行超时")
                break
            
            await asyncio.sleep(1)
```

## 五、执行流程

```
[学生提交代码执行请求]
    │
    ▼
[静态扫描]
    ├── BLOCK级问题 → 拒绝执行，返回错误
    ├── WARNING → 记录日志，继续执行
    └── 通过 → 继续
    │
    ▼
[创建沙箱]
    ├── 启动gVisor容器
    ├── 挂载临时文件系统
    ├── 注入学生代码
    └── 设置资源限制
    │
    ▼
[执行代码]
    ├── 启动监控进程
    ├── 运行代码
    ├── 实时行为监控
    └── 捕获输出
    │
    ▼
[结果处理]
    ├── 停止沙箱
    ├── 收集输出
    ├── 清理临时文件
    └── 返回结果
```

## 六、逃逸检测与响应

| 检测项 | 检测方法 | 响应 |
|--------|----------|------|
| 尝试读取/etc/passwd | 文件系统访问审计 | 立即终止+告警 |
| 尝试连接黑名单域名 | 网络连接监控 | 阻断连接+告警 |
| CPU持续100% | 资源监控 | 降低优先级，超时终止 |
| 内存突增 | 资源监控 | 触发OOM Killer |
| 尝试fork大量进程 | 进程监控 | 终止+告警 |
| 尝试写入系统目录 | 文件系统审计 | 拒绝写入+告警 |
