## 一、技术选型总表

| 层级 | 选型 | 版本建议 | 理由 |
|------|------|----------|------|
| **学生/教师 Web** | React 18 + TypeScript + Vite | 与现有 MVP 一致 | 组件化、生态、可复用 `web应用商业教育/frontend` |
| **样式** | Tailwind CSS + 设计 Token | - | 与 `商赛界面展示` 统一视觉 |
| **状态** | Zustand + TanStack Query | - | 本地 UI 状态 + 服务端缓存 |
| **路由** | React Router v6 | - | 多角色路由守卫 |
| **移动端** | PWA 优先；二期 Taro 小程序 | - | 学生手机场景；家长端 |
| **API** | FastAPI（Python）或 NestJS（TS） | **Phase1 延续 FastAPI** | MVP 已落地；引擎可 TS/Python 双轨 |
| **实时** | Socket.io 或 FastAPI WebSocket | - | 房间制商赛、大屏 |
| **主库** | PostgreSQL 15+ | 替代 SQLite | JSONB 存规则配置、生涯事件 |
| **缓存** | Redis 7 | 会话、排行榜、限流、任务队列 |
| **分析** | ClickHouse 或 PG 分区表 | Phase2 | 决策日志、教学分析 |
| **对象存储** | MinIO（开发）/ 阿里云 OSS（生产） | - | 课件、证书 PDF、上传作业 |
| **向量库** | pgvector 或 Qdrant | Phase2 | Athena RAG（知识卡片） |
| **AI** | OpenAI / Claude API + RAG + **LangGraph**（Rival 状态机） | - | Athena / Demia / Rival 三服务 |
| **Agent 运行时** | Python `ai-orchestrator` + Redis 会话 | - | 谈判多轮、Debrief 队列 |
| **消息队列** | Redis + BullMQ 或 Celery | Phase2 | 异步结算、榜单、导出 |
| **容器** | Docker Compose → K8s | - | 开学季弹性 |
| **CI/CD** | GitHub Actions | - | lint、测试、镜像 |
| **监控** | Prometheus + Grafana + Sentry | - | 可观测 |

### 1.1 关键技术决策

| 决策点 | 选择 | 说明 |
|--------|------|------|
| 架构形态 | **模块化单体（Modular Monolith）** → 按需拆微服务 | 团队规模初期 < 10 人，降低运维成本 |
| 后端语言 | Phase1 **Python FastAPI**；结算核心可 **TypeScript 包** | 保留 `v6Engine` 资产时用 npm workspace 供 Python 子进程或 HTTP 调用 |
| ORM | SQLAlchemy 2.0（Py） | 与现有 MVP 一致 |
| 规则引擎 | CyberCore：**YAML/JSON + JSON Schema 校验** | 对齐 `13-` 的 `GC` 类型 |
| 多租户 | `organization_id` 行级隔离 | 学校/机构 SaaS |

## 二、推荐 Monorepo 结构

　　建议在仓库根目录逐步落成如下结构（`商业模拟教育平台/` 为规划文档；**代码**可置于 `platform/` 或继续扩展 `web应用商业教育/`）：

```
platform/                              # 建议最终代码根（可由 web应用商业教育 重命名/迁移）
├── apps/
│   ├── web-student/                   # 学生端 React
│   ├── web-teacher/                   # 教师端（可 Phase2 从 student 拆路由）
│   ├── web-admin/                     # 运营管理
│   └── screen-display/                # 商赛大屏（ECharts / Canvas）
├── packages/
│   ├── ui/                            # 共享组件、设计系统
│   ├── types/                         # 跨端 TypeScript 类型
│   ├── api-client/                    # OpenAPI 生成客户端
│   ├── cybercore-engine/              # 结算引擎 @bizsim/engine-core
│   └── game-config-schema/            # 赛制 JSON Schema
├── services/
│   └── api/                           # FastAPI 主服务（模块化）
│       ├── app/
│       │   ├── domains/
│       │   │   ├── identity/          # 用户、班级、JWT
│       │   │   ├── career/            # 生涯、XP、排名、奖励
│       │   │   ├── atlas/             # 知识图谱、掌握度
│       │   │   ├── academy/           # 课程、单元进度
│       │   │   ├── quest/             # 日常任务、streak
│       │   │   ├── arena/             # 房间、对局、CyberCore 适配
│       │   │   ├── credenti/          # 徽章、证书
│       │   │   ├── persona/           # 测评、推荐
│       │   │   ├── ethos/             # 诚信、举报
│       │   │   ├── ai/                # Athena / Demia / Rival 路由
│       │   │   ├── content/           # CMS、Bundle 导入
│       │   │   └── analytics/         # Apollo 查询 API
│       ├── services/ai-orchestrator/  # 可选独立进程：LLM 队列
│       ├── content/pops/              # Demia POP YAML
│       └── content/rivals/            # Rival 人格 YAML
│       │   ├── events/                # 域事件发布
│       │   ├── integrations/          # AI、支付、短信
│       │   └── main.py
│       ├── alembic/                   # 数据库迁移
│       └── tests/
├── content/                           # 可选：Git 管理 YAML 内容源
│   ├── bundles/                       # 来自 college + 13-
│   ├── game-configs/                  # 来自 商赛主题与真题库
│   └── knowledge-graph/               # 来自 知识卡片库 YAML
├── infra/
│   ├── docker-compose.yml
│   ├── docker-compose.prod.yml
│   └── k8s/                           # Phase3
├── scripts/
│   ├── import_knowledge_cards.py
│   ├── import_game_configs.py
│   └── seed_demo_career.py
└── docs/                              # 可软链到 商业模拟教育平台/
```

## 四、核心数据模型（逻辑 ER）

```
User 1──1 CareerProfile
User N──M Class (via Enrollment)
CareerProfile 1──N XPEvent
CareerProfile 1──N UserAchievement
CareerProfile N──M KnowledgeNode (mastery join)
CareerProfile 1──N SeasonParticipation

Course 1──N LearningUnit
LearningUnit N──M KnowledgeNode
LearningUnit 1──N UnitProgress (per user)

GameMode 1──N GameConfig (versioned)
GameSession 1──N Round
GameSession N──M User (participants)
Round 1──N DecisionLog

QuestTemplate 1──N QuestInstance (per user per day)
Badge 1──N UserBadge

Organization 1──N Class
Organization 1──N User (teachers)
```

### 4.1 关键表说明

| 表 | 用途 |
|----|------|
| `career_profiles` | 生涯主线：等级、赛季、legacy JSON |
| `xp_events` | 不可变账本：`source_type`, `source_id`, `amount`, `created_at` |
| `leaderboard_snapshots` | 班级/全校/全国榜定期快照 |
| `knowledge_nodes` / `knowledge_edges` | 图谱结构 |
| `user_node_mastery` | 0–100 掌握度、最后练习时间 |
| `game_configs` | CyberCore YAML 存 JSONB + version |
| `decision_logs` | 赛后分析与 Ethos 审计 |
| `dialogue_logs` | Rival 谈判与 Athena 会话 |
| `pop_states` | 每局每回合 POP 满意度与需求份额 |
| `athena_debriefs` | 结构化复盘缓存 |

## 五、CyberCore 工程化要点

1. **规则即代码**：`game-configs/*.yaml` 经 Schema 校验后入库。
2. **确定性重放**：随机种子写入 `GameSession.seed`。
3. **版本 pinning**：每局记录 `config_version`。
4. **Worker 结算**：高并发时 `arena.settle` 入队 Redis。
5. **与主题库对齐**：`商赛主题与真题库/02-` 每个文件对应一个 `game_mode_id`。

## 七、非功能性需求

| 需求 | 指标 | 策略 |
|------|------|------|
| 并发 | 单校 500 人同时在线 | 无状态 API + Redis |
| 延迟 | 决策提交 < 500ms | WebSocket + 边缘缓存热配置 |
| 安全 | 未成年人数据 | 等保思路、最小采集、家长授权 |
| 可用性 | 99.5% | 健康检查、灰度发布 |
| 可测试 | 引擎纯函数 | `cybercore-engine` 单测覆盖率 > 80% |
