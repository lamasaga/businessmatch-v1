## 零、为什么要单独做“教师端”

　　教师端的价值不是“再做一个管理后台”，而是把商赛与沙盘从“可玩”提升到“可教、可控、可验收”。教师要能把一段学习目标（概念 → 练习 → 复盘 → 产出）编排成一个可执行的赛季，并把学生的学习过程可视化。

　　教师端是教学组织与节奏的“导演台”：它要同时掌控群组（谁在一起学）、赛季（这一段时间要完成什么）、活动（课堂内外如何推进）、资源（给学生什么材料与工具）、以及 AI（何时介入、以何种形式协助）。

## 一、教师端的核心对象（初期最小模型）

　　为避免一上来做成“万能教务系统”，我建议教师端先围绕 4 个核心对象建立最小闭环。

### 1.1 群组（Group）

　　群组是课堂/班级/社团的数字化容器。教师创建群组，学生以邀请码加入，群组承载成员、讨论、赛季记录与学习档案聚合。

- **关键字段（草案）**：`group_id`、`name`、`school`、`term`、`invite_code`、`teacher_ids`、`student_ids`、`created_at`
- **关键能力**：分组（小队/同桌）、角色分配（组长/记录员）、群公告与资料库

### 1.2 赛季（Season）

　　赛季是教师端的“教学段落”：从开季到收官，包含若干周/若干课时的节奏安排，以及若干次赛事、沙盘推演与产出任务。

- **关键字段（草案）**：`season_id`、`group_id`、`title`、`start_at`、`end_at`、`theme`、`milestones[]`
- **关键能力**：开季（初始化规则与资源）、推进（按节奏解锁）、收官（总结与评价）

### 1.3 活动（Activity）

　　活动是赛季内可执行的“教学单元”，它可以是一次沙盘推演、一场课堂赛事、一轮复盘、一次文书交付、或一次群聊讨论任务。

- **活动类型（草案）**：
  - **沙盘**：教师驱动的“概念演示 + 变量观察”
  - **教学赛事**：可控规则、可控时长、可控赛后复盘
  - **讨论任务**：围绕案例/数据/新闻的群聊讨论与角色扮演
  - **产出任务**：BMC/企划书/路演稿/复盘报告

### 1.4 资源（Resource）

　　资源是教师可调用的“教学工具箱”：规则解释卡、案例库、数据包、活动模板、评分量表、课堂讲义、视频片段等。资源既服务教师，也可按节奏下发给学生。

- **资源形态（草案）**：卡片/文档/表格/数据包/链接/模板（可版本化）
- **关键能力**：教师收藏、赛季绑定、按里程碑解锁、课堂投屏

## 二、教师端的独特功能（按“教学工作流”组织）

### 2.1 教学沙盘（课堂演示与变量试验）

　　教师需要一个“可控的世界”：能把核心概念（如现金流、成本结构、市场竞争、渠道策略）变成可观察、可对比的结果。沙盘的目标不是替代正式赛制，而是提供“可讲清楚”的可视化试验台。

- **教师视角能力**：
  - **变量面板**：选择 3～5 个关键变量（价格、成本、需求、风险）并做可控调整
  - **回放与对照**：同一变量不同设置的结果对比
  - **讲解模式**：一键生成“本节课要讲的 3 个观察点”
- **学生视角能力**：
  - **观察任务**：看到变化 → 回答问题 → 形成结论（可产出到笔记/报告）

### 2.2 教学赛事（可控节奏、可控规则、可控复盘）

　　教学赛事不是“放学生去打比赛”，而是带着教学目标去组织一段可复盘的经历。教师端要提供更强的可控性：时长、规则难度、AI 对手风格、赛后复盘模板、作业产出与评分量表。

- **教师可控项（草案）**：
  - **赛制选择**：TechVenture / Trading / 浮生记（练习/教学版）
  - **难度档位**：对手策略/旋钮预设（对齐 **80-角色 IP / 规则 NPC 框架**）
  - **课堂时长**：缩短回合、锁定某些机制、降低噪声
  - **复盘输出**：一键生成“课堂复盘卡 + 学生作业模板”

### 2.3 资源库与可调用工具（教师的“备课与课堂工具箱”）

　　教师端需要一个“可复用的教研资产库”。资源不仅是材料，还包含活动模板与评价工具，使教师能快速复用一套成熟的教学流程。

- **资源分类建议（草案）**：
  - **概念卡**：一页讲清“是什么/为什么/怎么做/常见误区”
  - **案例卡**：真实或拟真的商业案例，附讨论题
  - **活动模板**：一节课/一周的活动流程、台词、分组与时间点
  - **评价量表**：BMC、企划书、路演、复盘的评分标准
  - **数据包**：可用于沙盘/练习的结构化数据

### 2.4 AI 教练介入（“教师的副驾驶”，不是替代）

　　AI 教练（Athena）在教师端的定位是：把教师的教学目标落到可执行动作上，并把学生的过程转成可讲、可练、可复盘的材料。它不是“给学生答案”，而是帮助教师组织教学、生成讲解脚手架、产出可用的课堂材料。

- **教师侧可用能力（草案）**：
  - **备课助手**：输入本节课目标 → 生成活动节奏、讲解要点、提问脚本
  - **课堂助手**：实时汇总学生常见误区（来自可追溯事实/提交）
  - **复盘助手**：生成“全班复盘摘要 + 分组差异 + 下一步训练建议”
  - **批改助手**：按量表对文书/复盘作业做结构化反馈（可人工确认）
- **硬边界（必须）**：
  - **事实可追溯**：引用真实提交/对局事实，不编造数据
  - **答案不直给**：以提示/提问/对照为主
  - **可降级**：无 LLM 时用模板与规则输出仍可用（对齐 81）

### 2.5 群聊智能体介入（把“活动”搬进群聊）

　　教师端的一大增量是把“教学活动”落到群聊里，让学生在协作讨论中完成任务。群聊智能体的角色不是聊天，而是“活动主持人/记录员/裁判/提醒器”。

- **群聊活动形态（草案）**：
  - **角色扮演讨论**：学生扮演 CEO/CFO/市场/供应链，智能体扮演“董事会/媒体/对手”
  - **结构化辩论**：围绕策略选择进行正反方辩论，智能体负责计时、追问与总结
  - **任务推进**：拆解作业为若干步，智能体按时间点提醒并收集进度
  - **复盘圆桌**：按固定问题序列主持复盘，沉淀为“复盘纪要”
- **智能体能力边界（必须）**：
  - **主持与结构化**优先：给流程、给问题、给总结，不替学生做决策
  - **可审计**：每次活动都有“输入/产出/引用事实/教师确认”痕迹
  - **成本可控**：高频活动优先规则模板；必要时才用 LLM 增强措辞

## 三、教师端与现有“组织者端/学生端”的边界（先定清）

　　为了避免三套前端互相重叠，我建议先把边界说清楚，后续再决定工程形态（是否新前端、或扩展组织者端）。

- **学生端（学习与参赛）**：进入比赛、提交决策、查看个人复盘、完成任务与产出。
- **组织者端（赛事运营）**：面向“赛事主办方/控场”的能力：赛事创建、房间管理、直播/大屏、裁判/评分流程。
- **教师端（教学编排）**：面向“教师”的能力：建群组、开赛季、编排活动、下发资源、组织课堂复盘、管理群聊活动与作业评价。

　　初期可以允许教师端与组织者端有少量重叠（例如“创建教学赛事”），但必须以教师工作流为主，不把教师端做成组织者端的子菜单。

## 四、初期落地路线（只求一个最小闭环）

### 4.1 Phase A 友好最小闭环（不新增“世界域”，不引入重依赖）

　　我建议第一阶段只落地“群组 → 开赛季 → 组织一次教学赛事 → 赛后复盘 → 产出作业”的闭环。

- **最小功能集（草案）**：
  - 群组：创建/邀请码加入/成员列表
  - 赛季：创建/状态（进行中/已结束）/里程碑列表
  - 活动：创建一次“教学赛事”活动（调用现有练习/教学配置）
  - 复盘：全班复盘摘要（模板优先）+ 学生作业模板下发
  - 群聊：先做“活动公告 + 提交入口 + 复盘纪要”三件事（智能体可后置）

### 4.2 Phase B～C 增量（AI 与活动体系逐步增强）

　　第二阶段把教师端真正做成“导演台”：

- 资源库（模板化、可复用、可版本化）
- 群聊活动主持（结构化输出、可审计、可回放）
- AI 教练介入（教师副驾驶：备课/课堂/复盘/批改）
- 对手进化与班级画像（基于事实聚合的可控调参与差异化练习）

## 五、风险与约束（先写出来，避免后续走偏）


| 风险          | 表现         | 约束与对策                        |
| ----------- | ---------- | ---------------------------- |
| 教师端变成“万能教务” | 需求无限外溢     | 只围绕群组-赛季-活动-资源闭环；不做排课/成绩册全功能 |
| AI 替代教师     | 直接给答案、代写作业 | AI 只做脚手架、提问、总结；批改需教师确认       |
| 群聊变成自由聊天    | 成本失控、噪声大   | 群聊以活动模板驱动；结构化输出与可审计优先        |
| 赛事与教学目标脱钩   | 只玩不学       | 每个活动必须绑定“观察点/产出/评价量表”        |
| 多端边界混乱      | 三套前端互相复制   | 先定边界与命名，后定工程形态               |
