## 一、现状与目标

### 1.1 当前 webapp 视觉基线

| 维度 | 现状 | 含义 |
|------|------|------|
| 学生端 | `webapp/frontend/` — React 19、Vite 8、Tailwind、**lucide-react 图标** | 几乎无位图/精灵图管线 |
| 组织者端 | `webapp/organizer-frontend/` — 同栈 | 控场、大屏以信息面板为主 |
| 已落地赛制 UI | TechVenture（表单+Tab）、浮生记 RTS（城市名+列表）、回合制 trading | **数据驱动 UI**，非游戏画布 |
| 静态资源 | `public/` 仅 favicon；`src/assets/` 少量 hero/svg | 无统一 `game-assets` 目录 |
| 实时 | RTS 用 `rtsWebSocket.ts` + 轮询兜底 | 状态在 Zustand，**渲染与结算分离**（符合蓝图 RTS 单写者） |

　　目标不是「做成 3A」，而是在 **K12～大学课堂场景** 下达到：**一眼像商赛、决策有反馈、大屏有戏剧感**，且不与 Phase A 的「单 API、单库、赛制 YAML」架构冲突。

### 1.2 体验分层（建议优先级）

```
P0  全平台设计系统（色板、字体、卡片、空状态）— 低成本、全页面受益
P1  赛制主题包（按 game_config_id / theme）— 背景、城市/路线插画、回合结算动效
P2  对局「决策舱」强化 — 投资滑块、地图点选、车辆行进条（可先 CSS+轻 SVG）
P3  大屏/组织者叙事 — 排名升降、新闻 Ticker、全屏结算
P4  画布级玩法 — 可缩放大地图、精灵移动（Pixi/Canvas 层，见 §五）
```

## 二、美术资源分类与存放约定

### 2.1 资源类型

| 类型 | 用途示例 | 推荐格式 | 备注 |
|------|----------|----------|------|
| **UI 皮肤** | 按钮、面板纹理、品牌顶栏 | WebP/PNG @1x/@2x | 与 Tailwind token 对齐 |
| **插画 / 情境** | 每轮事件头图、城市名片 | WebP，宽度 ≤1920 | 按 `round`/`city_id` 索引 |
| **图标集** | 路线、产业、资源 | SVG sprite 或独立 SVG | 可替代部分 lucide |
| **地图底图** | 城市节点、区域块 | 分层 PNG 或 **Tiled JSON** | RTS/大地图用 |
| **精灵 / 动画** | 车辆、货物、粒子 | 精灵表 + JSON（TexturePacker）或 Lottie | 需统一帧率规范 |
| **字体** | 数字强调、标题 | woff2 子集 | 注意教育场景授权 |
| **音视频** | 回合开始、结算 | MP3/OGG 短音效 | 默认静音、用户开启 |
| **3D（远期）** | 展厅、城市鸟瞰 | glTF + Draco | Phase C+，非当前必做 |

### 2.2 仓库目录建议（与 CyberCore 对齐）

　　美术资源 **不进 Python 引擎**，放在 **content 层**，由前端按 `game_config_id` / `theme` 加载：

```
webapp/
├── frontend/
│   └── public/
│       └── game-assets/                    # 或 build 时从 content 同步
│           ├── _shared/                    # 通用：加载动画、占位图
│           ├── techventure-v1/
│           │   ├── manifest.json           # 资源清单 + 哈希版本
│           │   ├── ui/
│           │   ├── cities/{city_id}/
│           │   ├── routes/{route_id}/
│           │   └── rounds/{n}/
│           └── trading-v2-rts/
│               ├── map/
│               ├── vehicles/
│               └── cities/
└── backend/content/
    └── game-assets/                        # 可选：与 YAML 同仓版本化
        └── techventure-v1/manifest.yaml    # 声明 theme、默认图、音效键
```

**manifest 示例（逻辑，非强制实现）：**

```yaml
# content/game-assets/techventure-v1/manifest.yaml
theme: techventure
version: "1.0.0"
assets:
  cities:
    南京: { card: "cities/nanjing-card.webp", map_pin: "cities/nanjing-pin.svg" }
  routes:
    TECH: { icon: "routes/tech.svg", banner: "routes/tech-banner.webp" }
  rounds:
    1: { scenario: "rounds/r1-scenario.webp" }
```

　　`game-configs/*.yaml` 增加可选字段 `presentation.theme_asset_pack: techventure-v1`，前端读配置 → 加载对应 manifest，**避免硬编码在 TSX**。

### 2.3 命名与版本

- 路径：**小写、kebab-case、与引擎 ID 一致**（`city_id` 与 YAML `cities` 键一致）
- 版本：文件名或 manifest 内 `v` 字段；发布时用 **content hash** 做长期缓存（`?v=abc123` 或 Vite `assetsInlineLimit` 策略）
- **禁止**在组件内散落 `/src/assets/xxx.png` 而无主题映射 — 不利于十赛制扩展

## 三、在现有 React 应用中的嵌入方式

### 3.1 推荐模式（按复杂度递增）

| 模式 | 做法 | 适用 | Token/性能 |
|------|------|------|------------|
| **A. Tailwind + 背景图** | `bg-[url(...)]`、CSS 变量切换主题 | 大厅、决策舱边框、P0～P1 | 优 |
| **B. 静态 import / public URL** | Vite `import img from` 或 `/game-assets/...` | 城市卡片、头图 | 优；注意按需路由懒加载 |
| **C. SVG 内联 / React 组件** | 地图节点、可点击热区 | 三城点选、路线切换 | 优；利于无障碍 |
| **D. `<canvas>` 2D** | 现有 `KnowledgeGraph` 同类 | 轻量动态图、RTS 简易轨迹 | 中 |
| **E. PixiJS / Phaser（仅对局层）** | 独立 `GameCanvas` 组件 | 大地图、多车动画、粒子 | 需 **路由级 code-split** |
| **F. Lottie / Rive** | JSON 驱动 UI 动效 | 结算、徽章、大屏 | 中；注意包体积 |
| **G. iframe 沙箱** | 嵌入独立 mini-game 页 | 极复杂赛制、第三方引擎 | 隔离好；通信需契约 |

### 3.2 与 Zustand / 路由的集成原则

1. **状态仍在 store，画面只订阅** — 与 RTS「HTTP 只读、WS 推送」一致；动画层 **不得** 私自改分或 tick。
2. **一条对局一条路由** — 已有 `/games/:id/play`、`/techventure`；美术包随 `game_config_id` 在页面 `useEffect` 中 `loadManifest(packId)`。
3. **卸载即释放** — 离开对局路由时 `texture.destroy()` / 清空预加载缓存，避免多局切换内存涨。
4. **组织者大屏** — 可共用同一 manifest，只换 **layout 组件**（`BigScreenLayout`），数据仍走 `techventure_admin` API。

### 3.3 预加载与降级

```text
进入 Lobby → 预加载 manifest 中 critical 集（背景、当前城市图标）
进入 Play   → 按轮次懒加载 scenario 图
加载失败   → _shared/placeholder.webp + 文字标签（禁止白屏）
弱网/教室 PC → 提供「精简模式」：关动效、仅 SVG+色块
```

### 3.4 注意事项（踩坑清单）

| 风险 | 说明 | 对策 |
|------|------|------|
| **包体积膨胀** | 大量 PNG 打进 main chunk | 按赛制 **dynamic import**；CDN/独立 `game-assets` 路径 |
| **路径幻觉** | AI 引用不存在的 `/assets/...` | manifest 为唯一真相源；CI 校验 manifest 键存在 |
| **版权** | 素材站授权不清 | 保留 `LICENSE.txt`  per pack；商用需可追溯 |
| **无障碍** | 纯图无文字 | 关键决策旁保留文字+图标；动效 `prefers-reduced-motion` |
| **大屏色差** | 教室投影偏色 | 高对比度主题；避免细线+浅灰字 |
| **与 mock 混淆** | 用假图代替 API | 新资源走 manifest，**不**新增 mock 数据源（蓝图 AP-4） |
| **双端重复** | 学生/组织者各拷一份图 | `_shared` + 构建脚本同步到两个 `public/` |
| **中文路径** | Windows 构建乱码 | 资源路径 **仅 ASCII**（与仓库终端规范一致） |

## 四、美术资源来源建议

### 4.1 来源矩阵

| 来源类型 | 代表 | 适合 | 注意 |
|----------|------|------|------|
| **CC0 / 开源包** | [Kenney.nl](https://kenney.nl/assets)、OpenGameArt | UI 图标、等距城市、车辆 | 风格统一需筛选 |
| **付费游戏素材** | itch.io、Craftpix、Unity Asset Store（2D） | 成套主题、精灵表 | 看清 **教育商用** 条款 |
| **商用图库** | Shutterstock、Adobe Stock | 情境插画、真实城市氛围 | 按张授权，成本较高 |
| **定制外包** | 原画 + UI 设计师 | 品牌统一、十赛制差异化 | 需风格指南（Style Guide） |
| **AI 生成** | SD / Midjourney 等 | 概念图、背景探索 | **需人工修稿+版权审查**；不宜直接当正式包 |
| **学生共创** | 课程作业投稿 | 校园 IP、归属感 | 需审核与授权协议 |
| **官方合作** | 赛事方品牌素材 | LIBF/BPA 等主题赛 | 见 `inspire/a/` 真题库，单独 pack |

### 4.2 风格指南（建议立项时定稿）

- **主视觉**：拟真小店/城市经营（对齐 [06-生涯模式](../06-生涯模式-大循环家园与资源经济.md)），**避免**轻科幻星图为主（见 [53-游戏化](./53-游戏化与局外成长设计.md)）
- **TechVenture**：偏「创业路演 + 区域扩张」— 明亮、卡片式、四路线色板（可与现有 `ROUTE_COLORS` 对齐）
- **浮生记 RTS**：偏「物流地图 + 时间压力」— 俯视或 2.5D 地图、车辆精灵
- **统一栅格**：8px 网格；大屏安全区 16:9、1920×1080 为主

### 4.3 许可与合规（教育产品）

- 每套 `game-assets/<pack>/` 附带 **`CREDITS.md` + `LICENSE`**
- 禁止含 **未授权品牌 Logo、真人肖像、政治敏感符号**
- 未成年人场景：**无赌博视觉隐喻**（老虎机、筹码堆等需教研审核）
- 若资源含字体/音乐，单独列出 **可再分发** 条款

## 五、是否需要「独立运行窗口」与技术栈调整

### 5.1 先澄清：几种「独立」

| 概念 | 含义 | 是否推荐（当前阶段） |
|------|------|----------------------|
| **新浏览器窗口 `window.open`** | 每场比赛弹一个窗口 | ❌ 默认不推荐：焦点混乱、移动端差、登录态同步难 |
| **独立路由 / 对局 Shell** | `/match/:eventId/runtime` 全屏、隐藏主导航 | ✅ **推荐**：SPA 内隔离，易共享 token |
| **动态 chunk（代码分割）** | `import('./TechVentureStage')` | ✅ 必做：避免未开赛加载 Pixi |
| **iframe 子应用** | 每场对局加载 `match-runtime.html` | 🟡 赛制极复杂时再用 |
| **Web Worker** | 路径预览、大地图寻路（不算渲染） | 🟡 RTS 扩展时用 |
| **独立部署的「对局客户端」** | 第二个 Vite 工程 | 🟡 组织者大屏 / 展馆 kiosk 可考虑 |

### 5.2 推荐架构：Match Runtime Layer（对局运行时层）

　　在 **不拆第二个后端、不破坏单 API** 前提下，前端增加一层 **对局运行时**，与平台壳（Layout、生涯、课程）解耦：

```text
┌─────────────────────────────────────────────────────────┐
│  Platform Shell（React Router + Layout + 生涯/课程）      │
├─────────────────────────────────────────────────────────┤
│  Match Runtime（全屏路由，按 engine 动态加载）              │
│  ├─ Shell: 顶栏 tick / 资金 / 提交（React）                │
│  ├─ Stage: 地图/动画（React SVG 或 Pixi Canvas）          │
│  └─ Data: Zustand + WS（只读 state，actions 走 HTTP）     │
├─────────────────────────────────────────────────────────┤
│  Presenter View（可选，组织者大屏 mirror API）            │
└─────────────────────────────────────────────────────────┘
```

**与 CyberCore 的关系：**

| 层 | 职责 | 美术 |
|----|------|------|
| `game-configs/*.yaml` | 规则、城市参数 | `presentation.*` 指向 asset pack |
| `games/<engine>/` | 结算、tick | 无美术 |
| `Match Runtime` | 展示、输入 | manifest 加载、动画 |

### 5.3 技术栈演进路线（对齐 Phase）

| 阶段 | 渲染 | 依赖新增 | 交付 |
|------|------|----------|------|
| **Phase A+（现在）** | React + Tailwind + SVG/WebP | 无强制 | 主题包、城市卡、结算 CSS 动效 |
| **Phase A++** | + `@pixi/react` 或纯 `pixi.js` 单页 | `pixi.js` ~轻量 | RTS 车辆沿边移动、地图缩放 |
| **Phase B** | + Lottie；`match-runtime` 子路由 | `lottie-react` | 大屏排名动画、生涯家园插画 |
| **Phase C** | 可选 Tiled 地图层；Presenter 第二前端 | `pixi-tilemap` 等 | 拟真城市大地图（对齐 [75-](./75-拟真城市世界观设计.md)） |

**不建议** 为 Phase A 引入 Unity WebGL / Unreal Pixel Streaming — 运维与包体对教育场景过重。

### 5.4 大地图与车辆动画的实现要点（浮生记 RTS）

| 需求 | 轻量方案 | 重量方案 |
|------|----------|----------|
| 城市间移动 | 进度条 + 虚线路径 SVG | Pixi 精灵沿贝塞尔移动 |
| 多车 | 列表 + 图标状态 | 多 sprite + 对象池 |
| 大地图 | 可滚动 div + 背景图 | Tiled + 相机跟随 |
| 与 tick 同步 | `arrival_tick` 驱动 CSS `transition-duration` | 插值帧与服务器 tick 对齐，**仅展示** |

　　**硬约束**：动画时长可估算，但 **权威到达时刻以服务端 tick 为准**；客户端不得用动画结束触发业务逻辑。

### 5.5 多场比赛并行与资源效率

- **同一浏览器**：学生通常 **1 场活跃对局**；store 按 `eventId` 分片或进路由时 `resetStore`。
- **多 tab**：避免；若存在，用 `sessionStorage` 存 `activeEventId` 防串台。
- **教室 30+ 人**：资源在 **CDN/静态服务器**；客户端 manifest 缓存；**不要** 每场对局各起一个重 WebGL 上下文（GPU 上限）。

## 六、与声明式 UI 契约的衔接

　　[inspire/b/00-解耦框架](./b商赛界面展示/00-解耦声明式商业模拟框架总览.md) 第三层「界面声明」可扩展为：

```yaml
# game-configs 片段（规划）
presentation:
  asset_pack: techventure-v1
  layout: three-column-decision
  widgets:
    - type: city-map
      props: { selectable: true, asset_key: cities }
    - type: investment-sliders
      props: { dimensions: [tech, fit, show] }
```

　　Phase A 可 **先在 TS 硬编码组件 + manifest**，待 2～3 个赛制稳定后再把 `widgets` 下沉 YAML，避免过早抽象（蓝图 YAGNI）。

## 八、决策摘要

| 问题 | 建议 |
|------|------|
| 美术放哪？ | `content/game-assets/<pack>/` + manifest；`game-configs` 引用 pack |
| 要不要每场对局新窗口？ | **不要**默认弹窗；用 **全屏对局路由 + 动态 import** |
| 要不要改技术栈？ | **渐进**：React 为主；大地图/车辆再 **加 Pixi 层**，不替换整体框架 |
| 要不要独立后端/进程？ | **不要**；静态资源走 CDN/Nginx；逻辑仍单 API |
| 来源？ | CC0 包打底 + 定制主视觉；AI 仅作概念；教育商用授权必查 |
| 与蓝图关系？ | 新表仍归 arena/games 域；资源 **不进** 引擎 Python；推送前更新 `08-` 若新增路径 |
