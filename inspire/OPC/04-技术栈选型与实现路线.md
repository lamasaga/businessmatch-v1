## 二、OPC 新增技术栈

### 2.1 前端层新增

| 技术/库 | 用途 | 理由 |
|---------|------|------|
| **@modelcontextprotocol/sdk-js** | MCP客户端 | 官方JS SDK，用于前端与MCP Server通信 |
| **React Flow** | AI员工局可视化 | 拖拽式AI员工组织架构图 |
| **Monaco Editor** | 代码查看/轻量编辑 | AI员工代码交付物的展示与审阅 |
| **recharts + echarts** | 数据看板 | 财务/增长数据可视化 |
| **react-pdf** | 报告渲染 | BMC/商业计划书PDF生成预览 |

### 2.2 后端层新增

| 技术/库 | 用途 | 理由 |
|---------|------|------|
| **LangGraph (Python)** | AI员工工作流编排 | 复杂状态管理、生产级可靠性，适合Cortex任务编排 |
| **CrewAI (Python)** | 角色驱动AI团队 | 与LangGraph互补，快速构建角色化Agent团队 |
| **OpenAI Agents SDK** | 轻量Agent原型 | 快速验证单Agent能力，作为CrewAI/LangGraph的补充 |
| **mcp (Python/JS)** | MCP协议实现 | Anthropic官方SDK，构建MCP Server/Client |
| **ChromaDB / Qdrant** | 向量数据库 | AI员工长期记忆、知识图谱RAG |
| **Celery + Redis** | 异步任务队列 | AI员工长时间任务（代码生成、数据分析）的后台执行 |
| **Playwright / Puppeteer** | 浏览器自动化 | Scout市场探员的网页抓取、着陆页测试 |

### 2.3 外部服务集成

| 服务 | 用途 | 集成方式 |
|------|------|----------|
| **OpenAI API / Claude API / Gemini API** | LLM推理 | 直接API调用，支持模型路由 |
| **Vercel API** | 前端部署 | MCP Server: `vercel` |
| **GitHub API** | 代码仓库 | MCP Server: `github` |
| **Stripe API** | 支付处理 | MCP Server: `stripe` |
| **Resend API** | 邮件发送 | MCP Server: `resend` |
| **Supabase API** | 数据库托管 | MCP Server: `supabase` |
| **Figma API** | 设计稿协作 | MCP Server: `figma` |
| **Twitter/X API** | 社媒运营 | MCP Server: `twitter` |

### 2.4 部署与基础设施

| 组件 | 选型 | 理由 |
|------|------|------|
| **容器化** | Docker + Docker Compose | 开发环境一致性，AI员工沙箱隔离 |
| **AI沙箱** | Firecracker microVM / gVisor | 安全执行AI生成代码，防止逃逸 |
| **对象存储** | MinIO (本地) / 阿里云OSS (生产) | 设计稿、报告、日志文件存储 |
| **监控** | LangSmith + Sentry | AI Agent可观测性 + 应用异常追踪 |

## 三、核心数据模型

### 3.1 新增实体关系

```
User ──1:1──► CareerProfile (已有)
                │
                ├──1:N──► OneCompany (学生创建的公司)
                │           │
                │           ├──1:N──► Project (项目/产品)
                │           │           │
                │           │           ├──1:N──► Sprint (迭代周期)
                │           │           │           ├──1:N──► Task (任务)
                │           │           │           │           ├──1:N──► Deliverable (交付物)
                │           │           │           │           └──1:N──► TaskLog (执行日志)
                │           │           │           └──1:1──► SprintReview (评审)
                │           │           └──1:N──► Milestone (里程碑)
                │           │
                │           ├──1:N──► AIEmployee (AI员工)
                │           │           │
                │           │           ├──1:N──► SkillRecord (技能记录)
                │           │           └──1:N──► PerformanceReview (绩效)
                │           │
                │           ├──1:N──► FinanceRecord (财务记录)
                │           ├──1:N──► MarketIntel (市场情报)
                │           └──1:N──► GatewayReview (阶段评审)
                │
                └──1:N──► VentureLog (创业日志/叙事)
```

### 3.2 关键表结构（简化）

```sql
-- 学生创建的公司
CREATE TABLE one_companies (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    career_id UUID REFERENCES career_profiles(id),
    name VARCHAR(100) NOT NULL,
    slug VARCHAR(100) UNIQUE NOT NULL,  -- 用于子域名：slug.OPC.edu
    stage VARCHAR(20) CHECK (stage IN ('IDEATE','VALIDATE','BUILD','LAUNCH','SCALE','ARCHIVED')),
    business_model_canvas JSONB,  -- 完整BMC
    brand_config JSONB,           -- 品牌配置
    total_revenue DECIMAL(12,2) DEFAULT 0,
    total_cost DECIMAL(12,2) DEFAULT 0,
    status VARCHAR(20) DEFAULT 'active',
    created_at TIMESTAMP DEFAULT NOW(),
    launched_at TIMESTAMP
);

-- AI员工
CREATE TABLE ai_employees (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    company_id UUID REFERENCES one_companies(id),
    codename VARCHAR(20) NOT NULL,  -- 如 "DEV-01"
    role_type VARCHAR(30) NOT NULL, -- "strategist" | "worker" | "advisor" | "scout"
    avatar_emoji VARCHAR(10),
    level INT DEFAULT 1 CHECK (level BETWEEN 1 AND 5),
    skills JSONB DEFAULT '[]',      -- [{"skill": "frontend", "level": 3}]
    mcp_tools JSONB DEFAULT '[]',   -- 授权的工具列表
    personality_prompt TEXT,        -- 角色设定Prompt
    memory_vector_id VARCHAR(100),  -- 指向向量库
    status VARCHAR(20) DEFAULT 'idle',
    tasks_completed INT DEFAULT 0,
    satisfaction_score DECIMAL(3,2) DEFAULT 0,  -- 学生评分均值
    created_at TIMESTAMP DEFAULT NOW()
);

-- 任务与执行
CREATE TABLE ai_tasks (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    company_id UUID REFERENCES one_companies(id),
    employee_id UUID REFERENCES ai_employees(id),
    sprint_id UUID,
    title VARCHAR(200) NOT NULL,
    description TEXT,
    task_type VARCHAR(30),  -- "code" | "design" | "copy" | "research" | "analysis"
    status VARCHAR(20) DEFAULT 'pending' CHECK (status IN ('pending','in_progress','review','completed','rejected')),
    requirements JSONB,     -- 结构化需求
    deliverables JSONB,     -- 交付物清单
    mcp_calls JSONB,        -- MCP调用日志
    execution_logs JSONB,   -- 执行过程日志
    student_review TEXT,    -- 学生验收评语
    student_rating INT CHECK (student_rating BETWEEN 1 AND 5),
    started_at TIMESTAMP,
    completed_at TIMESTAMP,
    created_at TIMESTAMP DEFAULT NOW()
);

-- 阶段评审
CREATE TABLE gateway_reviews (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    company_id UUID REFERENCES one_companies(id),
    stage VARCHAR(20) NOT NULL,
    reviewer_type VARCHAR(20),  -- "ai_panel" | "mentor" | "peer"
    review_data JSONB,          -- 评审维度打分
    decision VARCHAR(20) CHECK (decision IN ('pass','conditional','fail')),
    feedback TEXT,
    reviewed_at TIMESTAMP DEFAULT NOW()
);

-- 财务记录
CREATE TABLE finance_records (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    company_id UUID REFERENCES one_companies(id),
    record_type VARCHAR(20) CHECK (record_type IN ('revenue','cost')),
    category VARCHAR(50),
    amount DECIMAL(12,2) NOT NULL,
    currency VARCHAR(3) DEFAULT 'CNY',
    is_real_money BOOLEAN DEFAULT FALSE,  -- 区分模拟/真实
    description TEXT,
    recorded_at TIMESTAMP DEFAULT NOW()
);
```

## 四、API 设计（新增）

### 4.1 OPC 核心接口

```yaml
# 公司管理
POST   /api/v1/opc/companies              # 创建公司
GET    /api/v1/opc/companies/{id}         # 公司详情
PATCH  /api/v1/opc/companies/{id}         # 更新公司信息
DELETE /api/v1/opc/companies/{id}         # 归档公司

# AI员工管理
GET    /api/v1/opc/companies/{id}/employees          # 员工列表
POST   /api/v1/opc/companies/{id}/employees          # 雇佣新员工
GET    /api/v1/opc/employees/{emp_id}               # 员工详情
PATCH  /api/v1/opc/employees/{emp_id}/skills        # 升级技能
POST   /api/v1/opc/employees/{emp_id}/tasks         # 派发任务
GET    /api/v1/opc/employees/{emp_id}/tasks         # 任务历史

# 任务与执行
GET    /api/v1/opc/tasks/{task_id}        # 任务详情
POST   /api/v1/opc/tasks/{task_id}/review # 学生验收任务
GET    /api/v1/opc/tasks/{task_id}/logs   # 执行日志

# 创业流水线
POST   /api/v1/opc/companies/{id}/sprints           # 创建Sprint
GET    /api/v1/opc/companies/{id}/sprints           # Sprint列表
POST   /api/v1/opc/companies/{id}/gateway-reviews   # 提交阶段评审
GET    /api/v1/opc/companies/{id}/gateway-reviews   # 评审历史

# 财务
GET    /api/v1/opc/companies/{id}/finance           # 财务报表
POST   /api/v1/opc/companies/{id}/finance/records   # 记账

# MCP工具
GET    /api/v1/opc/mcp/tools              # 可用MCP工具列表
POST   /api/v1/opc/mcp/tools/{tool}/call  # 调用MCP工具（调试用）

# 实时通信（WebSocket）
WS     /ws/opc/companies/{id}             # 公司实时状态推送
WS     /ws/opc/employees/{emp_id}         # AI员工实时进度推送
```

## 五、渐进式实施路线

### Phase 0：基础准备（与现有平台并行，4-6周）

**目标**：在不影响现有MVP的前提下，搭建OPC基础设施

| 任务 | 优先级 | 依赖 | 验收标准 |
|------|--------|------|----------|
| 数据库Schema设计+迁移 | P0 | — | 新表创建，与现有表无冲突 |
| 后端AI服务模块搭建 | P0 | — | FastAPI新路由，独立文件组织 |
| MCP协议层原型 | P0 | — | 至少1个内部MCP Server可运行 |
| 前端OPC路由+空壳页面 | P0 | — | /opc/* 路由可访问 |
| 向量数据库部署 | P1 | — | ChromaDB/Qdrant可写入/查询 |
| 异步任务队列(Celery) | P1 | — | 后台任务可执行 |

### Phase 1：AI员工局 MVP（6-10周）

**目标**：学生可雇佣AI员工、派发简单任务、验收交付物

| 任务 | 优先级 | 说明 |
|------|--------|------|
| AI员工CRUD+角色定义 | P0 | 4种基础角色模型 |
| 任务派发流水线 | P0 | 文本任务 → LLM → 交付物 |
| AI员工可视化面板 | P0 | React Flow组织架构图 |
| 简单MCP工具集成 | P0 | web_search, text_generation, spreadsheet |
| 学生验收界面 | P0 | 查看交付物+评分+评语 |
| AI员工升级系统 | P1 | 经验值+技能树 |
| 记忆系统V1 | P1 | 单任务上下文记忆 |

### Phase 2：创意孵化流水线（8-12周）

**目标**：完成 IDEATE → VALIDATE 阶段的可运行流程

| 任务 | 优先级 | 说明 |
|------|--------|------|
| BMC协作编辑器 | P0 | 9宫格画布，AI辅助填充 |
| 竞品分析自动化 | P0 | Scout + web_search MCP |
| 着陆页快速构建 | P0 | 集成Carrd/Framer API或自研生成器 |
| 假门测试系统 | P0 | 点击追踪+转化分析 |
| 用户访谈辅助 | P1 | UR-01生成访谈提纲+归纳反馈 |
| 阶段评审AI面板 | P1 | 自动化BMC检查+评分 |

### Phase 3：MVP构建与发射（10-16周）

**目标**：完成 BUILD → LAUNCH 阶段

| 任务 | 优先级 | 说明 |
|------|--------|------|
| 代码生成+沙箱执行 | P0 | DEV-01核心能力，安全运行AI代码 |
| 设计稿生成 | P0 | DES-01对接Figma API或自研生成 |
| 多平台部署集成 | P0 | Vercel/微信小程序/有赞等 |
| 支付集成 | P0 | Stripe/微信支付，测试模式+真实模式 |
| 发射 playbook 模板 | P1 | 5种发射策略的SOP+素材模板 |
| 数据看板 | P1 | 核心指标追踪+异常告警 |

### Phase 4：规模运营与认证（16-24周）

**目标**：完整SCALE阶段 + 毕业认证体系

| 任务 | 优先级 | 说明 |
|------|--------|------|
| 运营自动化工作流 | P0 | n8n/Zapier式可视化编排 |
| 财务系统自动记账 | P0 | 收入/成本自动分类 |
| 法务合规检查 | P1 | Ethos扩展，合同/隐私政策模板 |

## 六、技术风险与规避

| 风险 | 影响 | 规避策略 |
|------|------|----------|
| LLM API成本失控 | 💰 高 | 模型路由（简单任务用廉价模型）、Token配额管理、学校级套餐 |
| AI生成代码安全 | 🔒 高 | gVisor沙箱、网络白名单、无状态执行、禁止文件系统持久化 |
| AI幻觉导致错误商业决策 | ⚠️ 中 | 所有AI建议标注置信度；关键决策强制人工确认；知识图谱RAG约束 |
| 学生隐私泄露 | 🔒 高 | 真实业务数据与教学数据隔离；最小权限原则；学校可本地化部署 |
| 平台依赖（Vercel/Stripe等） | ⚠️ 中 | 多平台备选方案；核心能力不绑定单一供应商；教育优惠申请 |
| 并发性能（开学季） | ⚠️ 中 | 无状态API设计；Celery异步化AI任务；Redis缓存热点数据 |
