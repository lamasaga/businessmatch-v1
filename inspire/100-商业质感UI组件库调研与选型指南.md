## 二、基础组件层：整体设计与系统

### 2.1 shadcn/ui —— 现代商业应用的事实标准

| 属性 | 详情 |
|------|------|
| **GitHub** | `shadcn-ui/ui` |
| **模式** | 复制粘贴组件（非 npm 依赖，代码完全在仓库内） |
| **底层** | Radix UI 原语 + Tailwind CSS |
| **许可** | MIT |
| **成本** | 免费 |

**为什么成为 2025~2026 商业应用首选：**

- **代码完全自有** — 组件源码在你仓库里，无外部依赖风险，可任意修改
- **零运行时开销** — 无 CSS-in-JS 运行时，纯 Tailwind 类名
- **无障碍优先** — 基于 Radix UI 的 battle-tested 原语
- **RSC 优化** — React Server Components 友好，最小客户端 JS
- **TypeScript-first** — 类型完整，IDE 提示友好

**商识唯智现状：** 学生端/教师端已在使用 shadcn/ui 作为基础组件层。本文所有推荐均以「shadcn/ui 为基础，在其上做扩展」为前提。

---

### 2.2 Tailwind Plus（原 Tailwind UI）—— 官方生产级组件块

| 属性 | 详情 |
|------|------|
| **出品** | Tailwind CSS 官方团队 |
| **组件数** | 500+ UI blocks |
| **包含** | Catalyst UI Kit（启动组件套件） |
| **价格** | 付费订阅（终身访问含更新） |
| **框架** | React、Vue、纯 HTML |

**商业优势：**
- 由 Tailwind CSS 创作者亲自设计，一致性极高
- 覆盖 App、Marketing、eCommerce 三大场景
- 生产就绪的交互模式（分页、筛选、表单验证）
- 定期更新，跟随 Tailwind 版本演进

**与 shadcn/ui 的关系：** Tailwind Plus 提供**设计模式和页面结构**，shadcn/ui 提供**可交互的基础组件**。两者互补而非竞争。

### 2.3 企业级传统组件库（参考对比）

以下库在大型企业中广泛使用，但与 shadcn/ui 的「复制粘贴」哲学不同，它们以 npm 包形式分发：

| 库 | Stars | 特点 | 适合场景 | 与 shadcn 对比 |
|----|-------|------|----------|---------------|
| **Material-UI (MUI)** | 90k+ | 最全面的组件集，10+ 年积累 | 大型 Material Design 应用 | 更重、更封闭 |
| **Ant Design** | 90k+ | 60+ 密集功能组件，Table/Form/Tree 极强 | 中后台数据密集型工具 | 体积大(~200KB)，亚洲流行 |
| **Fluent UI (Microsoft)** | — | 微软官方出品，Teams/Azure Portal 在用 | MS 生态集成、合规要求高 | 设计风格绑定 MS |
| **HeroUI (原 NextUI)** | 28k+ | React Aria 基础，SSR 优化，玻璃拟态 | 现代感 SaaS 产品 | 视觉更精致，但生态小于 shadcn |
| **PrimeReact** | 6k+ | 90+ 组件，商业支持可选 | 最大覆盖率需求 | 传统依赖模式 |

**商识唯智建议：** 在已有 shadcn/ui 的基础上，**不引入**第二套完整组件库。如需特定组件，优先从 shadcn 生态扩展中获取。

## 三、数据报表层：仪表板与可视化

### 3.1 Tremor —— 数据分析仪表板首选 ⭐

| 属性 | 详情 |
|------|------|
| **GitHub** | `tremorlabs/tremor` |
| **Stars** | 14k+ |
| **许可** | Apache 2.0 |
| **栈** | React + Tailwind + Recharts |

**核心组件：**

| 组件 | 用途 | 商识唯智场景 |
|------|------|----------|
| `KpiCard` | 关键指标卡片 | 赛后统计：净利润、ROI、排名 |
| `AreaChart` / `BarChart` / `DonutChart` | 数据可视化 | 价格走势、市场份额、资源分布 |
| `Tracker` | 状态追踪条 | 赛事回合进度、任务完成度 |
| `Table` | 数据表格 | 排行榜、交易记录、成绩明细 |
| `Badge` / `Callout` / `Card` | 信息展示 | 等级标签、系统通知、面板容器 |

**为什么适合商识唯智：**
- 深色/浅色双主题，默认调色板克制专业
- 图表 + 指标卡片 + 表格 = 商业模拟平台的三大展示需求
- 与 `React 19 + Tailwind` 栈完全兼容
- 可直接用 shadcn/ui 的 Button/Dialog/Select 与之组合

**安装：**
```bash
npm install @tremor/react
```

### 3.2 Number Flow —— 数字动画专家 ⭐

| 属性 | 详情 |
|------|------|
| **GitHub** | `barvian/number-flow` |
| **Stars** | 6.3k+ |
| **周下载** | 17万+ |
| **许可** | MIT |
| **包体积** | ~6.8KB gzipped |

**核心特征：**
- 数字位逐个滚动切换（类似里程表/老虎机），Apple 般的丝滑
- 基于原生 Web Animations API，零外部依赖
- 支持货币、百分比、紧凑记数法（Intl.NumberFormat）
- 多语言本地化
- 无障碍：尊重 `prefers-reduced-motion`

**被谁使用：** X (Twitter)、Dub.co 等生产环境

**商识唯智场景：**
- 赛后成绩公布时的分数滚动动画
- 实时价格更新的数字过渡
- KPI 卡片中「净利润从 $0 增长到 $12,500」的计数动画

**快速使用：**
```jsx
import NumberFlow from '@number-flow/react'

<NumberFlow
  value={profit}
  format={{ style: 'currency', currency: 'USD' }}
  className="text-2xl font-bold"
/>
```

### 4.3 Aceternity UI —— 高端视觉动效

| 属性 | 详情 |
|------|------|
| **官网** | [ui.aceternity.com](https://ui.aceternity.com) |
| **作者** | Manu Arora |
| **核心** | 3D 透视、光影、磁吸等高端视觉效果 |

**关键动效组件：**

| 组件 | 效果 | 适用场景 |
|------|------|----------|
| `3D Card Effect` | 卡片 3D 倾斜跟随鼠标 | 特色功能展示 |

- 课程/功能介绍页
- 学生端「生涯档案」展示页

**不建议在以下场景使用：**
- 高频操作的数据表格
- 需要快速扫描的报表页面
- 比赛中需要毫秒级响应的界面

## 六、选型决策框架

### 6.1 按场景选型

| 场景 | 推荐方案 | 理由 |
|------|----------|------|
| **教师端数据面板**（成绩/排名/统计） | **Tremor** + shadcn/ui | 数据可视化专业，与现有栈兼容 |
| **学生端生涯档案**（成就/成长曲线） | **shadcn/ui** + **Magic UI** | 动画增强体验，不干扰数据阅读 |
| **平台首页/落地页** | **Aspect** 或 **Mainline** | 完整页面结构，快速上线 |
| **比赛中实时数据**（价格/库存/排名） | **Number Flow** + shadcn/ui | 数字动画流畅，性能开销低 |
| **赛后复盘报告** | **Tremor** + **Magic UI** `BorderBeam` | 数据密度高 + 关键指标高亮 |
| **营销/活动页面** | **Aceternity UI**（选择性） | 视觉冲击力强 |

### 6.2 按动效强度选型

| 动效强度 | 推荐方案 | 典型用法 |
|----------|----------|----------|
| **无动效**（纯静态） | shadcn/ui 默认 | 高频操作界面、表格 |
| **微动效**（ subtle ） | **Motion Primitives** `SlidingNumber` | 数字更新、状态切换 |
| **中等动效** | **Magic UI** `NumberTicker` + `BorderBeam` | KPI 卡片、按钮反馈 |
| **强动效** | **Aceternity UI** `3DCard` + `Spotlight` | 首页、展示页、营销 |

## 七、与商识唯智技术栈的对齐

### 7.1 当前栈兼容性矩阵

商识唯智当前前端栈：`React 19.2 + TypeScript ~6.0 + Vite 8.0 + Tailwind CSS 3.4 + shadcn/ui + Zustand`

| 方案 | 兼容性 | 迁移成本 | 风险 |
|------|--------|----------|------|
| **shadcn/ui 扩展组件** | ✅ 完美 | 无 | 无 |
| **Tremor** | ✅ 完美 | 极低 | 低 |
| **Number Flow** | ✅ 完美 | 极低 | 低 |
| **Magic UI** | ✅ 完美 | 低 | 低 |
| **Motion Primitives** | ✅ 完美 | 低 | 低（Pro 部分付费） |
| **Aceternity UI** | ✅ 兼容 | 低 | 中（动效过重需谨慎使用） |
| **Tailwind Plus** | ✅ 兼容 | 低 | 低（付费） |
| **MUI / AntD / Fluent** | ⚠️ 需评估 | 高 | 高（与现有 shadcn 冲突） |

### 7.2 推荐分层架构

```
┌─────────────────────────────────────────┐
│  Layer 3: 动效层（按需引入）              │
│  Magic UI / Motion Primitives /          │
│  Number Flow / Aceternity（选件）        │
├─────────────────────────────────────────┤
│  Layer 2: 数据报表层                      │
│  Tremor（图表+KPI+表格）                  │
│  TanStack Table v8（复杂数据表格）         │
├─────────────────────────────────────────┤
│  Layer 1: 基础组件层（已存在）            │
│  shadcn/ui（Button/Card/Dialog/Select）  │
│  Tailwind CSS 主题令牌                     │
└─────────────────────────────────────────┘
```

### 7.3 Bundle 体积控制

| 策略 | 说明 |
|------|------|
| **按需引入** | shadcn/ui、Magic UI、Motion Primitives 均支持单组件安装 |
| **Tree Shaking** | Vite 生产构建自动剔除未使用代码 |
| **Code Splitting** | 动效组件延迟加载（`React.lazy`），首屏不加载 |
| **Reduced Motion** | 所有动效组件需检测 `prefers-reduced-motion`，尊重用户偏好 |

## 九、风险与约束

| 风险 | 说明 | 缓解策略 |
|------|------|----------|
| **动效过载** | 过多动画干扰数据阅读，降低效率 | 核心数据页面禁用强动效；仅在高价值/低频页面使用 |
| **Reduced Motion** | 部分用户（眩晕/注意力障碍）需要关闭动效 | 所有动效组件必须检测 `prefers-reduced-motion` |
| **Bundle 膨胀** | 大量动效库增加打包体积 | 按需引入 + Code Splitting + Tree Shaking |
| **性能瓶颈** | Framer Motion 在低端设备上可能卡顿 | 提供降级方案（纯 CSS 过渡）；性能监控 |
| **学习成本** | 动效参数调试耗时 | 建立商识唯智内部动效规范（时长、缓动曲线、使用场景） |
| **Pro 付费墙** | Magic UI / Motion Primitives / Aceternity 均有付费组件 | 优先使用免费版；付费组件评估 ROI 后再引入 |

## 十、待探索问题

1. **商识唯智动效规范。** 是否需要建立一套内部动效设计令牌（duration、 easing、delay 的标准值）？
2. **Reduced Motion 全局开关。** 是否在用户设置中提供「关闭所有动效」的选项？
3. **Tremor 与现有 shadcn Table 的冲突。** 两者都提供 Table 组件，是否统一使用 TanStack Table + shadcn 样式？
4. **比赛中是否允许动效。** RTS 模式下毫秒级响应要求是否完全禁止非必要动效？
5. **教师端与学生端的动效差异。** 教师端更重信息密度（少动效），学生端更重体验（适度动效）？

---

> **与 99-游戏化 UI 的关系总结：** 99 号解决「比赛内如何像游戏一样好玩」，100 号解决「平台页如何像专业产品一样好用」。两者共享 React 19 + Tailwind + shadcn/ui 基础栈，在 Layer 3 动效层可以有限复用（如 Number Flow 同时服务比赛内价格显示和平台成绩展示）。
