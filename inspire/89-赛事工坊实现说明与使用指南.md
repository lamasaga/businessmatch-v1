## 一、已实现的功能

赛事工坊是一个**热迭代的商赛设计调试环境**，支持在浏览器中完成「选择模板 → 编辑 YAML → 即时运行 → 深度调试 → 一键发布」的完整闭环。

| 功能 | 状态 | 说明 |
|------|------|------|
| 模板选择 | ✅ | 加载现有 `content/game-configs/*.yaml` 作为起点 |
| YAML 编辑器 | ✅ | 实时编辑配置，带语法高亮 |
| 热重载 | ✅ | 修改 YAML 后点击「应用」即时生效，无需重启后端 |
| 单步运行 | ✅ | 每步推进一个 tick/round，观察状态变化 |
| 自动运行 | ✅ | 开始/暂停控制 |
| 重置 | ✅ | 保留配置，从头开始运行 |
| 市场价格监视 | ✅ | 各城各品价格实时表格 |
| AI 决策追踪 | ✅ | 查看每个 AI 的决策和原因 |
| 事件时间线 | ✅ | 随机事件触发记录 |
| 调试日志 | ✅ | 按类型分组的结构化日志 |
| 排名预览 | ✅ | 玩家与 AI 的资产排名 |
| 一键发布 | ✅ | 将配置写入 `content/game-configs/`，自动注册到 CyberCore |

## 二、架构总览

```
┌─────────────────────────────────────────────────────────────┐
│  前端 (React + Vite)                                         │
│  ├─ /sandbox 路由 → SandboxPage.tsx（三栏布局）              │
│  │   ├─ 左栏：TemplateSelector + YamlEditor                  │
│  │   ├─ 中栏：RunControls + GamePreview（价格表/排名/事件）   │
│  │   └─ 右栏：DebugPanel（市场/AI/事件/日志）                │
│  └─ stores/sandboxStore.ts（Zustand 状态管理）               │
└────────────────────────┬────────────────────────────────────┘
                         │ HTTP API
┌────────────────────────┴────────────────────────────────────┐
│  后端 (FastAPI)                                              │
│  ├─ app/domains/sandbox/                                     │
│  │   ├─ models.py          → SandboxSession（内存对象）      │
│  │   ├─ services/                                            │
│  │   │   ├─ hot_config.py  → 内存 YAML 热管理               │
│  │   │   ├─ debugger.py    → 调试数据收集器                 │
│  │   │   └─ runner.py      → 沙盒引擎驱动器                 │
│  │   └─ api.py             → /api/v1/sandbox/* 路由         │
│  └─ 复用现有引擎：games/trading/（不复制代码）              │
└─────────────────────────────────────────────────────────────┘
```

**关键设计原则**：沙盒与正式运行共用同一套引擎代码，通过 `sandbox_mode` 控制调试数据收集，确保行为一致性。

## 三、后端模块详解

### 3.1 文件清单

| 文件 | 职责 |
|------|------|
| `app/domains/sandbox/__init__.py` | 模块导出 |
| `app/domains/sandbox/models.py` | `SandboxSession` 内存模型（UUID、配置、运行状态、世界状态、调试日志） |
| `app/domains/sandbox/services/hot_config.py` | `HotConfigManager`：内存配置字典，支持从模板加载 / 从 YAML 加载 / 热更新 |
| `app/domains/sandbox/services/debugger.py` | `DebugCollector`：记录价格计算、AI 决策、事件触发、世界状态快照 |
| `app/domains/sandbox/services/runner.py` | `SandboxRunner`：直接驱动 `trading` 引擎，支持 auto/step 模式 |
| `app/domains/sandbox/api.py` | FastAPI 路由：sessions CRUD、start/step/pause/reset、debug、publish、templates |

### 3.2 API 端点

| 方法 | 路由 | 用途 |
|------|------|------|
| GET | `/api/v1/sandbox/templates` | 列出所有可用模板 |
| POST | `/api/v1/sandbox/sessions` | 创建沙盒会话（config_id 或 config_yaml） |
| GET | `/api/v1/sandbox/sessions` | 列出所有会话 |
| GET | `/api/v1/sandbox/sessions/:id` | 获取会话状态 |
| PUT | `/api/v1/sandbox/sessions/:id/config` | 热更新 YAML 配置 |
| POST | `/api/v1/sandbox/sessions/:id/start` | 开始自动运行 |
| POST | `/api/v1/sandbox/sessions/:id/step` | 单步推进 |
| POST | `/api/v1/sandbox/sessions/:id/pause` | 暂停运行 |
| POST | `/api/v1/sandbox/sessions/:id/reset` | 重置运行状态 |
| GET | `/api/v1/sandbox/sessions/:id/state` | 获取世界状态 |
| GET | `/api/v1/sandbox/sessions/:id/debug` | 获取调试数据 |
| POST | `/api/v1/sandbox/sessions/:id/publish` | 发布为正式配置 |
| DELETE | `/api/v1/sandbox/sessions/:id` | 删除会话 |

### 3.3 SandboxRunner 运行逻辑

`runner.py` 直接调用引擎核心函数，**不经过 ArenaMatch 生命周期**：

```
setup(config) → 初始化世界（价格、AI、玩家）
  ↓
step() → AI 决策 → 生成事件 → 计算价格 → 应用交易 → 更新排名
  ↓
debug.log 记录每一步的中间值
```

支持两种模式：
- **回合制**（`trading-v1`）：每步一个 round，手动推进
- **RTS**（`trading-v2-rts`）：每步一个 tick，模拟 5 秒间隔

## 五、使用流程

### 5.1 创建新赛事

1. 访问 `http://localhost:5173/sandbox`
2. 左栏选择模板（如 **trading-v2-rts**）
3. YAML 编辑器加载模板内容
4. 修改参数（如 `tick_interval_sec: 5 → 3`）
5. 点击「应用」→ 运行状态自动重置
6. 点击「单步」→ 观察价格变化和 AI 行为
7. 右栏「市场」标签查看价格计算过程
8. 右栏「AI」标签查看每个 AI 的决策
9. 反复调整参数 → 单步验证 → 直到满意

### 5.2 发布赛事

1. 点击左下角「发布为正式配置」
2. 输入配置 ID（如 `mygame-v1`）
3. 确认后，YAML 写入 `webapp/backend/content/game-configs/mygame-v1.yaml`
4. CyberCore 缓存自动清除，新配置立即可用
5. 在练习模式或组织者端即可选择该配置创建比赛

### 5.3 与现有流程的对比

| 环节 | 旧流程 | 赛事工坊 |
|------|--------|----------|
| 编辑配置 | 修改文件 → 保存 → 重启后端 | 浏览器内编辑 → 点击应用 |
| 验证效果 | 创建练习局 → 等待 AI 行动 → 查看日志 | 单步推进 → 实时查看价格/AI/事件 |
| 发布 | 手动复制 YAML 到正确目录 | 一键发布，自动命名和注册 |

## 九、注意事项

1. **沙盒会话为内存存储**：重启后端后所有会话丢失，发布前的配置请及时保存（ YAML 可复制到本地）。
2. **学生端不应暴露沙盒入口**：当前 `/sandbox` 路由需要登录，建议后续增加 `admin` 角色限制。
3. **引擎一致性**：沙盒 runner 直接调用 `games/trading/market.py` 等核心函数，与正式运行结果一致。
4. **AI 决策为简化版**：沙盒中的 AI 逻辑是 runner 内嵌的简化实现（套利 + 随机），与正式练习模式的 `ai_trader.py` 略有差异，不影响参数调试。
