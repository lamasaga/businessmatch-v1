## 命名约定

| 术语 | 含义 |
|------|------|
| **教师** | 使用 `:5174` organizer-frontend 的 `teacher` 或 `admin` 角色用户 |
| **学生** | 使用 `:5173` 学生端的 `student` 角色用户 |
| **营团** | `teaching_group`，6 位邀请码的班级/社团容器 |
| **赛季** | `season`，营团内的教学段落 |
| **里程碑** | `milestone`，赛季内的教学单元 |
| **商赛** | `competition_event`，通过 `organizer-frontend` 创建的正式赛/练习赛 |
| **复盘** | `debrief`，赛后班级表现汇总页 |

## Feature 1: 学员进度看板 (P0)

> **价值**：让教师一眼看出谁积极参与、谁掉队了，不用手动翻名册和比赛记录。

```gherkin
Feature: 学员进度看板
  作为教师
  我希望查看营团内所有学员的参与状态和进度
  以便及时发现掉队学员并介入

  Background:
    Given 教师 "王老师" 已登录 organizer-frontend
    And 王老师拥有一个名为 "高二商赛社" 的营团
    And 营团内有 3 名学员：小明、小红、小刚
    And 小明参加了 3 场营内商赛，累计获得 1250 XP
    And 小红参加了 1 场营内商赛，累计获得 400 XP
    And 小刚未参加任何商赛，XP 为 0

  # ── 场景 1：查看进度总览 ──
  Scenario: 教师进入学员进度 Tab 查看全班状态
    Given 王老师在 "高二商赛社" 营团详情页
    When 王老师点击 "学员进度" Tab
    Then 页面显示学员列表，包含列：昵称、加入时间、参赛场次、累计 XP、最近活跃、状态标签
    And 小明的状态标签为 "🟢 积极"
    And 小红的状态标签为 "🟡 正常"
    And 小刚的状态标签为 "🔴 需关注"

  # ── 场景 2：状态标签规则验证 ──
  Scenario Outline: 学员状态标签按规则计算
    Given 学员 "<学员>" 加入营团 <加入天数> 天
    And 参赛 <参赛场次> 场
    And 最近活跃在 <最近活跃> 天前
    When 教师查看学员进度看板
    Then "<学员>" 的状态标签为 "<预期标签>"

    Examples:
      | 学员   | 加入天数 | 参赛场次 | 最近活跃 | 预期标签 |
      | 积极生 | 10      | 3        | 2        | 🟢 积极  |
      | 普通生 | 10      | 1        | 5        | 🟡 正常  |
      | 掉队生 | 10      | 0        | 10       | 🔴 需关注 |
      | 新生   | 3       | 0        | 3        | ⚪ 从未参赛 |

  # ── 场景 3：筛选与排序 ──
  Scenario: 教师按状态筛选需关注的学员
    Given 王老师在学员进度 Tab
    When 王老师点击 "筛选" 下拉框，选择 "需关注"
    Then 列表仅显示小刚
    And 不显示小明和小红

  Scenario: 教师按参赛场次降序排列
    Given 王老师在学员进度 Tab
    When 王老师点击 "参赛场次" 表头
    Then 列表按参赛场次从高到低排列：小明(3) → 小红(1) → 小刚(0)

  # ── 场景 4：搜索学员 ──
  Scenario: 教师搜索特定学员
    Given 王老师在学员进度 Tab
    When 王老师在搜索框输入 "小"
    Then 列表显示小明、小红、小刚
    When 王老师在搜索框输入 "明"
    Then 列表仅显示小明

  # ── 场景 5：查看学员详情抽屉 ──
  Scenario: 教师点击学员行查看参赛时间线
    Given 王老师在学员进度 Tab
    When 王老师点击 "小明" 所在行
    Then 右侧弹出学员详情抽屉
    And 抽屉显示小明的参赛时间线：
      | 日期   | 赛制       | 名次 |
      | 05-22 | 回合制 #1  | 第3名 |
      | 05-25 | TechV #2   | 第1名 |
      | 05-28 | 浮生记 #3  | 第5名 |
    And 抽屉显示小明的 XP 变化简图

  # ── 场景 6：导出进度 CSV ──
  Scenario: 教师导出学员进度数据
    Given 王老师在学员进度 Tab
    When 王老师点击 "导出 CSV" 按钮
    Then 浏览器下载文件 "高二商赛社-学员进度-2026-06-01.csv"
    And CSV 内容包含所有学员的：昵称、加入时间、参赛场次、累计 XP、状态标签
```

## Feature 2: 赛后复盘汇总 (P0)

> **价值**：商赛结束后自动汇总班级表现，教师一键发布，学生端即时收到复盘。

```gherkin
Feature: 赛后复盘汇总
  作为教师
  我希望比赛结束后查看全班决策分布和排名
  以便生成复盘并发布给学生

  Background:
    Given 教师 "王老师" 已登录 organizer-frontend
    And 王老师的营团 "高二商赛社" 有一场已结束的 TechVenture 班级赛 "T2-001"
    And T2-001 有 20 名学员参与
    And 比赛结算数据已写入数据库

  # ── 场景 1：比赛结束后自动可查看复盘 ──
  Scenario: 已结束比赛显示"复盘"入口
    Given 王老师在 "高二商赛社" 营团详情页的 "营内商赛" Tab
    When 王老师查看状态为 "已结束" 的比赛 "T2-001"
    Then 比赛卡片上显示 "复盘" 按钮
    And 不显示 "控场" 按钮

  # ── 场景 2：查看通用复盘内容 ──
  Scenario: 教师查看 TechVenture 班级赛复盘
    Given 王老师在营内商赛列表点击 "复盘" 按钮
    When 页面跳转到赛后复盘页
    Then 页面显示比赛概览：
      | 字段       | 值              |
      | 赛制       | TechVenture     |
      | 结束时间   | 2026-05-28 10:00 |
      | 参与人数   | 20              |
    And 页面显示班级排名 Top 5
    And 页面显示全班 XP 发放明细

  # ── 场景 3：查看赛制特有复盘内容 ──
  Scenario: TechVenture 复盘显示决策分布
    Given 王老师在 TechVenture 赛后复盘页
    Then 页面显示 "路线选择分布"
    And 路线 A 被 8 支队伍选择 (40%)
    And 路线 B 被 7 支队伍选择 (35%)
    And 路线 C 被 5 支队伍选择 (25%)
    And 页面显示 BQI 统计：均值 72、最高 95、最低 45

  Scenario: 回合制 Trading 复盘显示交易统计
    Given 王老师在回合制 Trading 赛后复盘页
    Then 页面显示 "人均交易次数：4.2 次"
    And 页面显示 "最常买卖商品 Top 3"
    And 页面显示 "典型失误列表"

  Scenario: 浮生记 RTS 复盘显示物流热力图
    Given 王老师在浮生记 RTS 赛后复盘页
    Then 页面显示 "城市间物流热力图"
    And 页面显示 "人均 tick 内操作次数：3.5 次"
    And 页面显示 "车辆购买率：60%"

  # ── 场景 4：发布复盘到学生端 ──
  Scenario: 教师发布复盘
    Given 王老师在赛后复盘页
    And 页面显示 "当前复盘尚未发布"
    When 王老师编辑教师笔记为 "这节课大家路线选择比较保守，建议下次尝试差异化策略"
    And 王老师勾选 AI 洞察：
      | 洞察内容                              |
      | 80% 的队伍选择了路线 A，竞争激烈       |
      | 3 支队伍 BQI 低于 50，品牌策略需加强   |
    And 王老师点击 "发布复盘" 按钮
    Then 页面提示 "复盘已发布"
    And 学生端 "/camp" 顶部显示通知 "新的班级复盘已发布：T2-001"

  # ── 场景 5：发布后的复盘不可重复发布 ──
  Scenario: 已发布复盘显示发布状态
    Given 王老师已发布 T2-001 的复盘
    When 王老师再次进入 T2-001 复盘页
    Then 页面显示 "复盘已于 2026-05-28 14:30 发布"
    And "发布复盘" 按钮变为禁用状态

  # ── 场景 6：下载复盘摘要 ──
  Scenario: 教师下载复盘卡片
    Given 王老师在赛后复盘页
    When 王老师点击 "下载摘要" 按钮
    Then 浏览器下载图片 "T2-001-班级复盘卡.png"
    And 图片包含：排名、决策分布、教师笔记
```

## Feature 3: 营团公告 (P0)

> **价值**：教师无需依赖微信群，直接在平台内向营团学员发布公告。

```gherkin
Feature: 营团公告
  作为教师
  我希望在营团内发布公告通知学员
  以便同步教学安排和提醒

  Background:
    Given 教师 "王老师" 已登录 organizer-frontend
    And 王老师拥有一个名为 "高二商赛社" 的营团
    And 营团内有 24 名学员

  # ── 场景 1：发布公告 ──
  Scenario: 教师在营团内发布公告
    Given 王老师在 "高二商赛社" 营团详情页的 "公告" Tab
    When 王老师点击 "发布公告" 按钮
    And 填写标题为 "本周六下午 2 点有班级正式赛"
    And 填写内容为 "请大家准时参加，提前 10 分钟入场调试。"
    And 点击 "确认发布"
    Then 页面显示新公告在列表顶部
    And 公告显示发布时间为当前时间

  # ── 场景 2：公告内容限制 ──
  Scenario: 公告仅支持纯文本和链接自动识别
    Given 王老师在发布公告弹窗
    When 王老师尝试粘贴带有加粗格式的富文本
    Then 格式被自动去除，仅保留纯文本
    And 王老师输入 "https://example.com/guide"
    Then 链接被自动识别为可点击链接

  # ── 场景 3：置顶公告 ──
  Scenario: 教师置顶重要公告
    Given 王老师已发布公告 "紧急通知：本周课程取消"
    When 王老师点击该公告的 "置顶" 按钮
    Then 该公告显示 "置顶" 标记
    And 该公告在列表中始终位于最顶部

  # ── 场景 4：公告数量上限 ──
  Scenario: 最多展示 3 条未折叠公告
    Given 营团内已有 5 条公告
    When 王老师查看学生端 "/camp" 页面
    Then 顶部仅显示最新的 3 条公告
    And 显示 "展开历史公告 (2)" 折叠按钮

  # ── 场景 5：删除公告 ──
  Scenario: 教师删除过期公告
    Given 王老师已发布公告 "临时通知"
    When 王老师点击该公告的 "删除" 按钮
    And 确认删除
    Then 该公告从列表中消失
    And 学生端也不再显示该公告

  # ── 场景 6：学生端展示 ──
  Scenario: 学生端营首页显示最新公告
    Given 王老师已发布公告 "本周六下午 2 点有班级正式赛"
    When 学生 "小明" 访问 "/camp" 页面
    Then 页面顶部显示通知条："本周六下午 2 点有班级正式赛"
    And 点击通知条可展开完整公告内容
```

## Feature 4: 营团详情页 Tab 重构 (P0)

> **价值**：将原有散乱的信息区域重组为清晰的 Tab 结构，教师按需切换。

```gherkin
Feature: 营团详情页 Tab 重构
  作为教师
  我希望营团详情页有清晰的分类导航
  以便快速找到需要的功能和信息

    And 王老师拥有一个名为 "高二商赛社" 的营团

  Scenario: 营团详情页显示所有 Tab
    Given 王老师在 "高二商赛社" 营团详情页
    Then 页面显示以下 Tab：

      | 概览       | 新增   | 营团 KPI + 公告 + 时间线 |
      | 赛季       | P1新增 | 赛季列表与编排        |
      | 营内商赛   | 已有   | 商赛列表 + 复盘入口   |
      | 学员进度   | 新增   | 进度看板             |
      | 成员名册   | 已有   | 学员基本信息列表     |

  # ── 场景 2：概览 Tab 内容 ──
  Scenario: 概览 Tab 显示营团 KPI
    Given 王老师在 "高二商赛社" 营团详情页
    When 王老师点击 "概览" Tab
    Then 页面显示 KPI 卡片：

    When 王老师切换到 "营内商赛" Tab
    And 再切换回 "学员进度" Tab
    Then 学员进度列表无需重新加载，直接展示

  # ── 场景 4：移动端 Tab 适配 ──
  Scenario: 移动端 Tab 显示为下拉选择器
    Given 王老师使用移动设备访问 organizer-frontend
    When 王老师进入营团详情页
    Then Tab 显示为水平滚动或下拉选择器
    And 所有 Tab 内容均可正常访问
```

## Feature 5: 赛季与里程碑编排 (P1)

> **价值**：教师可以将一次完整教学段落编排为有序的活动序列，学生按节奏推进。

```gherkin
Feature: 赛季与里程碑编排
  作为教师
  我希望为营团创建赛季并编排里程碑活动
  以便系统化地组织教学节奏

  Background:
    Given 教师 "王老师" 已登录 organizer-frontend
    And 王老师拥有一个名为 "高二商赛社" 的营团
    And 系统预设 3 套赛季模板：
      | 模板名称   | 里程碑序列                              |
      | 4 周入门   | 理论课 → 练习赛×2 → 正式赛 → 复盘 → 作业 |
      | 单周体验   | 理论课 → 练习赛 → 复盘                   |
      | 暑期集训   | 理论课 → 练习赛×3 → 正式赛×2 → 复盘 → 路演 |

  # ── 场景 1：创建空白赛季 ──
  Scenario: 教师创建空白赛季
    Given 王老师在 "高二商赛社" 营团详情页的 "赛季" Tab
    When 王老师点击 "创建赛季" 按钮
    And 填写名称为 "4周商赛入门"
    And 填写主题为 "长三角贸易"
    And 设置开始时间为 "2026-03-01"
    And 设置结束时间为 "2026-03-28"
    And 点击 "保存草稿"
    Then 赛季状态为 "草稿"，仅教师可见
    And 赛季显示在赛季列表中

  # ── 场景 2：从模板创建赛季 ──
  Scenario: 教师从模板创建赛季
    Given 王老师在创建赛季弹窗
    When 王老师选择模板 "4 周入门"
    Then 系统预填里程碑序列：
      | 顺序 | 名称         | 类型          |
      | 1    | 第1周：理论课 | lecture       |
      | 2    | 练习赛 #1    | practice_match |
      | 3    | 练习赛 #2    | practice_match |
      | 4    | 班级正式赛   | formal_match   |
      | 5    | 复盘与作业   | debrief        |
      | 6    | 课后反思作业 | assignment     |
    And 教师可编辑每个里程碑的名称和顺序

  # ── 场景 3：编辑里程碑 ──
  Scenario: 教师添加和调整里程碑
    Given 王老师正在编辑赛季 "4周商赛入门"
    When 王老师从左侧类型面板拖拽 "讨论任务" 到时间线末尾
    Then 时间线末尾新增里程碑：
      | 名称     | 类型       | 状态    |
      | 小组讨论 | discussion | locked |
    When 王老师拖拽 "小组讨论" 到 "复盘与作业" 之前
    Then 里程碑顺序调整为：
      | 顺序 | 名称         |
      | 1    | 第1周：理论课 |
      | ...  | ...          |
      | 5    | 小组讨论     |
      | 6    | 复盘与作业   |
      | 7    | 课后反思作业 |
```

```gherkin

  # ── 场景 1：自动分组 ──

    And 选择分配方式为 "随机"

    And 组内其他学员显示 "组员" 标识
```
