## 一、P1 已有什么（与代码一致）

　　截至体验营分支，教师端（`:5174`）已具备：

| 能力 | 说明 |
|------|------|
| 创建体验营 | 名称、简介、可选起止日期；自动生成 **6 位营团码** |
| 邀请与名册 | 复制邀请码；查看已加入学员列表 |
| 营内商赛 | 发起浮生记 RTS / TechVenture；获得 **4 位房间码**；进入控场页 |
| 重置邀请码 | 旧码失效，已入营学员保留 |

　　学生端（`:5173`，`VITE_CAMP_PHASE1`）已具备：入营、我的体验营、查看营内房间码、商赛大厅加入对局。

### 1.1 P1 的「单薄感」从何而来

| 缺口 | 教师感受 | 根因 |
|------|----------|------|
| 无 **教学节奏** | 开营 = 只能不断「再开一场商赛」 | 未做 `seasons` / 里程碑 / 活动编排 |
| 无 **班级视角数据** | 不知道谁练了、谁落队 | 无营内学习看板、无导出 |
| 无 **沟通触达** | 发通知要靠微信 | 无公告、无作业、无站内消息 |
| 无 **课后闭环** | 商赛结束 = 结束 | 无班级复盘、无作业批改入口 |
| 与 **83- 蓝图** 差距大 | 文档很全，产品很瘦 | 83- 含赛季/AOTU/沙盘；代码仅 group |

## 二、产品原则（讨论时建议锁定）

1. **先营团、后赛季**：P2 强化「营团 + 商赛」闭环；`seasons` 表与里程碑放在 P3（与 ADR-009 一致）。  
2. **教师是导演，不是代打**：控场、发布、点评；AI 仅润色与模板（见 **81-** 支柱纪律）。  
3. **每条能力可单独演示**：校方参观时能讲清「这一步解决什么问题」。  
4. **复用 Arena，不 fork 引擎**：新能力尽量落在 `organizer-frontend` + 新 API，不改 `games/` 结算内核。

## 三、分阶段功能建议

### 3.1 P2 · 营团运营台（建议 2～3 周工程）

**目标**：让教师「开营之后有地方待」，而不只是「创建成功页」。

| 功能 | 描述 | 验收 |
|------|------|------|
| **营内首页看板** | 一屏：成员数、进行中商赛、最近 7 日入营/参赛人次 | 教师登录可见本营 KPI |
| **成员参与态** | 名册增加列：最近参赛时间、参与场次、是否在线练习 | 可筛「未参赛」学员 |
| **营内公告** | 教师发短文（支持 Markdown 简子集）；学生营首页顶部展示 | 学生刷新可见 |
| **商赛时间线** | 本营全部 `competition_events` 按时间排列，状态色块 | 替代仅列表点控场 |
| **一键复制「开赛说明」** | 模板含 6 位营团码 + 最近一场 4 位房间码 | 减少微信群重复打字 |

**可选（P2.5）**：

- **导出 CSV**：成员名单 + 各场商赛名次（读现有 `standings` API）。  
- **营团关闭向导**：关闭后学生端提示「营已结束」，历史商赛只读。

### 3.2 P3 · 教学节奏（赛季轻量版，建议 4～6 周）

　　不必一次上全量 **83-** 赛季引擎；可采用 **「里程碑清单」** 轻模型：

| 功能 | 描述 |
|------|------|
| **里程碑模板** | 内置 3 套：「4 周商赛入门」「暑期集训」「单周体验课」 |
| **里程碑 = 活动占位** | 每项：类型（商赛 / 阅读 / 讨论 / 作业）、建议周次、是否必做 |
| **一键生成营内商赛** | 从里程碑点击「发起对应商赛」，自动带 `teaching_group_id` |
| **学生营首页进度条** | 显示「本周建议：完成练习赛 1 次 + 参加班级赛」 |
| **教师推进按钮** | 「解锁下一周」→ 学生侧可见新里程碑（非自动日历，降低 AOTU 复杂度） |

　　数据模型可演进为 `seasons` + `milestones`；MVP 可用 `teaching_groups.config_json` 存里程碑数组，避免过早建表。

### 3.3 P4 · 教学闭环与 AI 辅助（与 86- 协同）

| 功能 | 描述 |
|------|------|
| **班级赛后复盘页** | 某场商赛结束后，教师查看全班决策分布、名次、可选 AI 生成「讲评三点」 |
| **作业布置** | 关联复盘卡：学生交 200 字反思；教师端待批改列表 |
| **AI 讲评助手** | 仅润色教师已选的讲评要点，不自动替教师做排名结论 |
| **群聊智能体（远期）** | 营内 FAQ 机器人：回答规则类问题，引用本营赛制说明 |

## 四、与现有页面的信息架构建议

```
教师端 :5174
├── 我的体验营（列表）          ← 已有
├── 体验营详情（营团 HQ）        ← P2 升级：看板 + 公告 + 时间线
│   ├── 成员名册
│   ├── 商赛活动（发起 / 控场）
│   └── 公告与资料（P2）
├── 发起商赛（带 groupId）      ← 已有
├── 控场页                       ← 已有；返回「体验营 HQ」
└── （P3）赛季 / 里程碑页       ← 可选子路由 /camps/:id/season
```

　　侧栏保持简洁：**我的体验营**、**创建体验营**；避免回到「组织者控制台」多入口混乱。

## 五、与学生端的协同触点

| 教师动作 | 学生应在哪感知 |
|----------|----------------|
| 发公告 | `/camp` 顶部通知条 |
| 发起商赛 | `/camp` 营内商赛列表 + 推送式红点（远期） |
| 解锁里程碑 | `/camp` 进度条 + `/quests` 可选联动 |
| 发布复盘作业 | `/career/debrief/:matchId` 或作业页（远期） |

## 六、不建议 P2 做的项（避免 scope 膨胀）

| 项 | 原因 |
|----|------|
| 完整 AOTU 自动排课 | 需赛季引擎 + 教师确认流；见 ADR-009 待决 |
| 课堂沙盘演示台 | 独立产品面；可放 P5 或 inspire 83- §2.1 单独立项 |
| 家长端 / 小程序 | 非 Phase A/B 核心 |
| 修改商赛局内数值 | 违反竞技公平；教师只选赛制与控场 |

## 七、成功指标（讨论用）

| 指标 | P2 目标 |
|------|---------|
| 教师开营后 7 日内二次登录率 | ≥ 60%（有看板可看） |
| 单营团场均商赛场次 | ≥ 2（说明不只建营不开赛） |
| 学生入营后参赛率 | ≥ 70%（入营成员中至少参加 1 场营内赛） |
