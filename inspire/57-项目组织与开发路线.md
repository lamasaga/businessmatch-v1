# 07 - 项目组织与开发路线

> 从一个比赛工具到一个教学平台，不只是写更多代码，而是产品、设计、内容、技术的协同演进。本文件提供项目管理的组织思路和分阶段路线图。

---

## 一、团队角色与组织建议

### 1.1 核心团队（MVP 阶段：5-8 人）

| 角色 | 职责 | 关键产出 |
|------|------|----------|
| **产品经理 / 项目负责人** | 需求定义、优先级、跨团队协调 | PRD、路线图、用户故事 |
| **教育内容设计师** | 课程体系、经济学概念映射、复盘文案 | 课程单元脚本、教师手册 |
| **UX/UI 设计师** | 界面设计、交互流程、视觉系统 | Figma 原型、设计系统 |
| **前端工程师** | 学生端、教师端、大屏端开发 | React/Vue 代码 |
| **后端工程师** | API、结算引擎、数据库 | Node.js / 其他服务端代码 |
| **测试/QA** | 功能测试、规则校验、用户体验测试 | 测试用例、Bug 报告 |
| **运营/教师支持** | 一线教师沟通、培训、反馈收集 | 使用手册、FAQ、案例库 |

### 1.2 扩展团队（平台化阶段：10-15 人）

- **游戏策划**：局外成长系统、数值平衡、活动设计
- **数据分析师**：学习效果分析、用户行为分析、A/B 测试
- **客户成功**：学校/机构对接、定制化需求、续约
- **市场/增长**：内容营销、赛事运营、社群运营

### 1.3 协作模式建议

**采用敏捷开发（Scrum），双周迭代**：

```
Week 1
├── 周一：Sprint Planning（2h，全员）
├── 周中：每日站会（15min）
└── 周五：内容/设计评审（教育与设计师主导）

Week 2
├── 周中：开发 + 联调
├── 周四：Sprint Review（演示可用增量）
└── 周五：Retrospective（复盘改进）
```

**特殊仪式**：
- **规则评审会**：任何结算引擎参数变更，必须经教育内容设计师 + 后端工程师 + 游戏策划三方会签
- **教师访谈日**：每两周至少访谈 1 位真实教师，收集使用反馈

## 二、产品演进路线图

### Phase 0：资产整理与奠基（1-2 个月）

**目标**：把现有的"比赛工具"升级为"可在线使用的教学工具"

| 任务 | 产出 | 验收标准 |
|------|------|----------|
| 现有引擎重构 | 抽取 `@bizsim/engine-core` | 纯函数、无 Express 依赖、100% 单测覆盖 |
| 数据库设计 | PostgreSQL Schema | 支持用户、班级、对局、回合、决策、结算 |
| 前端脚手架 | React + TS + Tailwind | 设计系统初版（色彩、字体、按钮、卡片） |
| 部署基础 | Docker + CI/CD | 开发环境一键启动，测试环境自动部署 |
| 规则文档化 | 完整规则说明书 | 教师和学生都能看懂 |

**里程碑**："能在浏览器里完成一局 TechVenture"

### Phase 1：在线体验化（2-3 个月）

**目标**：让学生不需要培训就能上手，让教师能轻松组织活动

| 任务 | 说明 |
|------|------|
| 学生端完整流程 | 注册 → 加入班级 → 参与对局 → 查看结果 |
| 教师端控制台 | 创建班级、导入学生、发起对局、查看进度、导出成绩 |
| 新手引导系统 | 首次进入强制交互教程（3 分钟） |
| 结算可视化 | 动画、图表、可分享的成绩卡片 |
| 基础班级管理 | 班级码加入、批量导入、分组 |

**里程碑**："一位教师能在 10 分钟内组织起全班参与的商业模拟"

### Phase 2：游戏化与成长（2-3 个月）

**目标**：学生有持续回来的动力，平台有"粘性"

| 任务 | 说明 |
|------|------|
| 用户账号系统 | 学生个人主页、历史对局、数据统计 |
| 经验与等级 | 完成活动获得 XP，升级解锁称号 |
| 徽章/成就系统 | 行为标签、路线专精、隐藏成就 |
| 课程单元模式 | 将商赛拆解为独立教学单元（微课 + 模拟 + 测验） |
| 剧情模式（PVE） | 单人闯关，AI 对手，叙事驱动 |

**里程碑**："学生主动问老师下周还有没有商业模拟课"

### Phase 3：平台化与规模化（3-6 个月）

**目标**：支持多学校、多课程、自定义规则，成为真正的教学平台

| 任务 | 说明 |
|------|------|
| 多租户支持 | 学校/机构级别隔离、独立 branding（可选） |
| 课程市场 | 内置多种课程模板（财商启蒙、创业入门、商战策略） |
| 规则编辑器（简易） | 教师可调参数：资金规模、轮数、城市、事件开关 |
| 数据分析看板 | 班级学习报告、概念掌握度分析、横向对比 |
| 赛事系统 | 校内赛、区域赛、晋级赛制、自动排程 |
| 移动端小程序 | 微信生态渗透、轻量体验、社交分享 |

**里程碑**："多所学校常态化使用，举办校级/区域级线上赛事"

### Phase 4：生态化（6-12 个月）

**目标**：连接教育者、学生、行业，形成生态

| 任务 | 说明 |
|------|------|
| 教师社区 | 教案分享、经验交流、认证体系 |
| 行业导师 | 邀请企业家/投资人作为线上导师、点评 |
| UGC 内容 | 学生商业计划书展示、案例分析投稿 |
| API 开放 | 允许第三方开发者创建新的课程模板或游戏模式 |
| 国际化 | 多语言支持、海外课程适配 |

## 三、关键决策点与风险

### 3.1 技术决策

| 决策 | 选项 A | 选项 B | 建议 |
|------|--------|--------|------|
| 前端框架 | React | Vue | 看团队熟悉度，两者均可；若有小程序需求，React + Taro 或 Vue + UniApp |
| 后端架构 | 单体（NestJS） | 微服务 | **Phase 0-2 用单体**，Phase 3 后按模块拆分 |
| 数据库 | PostgreSQL | MongoDB | **PostgreSQL**，关系型数据为主，JSONB 可存灵活配置 |
| 实时通信 | Socket.io | SSE | Socket.io 功能更全，SSE 更简单；推荐 Socket.io |
| 部署 | 云服务器 | Serverless | 初期云服务器（ECS），稳定后部分无状态服务可 Serverless |

### 3.2 产品决策

| 决策 | 风险 | 建议 |
|------|------|------|
| 先做学生端还是教师端？ | 两端都弱则两端不讨好 | **先做教师端发起流程 + 学生端核心决策**，先跑通课堂闭环 |
| 是否立即做移动端？ | 分散精力，体验打折 | Phase 1 只做适配，Phase 2 做小程序 |
| 是否引入付费？ | 教育产品付费敏感，口碑风险 | Phase 3 再考虑，且仅限 cosmetic / 高级课程，基础功能免费 |
| 是否支持用户自创规则？ | 规则质量参差，可能破坏教学效果 | 先提供"官方模板市场"，审核后再开放有限自定义 |

### 3.3 风险矩阵

| 风险 | 可能性 | 影响 | 缓解措施 |
|------|--------|------|----------|
| 规则太复杂，学生上手难 | 高 | 高 | 强制新手引导、规则分层显示、简化默认模板 |
| 教师不愿意改变教学习惯 | 高 | 高 | 提供完整教案、降低组织成本、展示同行案例 |
| 竞品快速跟进 | 中 | 中 | 核心壁垒在教育内容质量 + 用户数据积累，而非技术 |
| 引擎结算 Bug 导致争议 | 中 | 极高 | 引擎 100% 单元测试、结算结果可重放、异常人工复核 |
| 数据安全事件 | 低 | 极高 | 合规先行、安全审计、最小权限 |

## 四、成功指标（North Star Metrics）

### 4.1 产品健康度

| 指标 | 定义 | 目标（Phase 2） |
|------|------|----------------|
| **周活跃学生数 (WAU)** | 近 7 天至少参与 1 次对局或课程 | 班级覆盖率的 60% |
| **课程完成率** | 开始课程单元的学生中，完成全部环节的比例 | > 70% |
| **NPS（净推荐值）** | 教师愿意向同事推荐平台的意愿 | > 40 |
| **平均对局数/学生/月** | 反映留存和参与深度 | > 3 |

### 4.2 教学效果

| 指标 | 定义 | 目标 |
|------|------|------|
| **概念测验正确率提升** | 课前测 vs 课后测 | +20% |
| **决策理由质量** | 系统/教师对学生决策理由的评分 | 逐轮提升 |
| **复购率（教师）** | 本学期使用 3 次以上的教师占比 | > 50% |

### 4.3 技术稳健性

| 指标 | 目标 |
|------|------|
| 结算引擎单元测试覆盖率 | > 95% |
| API 可用性 | > 99.9% |
| 平均故障恢复时间 (MTTR) | < 30 分钟 |

## 五、开源与社区策略

考虑将非核心模块开源，建立行业影响力：

| 模块 | 开源价值 | 时机 |
|------|----------|------|
| 结算引擎核心 | 吸引教育科技开发者、学术验证 | Phase 1 后 |
| 规则配置 Schema | 标准化商业模拟规则描述 | Phase 2 后 |
| 前端组件库 | 降低同类产品开发成本 | Phase 3 后 |

**核心资产保留**：课程内容、用户数据、特定算法参数。

---

> **核心建议**：从工具到平台的跃迁，最大的敌人不是技术难度，而是**试图一次性做太多**。守住"教师能在 10 分钟组织一次高质量商业模拟"这个核心价值，以此为圆心逐步扩展。每一阶段都必须有真实的课堂验证，不要闭门造车。
