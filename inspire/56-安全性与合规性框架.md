# 06 - 安全性与合规性框架

> 面向未成年人、涉及竞赛排名、可能有付费内容的教育平台，必须在设计之初就嵌入安全与合规基因。

---

## 一、数据安全与隐私保护

### 1.1 法律合规清单

| 法规/标准 | 适用性 | 关键要求 |
|-----------|--------|----------|
| **《个人信息保护法》** | 必遵 | 告知-同意、最小必要、加密存储 |
| **《未成年人保护法》网络专章** | 必遵（18岁以下） | 家长同意、时长限制、内容过滤、消费限制 |
| **《数据安全法》** | 必遵 | 数据分类分级、跨境传输限制 |
| **等保 2.0** | 建议二级，大型平台三级 | 物理、网络、主机、应用、数据五层安全 |
| **GDPR** | 若有海外用户 | 数据可携带权、被遗忘权 |

### 1.2 数据分类与保护策略

| 数据级别 | 示例 | 存储 | 传输 | 访问控制 |
|----------|------|------|------|----------|
| **公开** | 课程介绍、规则说明 | 无特殊 | HTTPS | 无需认证 |
| **内部** | 班级排行榜（匿名） | 数据库 | HTTPS | 班级成员 |
| **敏感** | 学生姓名、学校、手机号 | 加密存储（AES-256） | HTTPS + TLS 1.3 | 本人+教师 |
| **高度敏感** | 身份证号（如赛事需要）、家长信息 | 加密 + 脱敏 | HTTPS | 最小授权 |

### 1.3 具体技术措施

1. **密码安全**
   - 用户密码：bcrypt/Argon2 哈希，禁止明文存储
   - 管理后台：强制 2FA（TOTP 或短信）
   - 队伍 PIN 码：虽然是弱口令场景，但应限制错误次数（5 次锁定 15 分钟）

2. **会话安全**
   - JWT 或 Session + Redis，设置合理过期时间（学生端 2 小时，管理端 30 分钟无操作过期）
   - HttpOnly + Secure + SameSite=Strict Cookie
   - 登出即失效（服务端销毁会话）

3. **API 安全**
   - 全站 HTTPS（HSTS 预加载）
   - Rate Limiting：单 IP / 单用户限流，防止暴力破解和脚本刷榜
   - 输入校验：所有接口严格校验参数（Zod / Joi），防 SQL 注入和 XSS
   - 敏感操作二次确认：如删除队伍、重置对局、修改成绩

4. **文件上传**
   - 若允许上传头像/计划书：限制类型、限制大小、服务端二次校验、病毒扫描、独立存储桶

## 二、内容安全

### 2.1 用户生成内容（UGC）审核

平台中可能产生的 UGC：
- 队伍名称、产品名称
- 宣言/口号文本
- 头像/上传图片
- 聊天/评论（若开放）

**审核策略**：

| 场景 | 策略 | 工具/方法 |
|------|------|----------|
| 实时拦截 | 关键词过滤 + 正则匹配 | 自建敏感词库（政治、色情、暴力、歧视） |
| 异步审核 | AI 文本分类 + 人工抽检 | 阿里云/腾讯云内容安全 API |
| 用户举报 | 一键举报 + 快速响应机制 | 管理后台 24h 内处理 |
| 先审后发 | 高风险场景（如全国公开赛事） | 人工审核队列 |

### 2.2 竞赛公平与反作弊

| 作弊类型 | 检测方法 | 防范措施 |
|----------|----------|----------|
| **代打/账号共享** | 异地登录检测、行为模式突变 | 设备指纹、频繁切换账号警告 |
| **多账号刷榜** | 同 IP / 同设备多账号 | 注册限制、关联账号标记 |
| **自动化脚本** | 操作频率异常、API 调用模式 | 验证码（必要时）、行为验证（如鼠标轨迹） |
| **信息泄露** | 未提交即知道他人决策 | 服务端严格校验权限，前端不预加载敏感数据 |
| **教师偏袒** | 异常修改记录 | 所有后台操作审计日志、修改留痕 |

**结算引擎的防篡改**：
- 结算过程应在服务端完成，前端只接收结果
- 关键参数变更需双人复核（如修改 BQI 规则）
- 每局生成哈希摘要，支持结果验证

## 三、未成年人保护专项

### 3.1 注册与身份识别

- 注册时必须选择身份：学生 / 教师 / 家长
- 学生账号需绑定教师/班级码，或家长手机号验证
- 年龄询问（不强制实名，但需自我声明）
- 14 岁以下：需家长明确同意（电子协议 + 短信验证）

### 3.2 使用时长管理

| 年龄段 | 建议限制 | 实现方式 |
|--------|----------|----------|
| 8-12 岁 | 单次 30 分钟，每日累计 1 小时 | 系统定时提醒 + 到点锁定 |
| 13-15 岁 | 单次 45 分钟，每日累计 1.5 小时 | 提醒 + 教师端可覆盖（课堂需要） |
| 16-18 岁 | 单次 60 分钟，适度提醒 | 软提醒，不强制锁定 |

**课堂模式**：教师可一键开启"课堂模式"，此时时长限制由教师控场决定。

### 3.3 社交安全

- 默认关闭陌生人私聊
- 聊天内容实时过滤
- 禁止个人联系方式交换（手机号、微信、QQ 等自动屏蔽）
- 提供"一键屏蔽 + 举报"按钮

### 3.4 付费与消费保护

若平台引入付费（会员、通行证、皮肤）：
- 16 岁以下：单次消费不超过 50 元，月累计不超过 200 元
- 充值需家长确认（短信/微信验证）
- 明确公示退款政策
- 禁止开箱/抽卡等赌博机制（教育平台尤其敏感）

## 四、运维安全

### 4.1 审计与监控

| 层面 | 监控内容 | 工具 |
|------|----------|------|
| 基础设施 | CPU、内存、磁盘、网络 | Prometheus + Grafana |
| 应用层 | API 响应时间、错误率、QPS | APM（如 Sentry / New Relic） |
| 业务层 | 异常登录、高频操作、数据导出 | 自定义审计日志 + 告警 |
| 安全层 | 入侵检测、漏洞扫描、依赖安全 | WAF、Snyk/Dependabot |

### 4.2 备份与灾难恢复

- 数据库：每日全量备份 + 实时 WAL 归档，保留 30 天
- 文件存储：多地域冗余（OSS 标准存储）
- 演练：每半年一次恢复演练
- RPO < 1 小时，RTO < 4 小时

### 4.3 第三方依赖安全

- 定期扫描依赖漏洞（`npm audit` / Snyk）
- 锁定依赖版本（package-lock.json / yarn.lock）
- 避免使用停止维护的库
- 开源协议合规：记录所有依赖的许可证

## 五、应急响应预案

### 5.1 事件分级

| 级别 | 示例 | 响应时间 | 行动 |
|------|------|----------|------|
| P0 紧急 | 数据泄露、服务完全不可用 | 15 分钟 | 核心团队全部响应、启动降级、通知用户 |
| P1 严重 | 大面积作弊、关键功能故障 | 1 小时 | 工程师修复、运营公告 |
| P2 一般 | 单班级数据异常、UI 缺陷 | 24 小时 | 排期修复 |
| P3 轻微 | 文案错误、非核心样式问题 | 下次迭代 | 记录待办 |

### 5.2 数据泄露响应

1. 立即隔离受影响系统
2. 评估泄露范围（哪些数据、多少用户）
3. 72 小时内向监管部门报告（若达到阈值）
4. 通知受影响用户及家长
5. 事后复盘，修补漏洞
