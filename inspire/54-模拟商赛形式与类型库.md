# 04 - 模拟商赛形式与类型库

> TechVenture 当前是"多队同图、回合制、属性竞争"模式。本文件系统梳理商业模拟竞赛的可能形态，为平台的多玩法扩展提供菜单。

---

## 一、按核心机制分类

### 1.1 回合制策略（Turn-Based Strategy）

**代表**：现有 TechVenture、JA 公司、BPA

| 维度 | 说明 |
|------|------|
| 节奏 | 异步或同步回合，每轮 5-15 分钟决策 |
| 信息结构 | 同时决策（sealed bid）或顺序决策 |
| 核心乐趣 | 资源分配、战略预判、博弈推理 |
| 教学优势 | 教师易控场、学生有思考时间、便于复盘 |
| 平台适配 | ⭐⭐⭐ 完全适合在线化 |

**TechVenture 改进方向**：
- 增加"间谍"机制（投入一定预算可查看某队上回合决策摘要）
- 增加"联盟"机制（两队可临时合作共享某城市 Fit 属性）
- 增加"暗标拍卖"（城市广告位竞价）

### 1.2 实时经营（Real-Time Management）

**代表**：模拟城市、创业模拟器类手游

| 维度 | 说明 |
|------|------|
| 节奏 | 持续运转，决策即时生效 |
| 信息结构 | 全透明或半透明，动态变化 |
| 核心乐趣 | 多线程操作、应急响应、效率优化 |
| 教学优势 | 训练时间管理和多任务处理能力 |
| 平台适配 | ⭐⭐ 需要更强的前端实时渲染 |

**设计建议**：可作为"沙盒练习模式"，非正式比赛。
- 学生经营一家虚拟公司，24 小时为一个"游戏年"
- 期间随机发生事件（供应链断裂、竞品发布、舆情危机）
- 需要在 5 分钟内做出应急决策

### 1.3 拍卖与交易（Auction & Trading）

**代表**：模拟股市、能源交易模拟

| 维度 | 说明 |
|------|------|
| 节奏 | 快节奏，通常 1-2 分钟一轮 |
| 信息结构 | 公开喊价或密封报价 |
| 核心乐趣 | 价格发现、信息不对称利用、风险控制 |
| 教学优势 | 直接体验金融市场逻辑 |
| 平台适配 | ⭐⭐⭐ 适合在线 |

**可嵌入 TechVenture 的变体**：
- **城市广告位拍卖**：每轮开始前，各城市置顶展示位拍卖
- **技术专利交易**：队伍间可买卖 Tech 属性（一次性转移）
- **供应链竞标**：上游原材料供应商角色由 NPC 或教师扮演

### 1.4 角色扮演与谈判（RPG & Negotiation）

**代表**：商务谈判模拟、供应链角色扮演

| 维度 | 说明 |
|------|------|
| 节奏 | 自由协商，通常一轮 20-40 分钟 |
| 信息结构 | 高度不对称，各角色掌握不同信息 |
| 核心乐趣 | 社交互动、话术、利益权衡 |
| 教学优势 | 训练沟通、谈判、团队协作 |
| 平台适配 | ⭐⭐ 需要音视频或实时聊天支持 |

**设计建议**：
- **产业链角色扮演**：将 16 人分为供应商、制造商、分销商、零售商四组
- 每组内部竞争，组间必须交易
- 平台提供"合同系统"：双方确认条款后系统执行

### 1.5 案例推演与决策树（Case Simulation）

**代表**：哈佛商学院案例、沙盘推演

| 维度 | 说明 |
|------|------|
| 节奏 | 慢，通常 1-2 天一个决策点 |
| 信息结构 | 叙事驱动，信息逐步释放 |
| 核心乐趣 | 沉浸故事、道德两难、长期后果 |
| 教学优势 | 训练复杂决策和伦理思考 |
| 平台适配 | ⭐⭐⭐ 非常适合异步在线 |

**设计建议**：
- 以真实企业改编的"互动案例"
- 学生扮演 CEO，面对 10 个关键决策点
- 每个决策影响后续剧情分支
- 最终看到"如果当初选 A，3 年后会怎样"

## 二、按参与规模分类

| 规模 | 人数 | 形式 | 平台支持 |
|------|------|------|----------|
| **个人闯关** | 1 | 剧情模式、挑战模式 | 自动匹配 NPC 对手 |
| **双人博弈** | 2 | 囚徒困境、竞价博弈 | 经典博弈论教学 |
| **小队竞技** | 3-5 | 小组经营一家虚拟公司 | 强调内部分工 |
| **班级联赛** | 16-40 | 4-10 队同场竞技 | TechVenture 当前形态 |
| **年级/校际赛** | 40-200 | 多班级晋级制 | 需要锦标赛系统 |
| **全国/公开赛** | 200+ | 线上预选赛 + 线下决赛 | 需要排位赛与反作弊 |

## 三、按胜负规则分类

### 3.1 排名制（现有模式）
- 按 Attention / 加权总分排名
- 适合：竞赛、考试场景

### 3.2 目标达成制
- 预设目标：如"在 4 轮内将 Tech 提升到 8 且不出先营销过度"
- 所有达成目标的队伍都算"获胜"
- 适合：教学场景，减少零和博弈的挫败感

### 3.3 生存制
- 模拟真实创业：现金流断裂即出局
- 最后存活者胜，或存活轮数长者为胜
- 适合：高年级、风险教育

### 3.4 合作制
- 全队（或全班）共享一个总目标
- 如：全班总 Attention 达到某个阈值，解锁集体奖励
- 适合：低年级、团队建设

### 3.5 混合制
- 个人排名 + 团队目标双重奖励
- 如：个人进入前 3 获得个人徽章；全班平均排名进入前 50% 获得班级奖励
- 适合：大多数教学场景

## 四、特殊赛制设计（创新方向）

### 4.1 "盲盒市场"赛
- 每轮城市参数（群体比例、规模）对参赛者隐藏
- 只能通过"市场调研"（投入 Fit 预算）逐步解锁信息
- 教学点：信息不对称下的决策、市场调研的价值

### 4.2 "黑天鹅"赛
- R1-R2 正常进行
- R3 发生极端事件（如：某城市市场规模暴跌 50%，或某路线被政策禁止）
- 教学点：韧性、危机管理、战略灵活性

### 4.3 "并购"赛
- 允许排名相邻的队伍"合并"
- 合并后属性加权平均，预算相加，但后续排名共享
- 教学点：产业整合、规模经济、反垄断

### 4.4 "遗产"赛
- 4 轮结束后，队伍的属性、预算、排名作为"遗产"传递给下一届学生
- 下一届在"学长留下的基础上"继续经营
- 教学点：长期主义、代际责任、基业长青

### 4.5 "投资人"赛
- 学生分为"创业者"和"投资人"两派
- 投资人用虚拟资金投资创业者，按回报率排名
- 创业者需要路演、 pitch
- 教学点：投融资、估值、沟通表达

## 五、与真实赛事的对接

平台应预留接口，支持将线上对局成绩与线下赛事挂钩：

| 赛事类型 | 线上环节 | 线下环节 | 平台功能 |
|----------|----------|----------|----------|
| 校内选拔赛 | 班级积分赛 | 无 | 自动排名、晋级名单 |
| 区域联赛 | 线上预选赛（异步） | 现场决赛（同步） | 成绩导出、现场大屏 |
| 全国赛 | 多轮积分赛 | 线下答辩 | 视频上传、评委打分模块 |
| 国际交流赛 | 跨境异步对局 | 线上峰会 | 多时区支持、翻译接口 |

## 六、玩法扩展的模块化设计

为了让平台能够灵活组合不同玩法，建议将"对局"抽象为可配置对象：

```typescript
interface GameMode {
  modeId: string;
  name: string;
  targetAge: [number, number];
  
  // 核心机制
  coreMechanic: "turn_based" | "real_time" | "auction" | "rpg" | "case";
  
  // 规则模板（引用引擎版本）
  engineVersion: string;
  ruleOverrides: Partial<V6Params>;
  
  // 参与结构
  teamSize: number;        // 每队人数
  minTeams: number;
  maxTeams: number;
  rounds: number;
  
  // 胜负规则
  winCondition: "ranking" | "objective" | "survival" | "coop" | "hybrid";
  
  // 特殊机制开关
  features: {
    allowAlliances: boolean;
    allowSpying: boolean;
    allowTrading: boolean;
    hiddenParams: boolean;  // 盲盒市场
    legacyMode: boolean;    // 遗产赛
  };
  
  // 教学关联
  linkedCourses: string[]; // 关联的课程单元 ID
}
```

**示例**：教师创建班级活动时，从"玩法市场"选择一个模板，微调参数后即可发布。

---

> **核心建议**：不要试图一次性实现所有玩法。建议以 TechVenture 的回合制竞技为"第一宇宙"，逐步增加"剧情模式"（PVE）和"挑战模式"（特殊规则）作为扩展宇宙。平台的价值在于**承载多样化的商业学习体验**，而非局限于一种比赛形式。
