## 一、当前架构的高并发瓶颈

### 1.1 瓶颈总览

```
当前架构压力模型（单服务器）

  请求流量
     │
     ▼
┌─────────────────────────────────────────┐
│  FastAPI (单进程 ASGI)                  │
│  ├─ HTTP API 路由                       │
│  ├─ WebSocket 连接管理（内存字典）        │
│  └─ RTS 调度器（全局 asyncio 事件循环）   │
└────────────┬────────────────────────────┘
             │
     ┌───────┴───────┐
     ▼               ▼
┌──────────┐   ┌──────────────┐
│ SQLite   │   │ 内存状态      │
│ 单文件   │   │ (rooms/game  │
│ 写锁排队  │   │  sessions)   │
└──────────┘   └──────────────┘
```

### 1.2 具体瓶颈分析

| 组件 | 现状 | 瓶颈描述 | 风险等级 |
|------|------|----------|----------|
| **数据库** | SQLite 单文件 | 写操作全局文件锁，并发写入时串行排队；连接池默认 5 个 | 🔴 **高** |
| **WebSocket 广播** | 内存 `Dict[int, Set[WebSocket]]` | 每 tick 遍历全房间连接发送，O(n)；无连接数上限，大房间（200+人）可能阻塞事件循环 | 🔴 **高** |
| **RTS 调度器** | 全局 `asyncio` 事件循环 | 所有对局共享一个循环，单个对局的密集计算会拖慢全局 tick | 🟡 **中高** |
| **应用进程** | 单进程 Uvicorn | 无法利用多核 CPU；一个请求阻塞影响全部 | 🟡 **中** |
| **内存状态** | 游戏 session 全内存 | 进程重启 = 全部对局丢失；无水平扩展能力 | 🟡 **中** |
| **沙盒调试** | 内存 session + 热重载 | 大量沙盒实例同时运行会快速耗尽内存 | 🟡 **中** |

### 1.3 压力场景推演

**场景 A：单班级竞赛（40 人）**
- 40 个 WebSocket 连接，每 5 秒一次广播
- SQLite 写入：每 tick 每个玩家决策一次写入
- **预判**：单服务器可支撑，但已接近舒适区边界

**场景 B：跨校联赛（200 人，同时在线）**
- 200 WS 连接 × 每 5 秒广播 = 40 msg/s 出站
- 假设 10 个房间同时运行 = 400 msg/s
- SQLite 写锁竞争加剧，响应延迟抖动
- **预判**：单服务器在 tick 广播峰值时可能出现明显卡顿

**场景 C：夏令营高峰（500+ 人同时在线）**
- 多房间并发，WebSocket 连接池膨胀
- 内存中 session 对象累积
- **预判**：单服务器极有可能出现连接丢失、广播延迟、甚至 OOM

### 1.4 CDE 带来的额外并发压力

| CDE 功能 | 新增压力 | 影响 |
|----------|----------|------|
| Formula VM 执行 | 每 tick 执行 N 条公式，CPU 密集型 | tick 处理时间从 <10ms 增长到 50~200ms |
| 千局模拟（平衡测试） | 后台批量运行 1000 局 × 240 tick | 与生产对局争夺 CPU/内存 |
| AI Opponent（LLM 模式） | 每 tick 每个 AI 调用一次外部 API | API 延迟 500ms~2s 会阻塞 tick 推进 |
| Asset Pipeline | 大量美术资源加载 | 带宽和 CDN 压力 |

## 二、CDE 新增组件的安全风险

### 2.1 风险矩阵

| 组件 | 风险类型 | 攻击向量 | 潜在后果 | 风险等级 |
|------|----------|----------|----------|----------|
| **Formula VM** | 计算资源耗尽 | 提交深层递归/无限循环公式 | DoS，单请求占满 CPU | 🔴 **高** |
| **Formula VM** | 信息泄露 | 公式中读取越界状态 | 看到其他玩家的私有数据 | 🟡 **中** |
| **CitySim Protocol** | SSRF | 配置指向恶意城市模拟服务端 | 内网探测、数据外泄 | 🟡 **中** |
| **Asset Pipeline** | 路径遍历 | `../../../etc/passwd` 式资产路径 | 读取服务器任意文件 | 🔴 **高** |
| **Asset Pipeline** | 恶意文件上传 | 上传伪装成 SVG 的 XSS payload | 学生端执行恶意脚本 | 🟡 **中** |
| **AI Opponent (LLM)** | 提示注入 | 通过配置注入 system prompt | AI 行为被篡改 | 🟡 **中** |
| **AI Opponent (LLM)** | API Key 泄露 | 配置中硬编码 LLM API key | 密钥被盗用 | 🔴 **高** |
| **赛事工坊** | 配置注入 | YAML 中嵌入恶意结构 | 覆盖系统配置、代码执行 | 🟡 **中** |
| **MCP 接口** | 权限提升 | AI Agent 越权操作 | 删除/篡改他人赛事 | 🟡 **中** |
| **Visual Orchestrator** | XSS | 资产绑定中的 `on_click` 执行任意 JS | 前端脚本注入 | 🟡 **中** |

### 2.2 详细分析

#### 2.2.1 Formula VM：沙箱逃逸与资源耗尽

**问题**：当前设计限制执行时间 100ms / 内存 64MB，但这些限制本身需要可靠的实现机制。

```python
# 假设的攻击向量（如果 VM 基于 Python exec/eval）
# 即使限制了 builtins，仍可能通过 __import__ 绕过
formula = """
().__class__.__bases__[0].__subclasses__()  # 反射绕过
"""
```

**加固方向**：
- 使用独立进程/容器执行公式（而非线程），通过 OS 级 cgroup 限制资源
- 禁止任何形式的 `eval` / `exec` / `compile`
- 表达式解析使用白名单 AST 遍历，只允许预定义的节点类型
- 超时使用 `multiprocessing.Process` + `join(timeout)`，而非信号（信号在多线程不安全）

#### 2.2.2 WebSocket：鉴权与广播安全

**现状风险**：从 `rts_ws.py` 观察：
- `connect()` 仅接受 `event_id` 和 `websocket`，**无显式身份验证**
- 任何知道 event_id 的连接都可以订阅广播
- 广播失败时静默丢弃连接，无日志记录

```python
# 当前实现（简化）
async def connect(self, event_id: int, websocket: WebSocket):
    await websocket.accept()          # ← 无鉴权
    self._rooms[event_id].add(websocket)
```

**加固方向**：
- WebSocket 握手时校验 JWT token，验证用户是否属于该 event
- event_id 使用不可预测的随机 ID（而非自增整数），防止枚举攻击
- 广播异常记录到日志，用于排查连接风暴
- 单房间连接数设上限（如 500），超限拒绝新连接

#### 2.2.3 配置与密钥管理

**现状风险**：从 `config.py` 观察：

```python
SECRET_KEY: str = "your-secret-key-change-in-production"  # ← 硬编码弱密钥
DEBUG: bool = True                                         # ← 生产应 False
ACCESS_TOKEN_EXPIRE_MINUTES: int = 60 * 24 * 7            # ← 7 天过长
CORS_ORIGINS: list[str] = ["http://localhost:5173", ...]   # ← 生产环境过度开放
```

**加固方向**：
- SECRET_KEY 从环境变量读取，生产环境使用 KMS 管理
- DEBUG=False 时关闭 `/docs`、`/redoc`、`/openapi.json`
- Token 过期缩短至 2 小时（学生端）/ 30 分钟（管理端）
- CORS 在生产环境只允许特定域名

#### 2.2.4 数据库安全

**现状风险**：
- SQLite 单文件，无用户/权限概念
- 数据库文件位于项目目录 `./bizsim.db`
- 若目录有文件上传功能，存在数据库文件被下载/覆盖的风险

**加固方向**：
- 生产环境迁移至 PostgreSQL（用户隔离、连接池、审计日志）
- 数据库文件放置在非 Web 可访问目录
- 启用 WAL 模式提升并发性能
- 定期备份 + 异地容灾

## 三、网络安全：云服务器加固

### 3.1 云厂商选择对比

| 维度 | 阿里云 | 腾讯云 | 说明 |
|------|--------|--------|------|
| DDoS 基础防护 | 5Gbps 免费 | 2Gbps 免费 | 教育平台通常够用 |
| WAF | 按量付费 | 按量付费 | **必须启用**，防 SQL 注入、XSS |
| CDN | 全球节点 | 国内节点更优 | 静态资源加速 + 隐藏源站 |
| 内容安全 | 绿网 | 天御 | 文本/图片审核，未成年人平台**必需** |
| 密钥管理 | KMS | KMS | 管理 SECRET_KEY、API Key |
| 数据库 | RDS PostgreSQL | TDSQL-C | 托管数据库，自动备份 |

### 3.2 安全组与网络架构

```
公网流量
   │
   ▼
┌─────────────────────────────────────────┐
```

### 3.3 安全组规则（最小权限原则）

| 方向 | 端口 | 源 | 说明 |
|------|------|-----|------|
| 入站 | 443 | 0.0.0.0/0 | HTTPS 入口 |
| 入站 | 80 | 0.0.0.0/0 | HTTP（仅重定向到 HTTPS） |
| 入站 | 22 | 办公 IP/跳板机 | SSH（禁止 0.0.0.0/0） |
| **拒绝** | 3306/5432/6379 | 公网 | 数据库/Redis 不暴露 |
| 出站 | 全部 | 0.0.0.0/0 | 应用需要访问外网 API |

### 3.4 关键安全服务清单

| 服务 | 用途 | 优先级 |
|------|------|--------|
| **WAF** | 拦截 Web 攻击（SQLi/XSS/CC） | 🔴 **P0** |
| **SSL 证书** | 全站 HTTPS（Let's Encrypt 或云厂商） | 🔴 **P0** |
| **云数据库** | RDS PostgreSQL（替代 SQLite） | 🔴 **P0** |
| **Redis** | 会话共享 + 限流 + WS 状态 | 🔴 **P0** |
| **内容安全 API** | 文本/图片审核（未成年人合规） | 🔴 **P0** |
| **KMS** | 密钥管理（SECRET_KEY、API Key） | 🟡 **P1** |
| **云审计** | 操作日志、API 调用审计 | 🟡 **P1** |
| **漏洞扫描** | 定期扫描服务器漏洞 | 🟡 **P1** |
| **DDoS 高防** | 大规模活动时防流量攻击 | 🟢 **P2** |

## 四、分阶段加固建议

### 4.1 Phase 1：立即修复（上线前必须）

| # | 问题 | 修复方案 | 预计工时 |
|---|------|----------|----------|
| 1 | SECRET_KEY 硬编码 | 改为环境变量，生产用 KMS | 2h |
| 2 | DEBUG=True | 生产环境设 False，关闭 docs/redoc | 1h |
| 3 | CORS 过度开放 | 生产环境只允许特定域名 | 2h |
| 4 | Token 过期 7 天 | 缩短至 2h（学生）/ 30min（管理） | 2h |
| 5 | WebSocket 无鉴权 | 握手时校验 JWT，验证 event 成员身份 | 4h |
| 6 | SQLite 生产使用 | 迁移至 PostgreSQL 或至少启用 WAL | 1d |
| 7 | 数据库文件暴露风险 | 移至非 Web 目录，禁止直接下载 | 2h |

### 4.2 Phase 2：高并发优化（P1 阶段）

| # | 问题 | 修复方案 | 预计工时 |
|---|------|----------|----------|
| 1 | 单进程瓶颈 | Uvicorn worker 多进程（`--workers 4`）或 Gunicorn | 4h |
| 2 | WebSocket 广播 O(n) | 引入 Redis Pub/Sub 做 WS 状态共享 + 分片广播 | 2d |
| 3 | 内存 session 无持久化 | 游戏状态定期快照到 Redis/DB | 2d |
| 4 | 无连接数上限 | 单房间 WS 连接数上限 + 全局连接数监控 | 4h |
| 5 | 无 Rate Limiting | 全站 API 限流（慢速爬虫/CC 防护） | 1d |
| 6 | 千局模拟争资源 | 模拟任务放入独立队列（Celery + Redis），隔离生产 | 2d |

### 4.3 Phase 3：CDE 安全加固（P2 阶段）

| # | 问题 | 修复方案 | 预计工时 |
|---|------|----------|----------|
| 1 | Formula VM 沙箱逃逸 | 独立进程执行 + 白名单 AST + cgroup 资源限制 | 3d |
| 2 | Asset 路径遍历 | 路径规范化 + 白名单校验，禁止 `../` | 4h |
| 3 | LLM API Key 泄露 | KMS 管理 + 服务端代理（前端不直接调用 LLM） | 1d |
| 4 | MCP 越权 | 每个 MCP 调用校验用户权限 + 操作审计 | 2d |
| 5 | 赛事工坊配置注入 | YAML Schema 严格校验 + 禁止未知字段 | 1d |
| 6 | 前端 XSS（编排器） | `on_click` 等事件绑定只允许白名单 action | 4h |

### 4.4 Phase 4：生产级运维（长期）

| # | 项目 | 方案 |
|---|------|------|
| 1 | 日志聚合 | ELK / 云厂商日志服务，保留 90 天 |
| 2 | 监控告警 | Prometheus + Grafana，CPU/内存/WS 连接数/QPS |
| 3 | 自动化测试 | 安全扫描（SAST/DAST）集成 CI/CD |
| 4 | 渗透测试 | 上线前第三方安全测试 |
