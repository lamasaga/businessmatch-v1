## 2. 产品定位

### 2.1 一句话玩法

　　**OPS 是一场围绕产品定位、产销运营和关键资源竞拍展开的回合制商业模拟赛**：队伍经营一家虚拟公司，在 6 轮运营和 2 次拍卖中配置生产、定价、营销、研发、渠道与战略资源，最终以净资产和累计利润排名。

### 2.2 教育目标

| # | 能力 | 游戏中如何体现 |
|---|------|----------------|
| 1 | 商业闭环理解 | 产品定位、生产、定价、销售、报表、资产结算形成闭环 |
| 2 | 资源配置 | 每轮在现金约束下权衡产量、价格、营销、研发、人力与城市进入 |
| 3 | 战略时点判断 | R1 前和 R4 前两次拍卖让学生判断“早期基础资源”和“中后期战略资源”的价值 |
| 4 | 财务健康 | 每轮输出损益表、资产负债表、库存与净资产变化 |
| 5 | 市场竞争 | Softmax 份额、城市客群、价格与品牌共同影响销量 |
| 6 | 风险意识 | 主题事件、竞价溢价、库存积压和现金约束制造不确定性 |
| 7 | 团队协作 | 正式赛中队伍需在 20 分钟倒计时内形成一致决策 |

### 2.3 目标受众

| 维度 | 说明 |
|------|------|
| 目标年龄 | 14~18 岁为主，可扩展至大学低年级 |
| 适合场景 | 商赛训练营、夏令营、课堂经营模拟、正式控场赛 |
| 练习赛 | 单人、无时间限制、AI 对手补齐、点击推进 |
| 正式赛 | 4~40 支队伍，2~6 人/队，教师控场 |
| 标准正式赛时长 | 约 150~180 分钟，可拆成两节或多节课 |
| 快速练习时长 | 30~60 分钟，取决于玩家阅读与决策速度 |

### 2.4 单局节奏

```text
产品定位
  ↓
拍卖 A：基础经营资源（R1 前）
  ↓
R1 运营决策
  ↓
R2 运营决策
  ↓
R3 运营决策
  ↓
拍卖 B：独家渠道 / 战略资源 / 品牌代言 / 法律保护（R4 前）
  ↓
R4 运营决策
  ↓
R5 运营决策
  ↓
R6 运营决策
  ↓
最终结算 + 排名 + Career 奖励
```

　　正式赛运营轮默认 **20 分钟/轮**，教师可手动提前截止或延长。练习赛不设倒计时：真人提交策略后，AI 自动补齐策略，页面的「进入下一回合」按钮亮起，玩家点击后推进。

### 2.5 阿思丹/ABS 类赛事对标结论

　　公开资料中，阿思丹商业模拟类活动通常不是单一软件功能，而是由多轮经营模拟、战略资源竞拍、商业演讲/路演、案例分析、交易谈判或商业对决等环节组成的综合赛程。OPS 本轮 P0 只承接其中最适合产品化和自动结算的主干：同起始资金、同市场规则、多轮经营决策、关键资源竞拍、财务报表反馈和最终排名。

| 对标元素 | 阿思丹/ABS 类活动常见形态 | OPS 本轮处理 |
|----------|---------------------------|--------------|
| 多轮经营 | 队伍在相同初始条件下做经营决策，比拼经营表现 | P0：6 轮运营决策 |
| 战略资源 | 通过竞拍/争夺获得稀缺资源，改变后续策略空间 | P0：R1 前拍卖 A、R4 前拍卖 B |
| 主题化赛题 | 每场赛事可围绕不同产业、产品或商业情境展开 | P0：`theme_pack` 改名和叙事，不改结算内核 |
| 财务表现 | 以经营成果、资产或综合表现形成排名依据 | P0：净资产 70% + 累计利润 30% |
| 路演表达 | 商业计划、展示、答辩、评委评价 | P1/P2：外围活动，不进入本轮引擎结算 |
| 交易谈判 | 队伍间自由交易、资源置换或商务谈判 | P1/P2：活动层扩展，不进入 P0 |
| 知识问答/案例 | 商业知识、案例分析、评委评分 | P1/P2：课程/活动层扩展 |

　　因此，OPS 当前的“6 轮 + 双拍卖”不是完整复刻某个阿思丹赛程，而是提炼出最稳定、最适合在线练习和教师控场的经营模拟内核。这样设计既能贴近真实商赛的资源竞争和经营反馈，又避免把路演、评委评分和现场谈判一次性塞进 P0，导致引擎难以落地。

## 3. 核心循环

### 3.1 阶段列表

| 阶段 | 触发时机 | 核心动作 | 输出 |
|------|----------|----------|------|
| 产品定位 | 开赛后 | 选择品类、客群、产品名 | 成本结构与客群权重 |
| 拍卖 A | R1 前 | 竞拍生产线、原材料折扣、城市广告位 | 全局生效的基础资源 |
| R1~R3 | 前半场运营 | 生产、定价、营销、研发、人力、城市 | 每轮财务报表、排名 |
| 拍卖 B | R4 前 | 竞拍独家渠道、战略资源、品牌代言、法律保护 | 全局生效的战略资源 |
| R4~R6 | 后半场运营 | 利用资源优势完成冲刺 | 每轮财务报表、排名 |
| 最终结算 | R6 后 | 计算净资产、累计利润、特殊奖项 | 排名、奖励、复盘数据 |

### 3.2 状态机

| phase | 说明 | 可执行操作 |
|-------|------|------------|
| `registration` | 开放加入 | 加入、组队 |
| `positioning` | 产品定位 | 提交定位卡 |
| `auction_a` | R1 前拍卖 | 出价、跳过、结算拍卖 |
| `operation_round_1` | R1 运营 | 提交决策、查看状态 |
| `operation_round_2` | R2 运营 | 提交决策、查看状态 |
| `operation_round_3` | R3 运营 | 提交决策、查看状态 |
| `auction_b` | R4 前拍卖 | 出价、跳过、结算拍卖 |
| `operation_round_4` | R4 运营 | 提交决策、查看状态 |
| `operation_round_5` | R5 运营 | 提交决策、查看状态 |
| `operation_round_6` | R6 运营 | 提交决策、查看状态 |
| `finished` | 比赛结束 | 查看结果、奖励、复盘 |
| `paused` | 正式赛暂停 | 教师恢复 |

　　当前代码仍使用 `auction`、`operation_round_1~4` 等首期 phase；补齐 6+2 时以本表为目标，兼容迁移见 [SPEC-OPS.md](./SPEC-OPS.md)。

### 3.3 推进规则

| 模式 | 推进规则 |
|------|----------|
| 练习赛 | 无教师；真人提交当前阶段内容后，AI 自动补齐；「进入下一阶段」按钮亮起；玩家点击后推进 |
| 正式赛 | 教师控场；20 分钟倒计时必须生效；教师可提前截止、延长、暂停、恢复 |
| 拍卖 | 首期可由阶段推进按钮结算；倒计时与最后阶段提示是正式赛 P0 体验要求 |
| 结算 | 每次推进只结算当前阶段一次；重复点击必须幂等 |

## 4. 决策设计

### 4.1 产品定位

| 决策项 | 英文名 | 可选值 | 影响 |
|--------|--------|--------|------|
| 产品名 | `product_name` | 1~100 字 | 展示与复盘 |
| 产品品类 | `category` | `electronics` / `fast_moving` / `home` | 基础成本、基准价、市场规模 |
| 目标客群 | `target_segment` | `geek` / `pragmatic` / `show` | Tech/Fit/Show 权重 |

### 4.2 运营决策

| 决策项 | 英文名 | 类型 | 约束 |
|--------|--------|------|------|
| 生产量 | `production_quantity` | int | `>= 0`，受产能限制 |
| 单价 | `unit_price` | float | `> 0` |
| 营销投入 | `marketing_spend` | float | `>= 0` |
| 研发投入 | `rnd_spend` | float | `>= 0` |
| 销售人员数 | `sales_force` | int | `0~max_sales_force` |
| 目标城市 | `target_cities` | list[str] | 最多 3 个，必须存在于配置 |

　　总支出不得超过现金。新进入城市需支付一次性开城费。决策提交以 `ops_decision:{match_id}:{round_id}:{team_id}` 幂等。

### 4.3 拍卖 A：基础经营资源

　　拍卖 A 位于 R1 前，资源全局生效，适合帮助队伍确立前半场经营路线。

| 拍品类型 | 示例名称 | 效果 |
|----------|----------|------|
| 生产线 | 标准生产线 / 高端生产线 | 提升产能或产品品质 |
| 原材料折扣 | 供应商合同 | 降低原材料成本 |
| 城市广告位 | 上海广告位 / 杭州广告位 | 提升指定城市 Show 效果 |

### 4.4 拍卖 B：战略资源

　　拍卖 B 位于 R4 前，资源全局生效。具体名称应随每场比赛主题变化，可参考阿思丹类赛事每场主题化命名。

| 拍品类型 | 示例名称 | 效果方向 |
|----------|----------|----------|
| 独家渠道 | 校园渠道独家代理 / 区域经销权 | 增加需求、降低进入成本或提升城市份额 |
| 战略资源 | 稀缺供应协议 / 数据资源包 | 强化成本、研发、产能或需求侧优势 |
| 品牌代言 | 主题代言人 / 展会主舞台 | 提升 Show、品牌溢价或目标客群偏好 |
| 法律保护 | 专利保护 / 区域合规护城河 | 降低竞争扰动、保护份额或减少事件损失 |

### 4.5 不做范围

| 机制 | 状态 |
|------|------|
| 融资路演 / 商业计划书 / 答辩 | Phase B+ 活动外围扩展，不影响 P0 结算 |
| 玩家间自由交易 / 交易大会 | Phase B+ 活动外围扩展 |
| 商业知识问答 / 案例分析 | Phase B+ 课程或赛程扩展 |
| 贷款、分红、复杂负债 | Phase B+ 扩展 |
| LLM 裁判或自然语言结算 | Phase C+ |
| 跨比赛持久 World 状态 | Phase C+ |

## 5. 结算规则

### 5.1 单轮结算

```python
def settle_round(
    match_state: dict,
    decisions: dict,
    cfg: dict,
) -> dict:
    """结算单轮运营决策。纯函数、幂等、不读写数据库。"""
```

　　DB 编排由 `games/ops_sim/settle.py` 负责；纯计算由 `games/ops_sim/engine.py` 负责。结算必须记录中间变量，方便解释“为什么销量/利润/排名变化”。

### 5.2 单轮结算步骤

1. 读取队伍状态、产品定位、拍卖资源、城市配置。
2. 校验并裁剪生产量到产能上限。
3. 扣除原材料、营销、研发、人力、开城费等支出。
4. 计算 Tech/Fit/Show 与价格形成的城市效用。
5. 用 Softmax 分配市场份额。
6. 计算销量、库存、收入、成本、毛利、运营利润。
7. 结转现金、库存、累计利润、净资产。
8. 更新研发、营销等属性增量。
9. 生成损益表、资产负债表、新闻/事件提示。
10. 生成排行榜和下一阶段可读状态。

### 5.3 最终排名

```text
total_score = net_assets * scoring_weights.net_assets
            + cumulative_profit * scoring_weights.cumulative_profit
```

　　默认权重为净资产 0.70、累计净利润 0.30。排行榜按 `total_score` 降序；同分时按净资产、累计利润、最后一轮提交时间或稳定种子排序，具体口径进入 SPEC。

## 6. AI 对手

### 6.1 AI 要求

| 项 | 要求 |
|----|------|
| Token | 0，禁止调用 LLM |
| 策略 | `balanced` / `aggressive` / `conservative` |
| 练习赛 | 自动补齐定位、运营决策和拍卖决策 |
| 正式赛 | 可作为空位填补或教师强制托管的后续扩展 |
| 可预测性 | 同一状态下输出稳定或由可复现随机种子控制 |

### 6.2 三档行为

| 策略 | 行为 |
|------|------|
| `balanced` | 产量接近预期需求，价格接近均价，营销/研发/人力均衡 |
| `aggressive` | 高产量、低价、高营销，拍卖愿意更高溢价 |
| `conservative` | 低产量、高价、控现金，拍卖只在估值较低时参与 |

## 7. 前端体验

### 7.1 学生练习赛

　　练习赛是 OPS 的第一体验入口，必须保证单人无教师跑完整局。页面应在每个阶段清楚显示：

- 当前阶段与剩余阶段。
- 本队现金、库存、净资产、Tech/Fit/Show。
- 决策是否已提交。
- AI 是否已补齐。
- 「进入下一阶段」按钮是否可用。
- 本阶段结算后的关键因果解释。

### 7.2 正式赛

　　正式赛由教师控场。学生端必须服从倒计时和阶段锁定；教师端必须有 start、advance、pause、resume、screen/control 状态接口。正式赛倒计时不是装饰，它必须影响阶段状态或至少严格控制提交窗口。

### 7.3 教师控场 / 大屏

　　首期要求有完整控场数据接口，保证教师端不黑屏。独立投影页、图表增强、讲解模式属于 P1，但 `/screen` payload 必须稳定返回完整数组字段。

## 8. 配置规格

### 8.1 顶层结构

```yaml
id: ops-sim-v1
engine: ops_sim
meta:
  name: 生产经营销售赛
  runtime: react-game
design_mode: standalone
defaults:
  rounds: 6
  decision_time_minutes: 20
  practice_ai_count: 3
auction_stages:
  auction_a:
    before_round: 1
    item_pool: basic_operations
  auction_b:
    before_round: 4
    item_pool: strategic_resources
```

### 8.2 主题化配置

　　OPS 每场可以有自己的主题。主题不改变核心引擎，但可以改变展示名称、拍品叙事、城市/客群文案、新闻文本和奖励标题。

```yaml
theme_pack:
  id: campus-consumer-2026
  name: 校园消费品创业赛
  auction_b_labels:
    exclusive_channel: 校园渠道独家代理
    strategic_resource: 供应链数据资源包
    brand_endorsement: 校园明星代言
    legal_protection: 专利与合规保护
```
