# 异步状态机基础

> 本章讲解状态机、行为树、异步执行、黑板架构等基础，为后续 LLM + 状态机结合打基础。

## 1. 为什么要用状态机

NPC 的行为需要：

- **可预测**：玩家能理解 NPC 为什么这样做。
- **可调试**：出问题能找到原因。
- **可复现**：相同输入产生相同输出。
- **高性能**：大量 NPC 同时运行。

状态机能满足这些需求。LLM 负责自然语言，状态机负责行为控制。

## 2. 有限状态机（FSM）

### 2.1 基本概念

FSM 由以下部分组成：

- **状态（State）**：NPC 当前处于什么状态。
- **事件（Event）**：触发状态变化的外部信号。
- **转移（Transition）**：从一个状态到另一个状态的规则。
- **动作（Action）**：进入/退出状态时执行的行为。

### 2.2 商业 NPC 状态示例

```
[待机] --发现机会--> [评估机会]
    ↑                      │
    └──执行失败/放弃── [执行行动] --成功--
```

具体状态：

- 待机（Idle）
- 工作（Working）
- 寻找机会（OpportunitySeeking）
- 谈判（Negotiating）
- 执行项目（ExecutingProject）
- 危机处理（CrisisHandling）
- 休息/恢复（Resting）

## 3. 分层状态机（HFSM）

### 3.1 为什么分层

当状态很多时，FSM 会变成面条代码。HFSM 把相关状态组织成层级：

```
[商业生涯]
├── [在职]
│   ├── [稳定工作]
│   ├── [寻求晋升]
│   └── [准备跳槽]
├── [创业]
│   ├── [筹备]
│   ├── [早期]
│   ├── [成长期]
│   └── [危机]
└── [退休/投资]
```

### 3.2 优点

- 减少状态数量。
- 复用通用行为。
- 更容易理解。

## 4. 行为树（BT）

### 4.1 基本概念

行为树用树形结构组织行为：

| 节点类型 | 功能 |
|----------|------|
| Sequence | 顺序执行，一个失败就返回失败 |
| Selector | 选择执行，一个成功就返回成功 |
| Action | 执行具体动作 |
| Condition | 判断条件 |
| Decorator | 修饰子树行为（如循环、反转） |

### 4.2 商业 NPC 行为树示例

```
Selector: 处理当前情况
├── Sequence: 公司有危机
│   ├── Condition: 现金流 < 阈值
│   ├── Action: 寻找融资
│   └── Action: 削减成本
├── Sequence: 有晋升机会
│   ├── Condition: 绩效优秀
│   ├── Action: 向上司表达意愿
│   └── Action: 争取项目
└── Action: 日常工作
```

### 4.3 FSM vs BT

| 维度 | FSM | BT |
|------|-----|----|
| 适用 | 状态切换清晰 | 复杂决策 |
| 模块性 | 低 | 高 |
| 可读性 | 状态少时好 | 树形直观 |
| 反应性 | 需显式处理 | 内置反应 |

**最佳实践**：

- 用 **FSM** 管理高层状态（在职/创业/退休）。
- 用 **BT** 管理具体决策（如何应对当前情况）。
- 用 **黑板（Blackboard）** 共享数据。

## 5. 异步执行

### 5.1 什么是异步状态机

NPC 的行动可能需要很长时间：

- 一个项目持续数月。
- 一段关系需要多回合培养。
- 等待市场时机。

异步状态机允许：

- 行动在执行过程中被中断。
- 状态可以持续多个回合。
- 多个 NPC 同时行动。

### 5.2 实现方式

```python
class AsyncStateMachine:
    def __init__(self):
        self.current_state = IdleState()
        self.pending_action = None
    
    async def update(self, dt):
        # 检查当前状态是否需要转移
        new_state = self.current_state.check_transition()
        if new_state:
            await self.transition_to(new_state)
        
        # 执行当前状态的持续行为
        await self.current_state.update(dt)
```

### 5.3 游戏中的异步

```python
class ProjectExecutionState:
    def __init__(self, project):
        self.project = project
        self.progress = 0
    
    async def update(self, dt):
        self.progress += self.project.team_productivity * dt
        
        # 检查是否完成
        if self.progress >= self.project.total_work:
            return ProjectCompletedState(self.project)
        
        # 检查是否出现危机
        if random() < self.project.risk_per_tick:
            return CrisisState(self.project)
        
        return None  # 继续当前状态
```

## 6. 黑板架构（Blackboard）

### 6.1 什么是黑板

黑板是状态机和行为树共享数据的中心仓库：

```python
class Blackboard:
    def __init__(self):
        self.data = {}
    
    def set(self, key, value):
        self.data[key] = value
    
    def get(self, key, default=None):
        return self.data.get(key, default)
```

### 6.2 商业 NPC 黑板示例

```python
blackboard = {
    'npc_id': 'zhang_san',
    'current_company': 'techstar_inc',
    'cash': 50000,
    'skills': {'programming': 8, 'management': 5},
    'relationships': {'li_si': 0.7, 'wang_wu': -0.3},
    'goals': ['start_company', 'earn_1m'],
    'stress': 0.3,
    'recent_events': ['promoted', 'conflict_with_wang_wu'],
    'opportunities': ['new_project', 'investment_offer']
}
```

## 7. 事件队列

### 7.1 为什么需要事件队列

NPC 之间需要互相影响：

- A 挖角 B 的员工。
- C 向 D 发起合作邀约。
- E 的公司破产影响 F 的投资。

事件队列让这些交互有序处理。

### 7.2 事件处理流程

```python
class EventQueue:
    def __init__(self):
        self.events = []
    
    def add_event(self, event):
        self.events.append(event)
    
    async def process(self):
        for event in sorted(self.events, key=lambda e: e.priority):
            await self.handle_event(event)
        self.events = []
```

## 8. 调度器

### 8.1 异步 NPC 调度

```python
class NpcScheduler:
    def __init__(self):
        self.npcs = []
    
    async def tick(self):
        # 并行更新所有 NPC
        await asyncio.gather(*[
            npc.update() for npc in self.npcs
        ])
```

### 8.2 优先级

不是所有 NPC 都需要每回合更新：

- 主角身边的 NPC：高频更新。
- 普通 NPC：低频更新。
- 远方 NPC：只在相关事件时更新。
