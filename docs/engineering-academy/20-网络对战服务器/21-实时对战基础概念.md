# 实时对战基础概念

> 多人在线对战是赛事引擎的高级形态。本文解释实时对战里的核心概念，帮你和 AI 用同一套语言沟通。

## 1. 什么是在线对战

多个玩家通过互联网连接到同一个服务器，参与同一场比赛。服务器负责：

- 同步游戏状态
- 接收玩家操作
- 判定胜负
- 防止作弊

## 2. 关键角色

| 角色 | 说明 |
|------|------|
| 客户端（Client） | 玩家使用的浏览器 / App |
| 服务器（Server） | 后端程序，统一裁决 |
| 房间（Room/Match） | 一场比赛的隔离空间 |
| Tick | 实时游戏的最小时间单位 |
| 状态（State） | 某一时刻游戏的完整数据 |
| 输入（Input） | 玩家发送的操作命令 |

## 3. 实时 vs 回合制

| 对比 | 回合制 | 实时制 |
|------|--------|--------|
| 节奏 | 慢，等所有人提交 | 快，自动推进 |
| 同步压力 | 低 | 高 |
| 网络要求 | 可接受延迟 | 要求低延迟 |
| 代码复杂度 | 低 | 高 |
| 例子 | TechVenture | 浮生记 RTS |

## 4. 服务器权威（Server Authoritative）

重要原则：**服务器说的才算数**。客户端只能请求操作，不能自己改状态。

为什么？

- 防止玩家用外挂修改本地数据
- 保证所有玩家看到的状态一致
- 方便回放和仲裁

## 5. 延迟（Latency）

玩家操作从发出到生效需要时间，这个时间叫延迟或 ping。

- 延迟 < 100ms：很流畅
- 100~200ms：可接受
- > 300ms：明显卡顿

商业模拟对实时性要求不如 FPS 那么高，但仍需要让玩家感觉「我点了就有反馈」。

## 6. 与 AI 沟通关键词

| 你想说的 | 关键词 |
|---------|--------|
| 多人同时玩 | "multiplayer real-time match" |
| 服务器裁决 | "server authoritative" |
| 自动推进 | "tick-based scheduler" |
| 玩家隔离 | "room / match isolation" |
| 低延迟 | "low latency, optimize ping" |
| 防止作弊 | "anti-cheat, input validation" |
