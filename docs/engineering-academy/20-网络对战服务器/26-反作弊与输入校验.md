# 反作弊与输入校验

> 商业模拟涉及排名和奖励，必须防止玩家作弊。本文讲基础防护思路。

## 1. 核心原则：服务器权威

所有关键计算都在服务器做，客户端只负责：

- 显示
- 收集输入
- 播放动画

不相信客户端发来的任何「结果」，只相信「操作请求」。

## 2. 输入校验

客户端发来的每个操作都要检查：

| 检查项 | 说明 |
|--------|------|
| 身份校验 | 这个玩家真的在这个房间里吗 |
| 时机校验 | 现在允许操作吗 |
| 权限校验 | 这个玩家有权限做这件事吗 |
| 范围校验 | 数值是否在合法范围内 |
| 资源校验 | 玩家有足够资源吗 |
| 状态校验 | 当前状态允许这个操作吗 |

## 3. 常见作弊手段

| 手段 | 防护方式 |
|------|---------|
| 修改本地数值 | 服务器权威，不采信客户端结果 |
| 重复提交 | 使用幂等键或去重 |
| 伪造身份 | JWT 鉴权 + 房间成员校验 |
| 加速 / 外挂 | 服务器按 tick 处理，不依赖客户端时间 |
| 越权操作 | 严格校验玩家权限 |

## 4. 日志与审计

关键操作要记录日志：

- 谁
- 什么时候
- 做了什么
- 操作前后的状态

方便事后审计和纠纷处理。

## 5. AI 玩家公平性

如果 AI 玩家和人类玩家同场：

- AI 必须走同样的接口
- AI 不能看到不该看的信息
- AI 的随机数要可控，便于回放

## 6. 与 AI 沟通示例

```
我要为交易操作增加反作弊校验。
需求：
- 校验玩家身份和房间成员关系
- 校验交易数量不超过库存
- 校验价格在市场允许范围内
- 校验操作在合法 tick 内
- 所有校验失败记录日志并拒绝操作
请写在 scheduler 处理 action 时统一校验。
```
