# 如何验证 AI 的输出

> AI 会犯错，尤其是长上下文和跨文件修改。本文讲验收清单，防止被 AI 带偏。

## 1. 不要只看结果，要看过程

AI 给你代码时，要问：

- 改了哪些文件？
- 为什么这样改？
- 有没有违反域边界？
- 有没有改到不该改的表？

## 2. 后端验收清单

- [ ] 没有跨域写入
- [ ] 新表放到正确的域
- [ ] API 路径符合 REST 规范
- [ ] 参数有校验
- [ ] 身份和权限校验完整
- [ ] 数据库事务正确
- [ ] RTS 没有绕过调度器推进 tick
- [ ] YAML 配置可加载
- [ ] 单元测试或可运行验证

## 3. 前端验收清单

- [ ] 新页面有对应路由
- [ ] 调用了正确的 API
- [ ] 错误状态有处理
- [ ] 加载状态有处理
- [ ] 响应式适配
- [ ] 不使用 mock 数据冒充真实接口

## 4. 美术验收清单

- [ ] 尺寸符合规范
- [ ] 命名符合规范
- [ ] 透明背景正确
- [ ] 提供了所有状态
- [ ] 提供了 assets-manifest.json
- [ ] 前端引用的是 manifest 而不是硬编码路径

## 5. 跑起来验证

能运行就不要只看代码：

- 启动后端
- 启动前端
- 走一遍完整流程
- 看日志有没有报错
- 看数据库里数据对不对

## 6. 让 AI 自己检查

可以让 AI 做自评：

```
请检查以上修改，回答：
1. 是否违反了硬域边界？
2. 是否修改了 arena 表？
3. 是否所有新增 API 都有鉴权？
4. 是否引入了循环导入？
5. 列出至少 3 个潜在风险。
```

## 7. 遇到错误怎么处理

1. 把完整报错贴给 AI
2. 说明触发步骤
3. 让 AI 解释原因
4. 让 AI 给出最小修复

不要：

- 盲目接受「可能可行」的方案
- 让 AI 一次性改十个文件再验证
