# 搜索与规划 AI

> 当 AI 需要在大量可能性中找到最优解时，就需要搜索与规划。本章讲游戏中最常用的几种搜索算法。

## 1. 路径搜索：A*（A-Star）

### 原理

在地图上找从起点到终点的最短路径。

```
f(n) = g(n) + h(n)

- g(n)：从起点到 n 的实际代价
- h(n)：从 n 到终点的估计代价（启发函数）
```

每次选择 `f(n)` 最小的节点扩展。

### 例子

浮生记 RTS 中，AI 商人从一个城市移动到另一个城市，如果路网复杂，就可以用 A* 找最短/最便宜路线。

### 适用场景

- 单位移动
- 地图导航
- 物流路径规划

### 启发函数

- **曼哈顿距离**：格子只能四方向移动
- **欧几里得距离**：任意方向移动
- **实际路网距离**：用预计算距离

## 2. 博弈树搜索：Minimax

### 原理

两个玩家轮流行动，一方想最大化自己的得分，另一方想最小化对方的得分。

```
Max（我方）选择最大子节点
Min（敌方）选择最小子节点
```

### Alpha-Beta 剪枝

剪掉不可能影响最终决策的分支，减少计算量。

### 适用场景

- 棋类游戏（象棋、五子棋）
- 回合制策略对战
- 任何完全信息双人博弈

### 与商业模拟的关系

TechVenture 中，可以把「我和其他队伍的投资决策」看成博弈，但状态空间太大，Minimax 不太实用。更适合用规则 + 评估函数。

---

## 3. 蒙特卡洛树搜索（MCTS）

### 原理

通过大量随机模拟来评估决策。

四个步骤循环：

1. **选择（Selection）**：从根节点选择最有潜力的子节点。
2. **扩展（Expansion）**：加入新节点。
3. **模拟（Simulation）**：随机玩到结束，得到结果。
4. **回传（Backpropagation）**：把结果更新到路径上的节点。

### 适用场景

- 围棋、象棋等复杂棋类
- 卡牌游戏
- 状态空间巨大、难以用 Minimax 的问题

### 优点

- 不需要领域知识也能工作
- 随时可以被中断并返回当前最优解
- 适合高分支因子游戏

### 缺点

- 需要大量模拟
- 对实时游戏可能太慢
- 在商业模拟中不一定合适

## 4. 目标导向行动规划（GOAP）

### 原理

AI 有目标，系统反向规划出一系列动作达成目标。

```
目标：拥有 1000 金币
└── 动作：卖出库存
    └── 前提： inventory.rice > 0
    └── 效果： gold += 100, inventory.rice -= 1
```

### 适用场景

- 复杂 NPC（如《求生之路》《神偷》）
- 需要动态组合动作的系统
- 策略游戏 AI

### 与商业模拟的关系

浮生记 advanced AI 可以升级为 GOAP：

```
目标：最大化总资产
└── 子目标：在最高 bid 城市卖出库存
    └── 动作1：移动到目标城市
    └── 动作2：卖出商品
```

## 5. 搜索算法的选择

| 问题 | 推荐算法 |
|------|---------|
| 地图路径 | A* |
| 双人完全信息博弈 | Minimax + Alpha-Beta |
| 复杂棋类/卡牌 | MCTS |
| 动作组合规划 | GOAP |
| 实时策略多目标 | 效用系统 + 局部搜索 |

## 6. 与 AI 沟通示例

```
我要改进浮生记 advanced AI 的路线选择。
当前 AI 只扫描当前已知价格，我希望它：
- 根据未来 N 个 tick 的价格预测选择移动目标
- 考虑运输时间和路费成本
- 在多个城市间规划一条利润最大的巡回路线

请用 A* 或局部搜索实现，保持规则可解释，
不要引入神经网络。输出候选路径和预期利润。
```
