# 简单 AI 类型

> 不是每个游戏都需要深度学习。很多情况下，规则 AI 就够了。本章讲最基础的 AI 类型及其适用场景。

## 1. 随机 AI（Random AI）

### 原理

每次决策从合法选项中随机选一个。

```python
action = random.choice(legal_actions)
```

### 适用场景

- 新手教程敌人
- 需要不可预测性的简单行为
- 测试用的占位 AI

### 优缺点

| 优点 | 缺点 |
|------|------|
| 实现极简单 | 没有策略性 |
| 行为不可预测 | 可能做出明显愚蠢的行为 |
| 计算成本为零 | 玩家无法学习对抗模式 |

### 项目中例子

浮生记 `chaotic` AI：20% 概率故意做反向操作，模拟不稳定的市场参与者。

---

## 2. 查表 AI（Lookup Table / Scripted AI）

### 原理

预先写好「如果遇到情况 X，就做动作 Y」的表格。

```
如果 血量 < 30% → 逃跑
如果 敌人在射程内 → 攻击
如果 弹药 = 0 → 换弹
```

### 适用场景

- 简单 NPC
- 固定行为模式的 Boss
- 教学关卡

### 优缺点

| 优点 | 缺点 |
|------|------|
| 完全可控 | 行为呆板 |
| 易于调试 | 难以应对未预料情况 |
| 性能最好 | 维护大量规则会爆炸 |

---

## 3. 有限状态机（Finite State Machine, FSM）

### 原理

AI 有若干个状态，在状态之间按条件切换。

```
[待机] --看到玩家--> [追击] --靠近--> [攻击] --玩家死亡--> [待机]
```

### 代码结构

```python
class AI:
    def update(self):
        if self.state == "idle":
            if self.see_player():
                self.state = "chase"
        elif self.state == "chase":
            if self.near_player():
                self.state = "attack"
```

### 适用场景

- 敌人 AI
- NPC 日常行为
- 简单对话流程

### 优缺点

| 优点 | 缺点 |
|------|------|
| 直观易懂 | 状态多了会成面条代码 |
| 易于实现 | 难以表达并行行为 |
| 调试方便 | 扩展性差 |

---

## 4. 行为树（Behavior Tree, BT）

### 原理

用树形结构组织行为。节点类型：

| 节点类型 | 作用 |
|----------|------|
| **Sequence（顺序）** | 从左到右执行，一个失败就返回失败 |
| **Selector（选择）** | 从左到右执行，一个成功就返回成功 |
| **Action（动作）** | 执行具体行为 |
| **Condition（条件）** | 判断条件是否满足 |

### 例子

```
Selector
├── Sequence: 攻击玩家
│   ├── Condition: 看到玩家
│   ├── Condition: 在射程内
│   └── Action: 射击
├── Sequence: 追击玩家
│   ├── Condition: 看到玩家
│   └── Action: 移动向玩家
└── Action: 巡逻
```

### 适用场景

- 复杂敌人 AI
- NPC 行为组合
- 需要模块化、可复用行为的系统

### 优缺点

| 优点 | 缺点 |
|------|------|
| 模块化 | 学习曲线比 FSM 陡 |
| 可复用子树 | 调试复杂行为较困难 |
| 比 FSM 更适合复杂逻辑 | 设计不好会变成复杂面条 |

---

## 5. 基于规则的 AI（Rule-Based AI）

### 原理

用一系列「如果…那么…」规则做决策。比查表更灵活，规则可以组合、加权。

```
如果 现金 > 20000 且 库存紧张 → 买车辆
如果 当前城市 A 的商品 bid > 其他城市 ask × 1.12 → 移动去 A 卖出
如果 产能利用率 < 50% → 减少生产
```

### 适用场景

- 商业模拟中的 AI 对手
- 策略游戏
- 需要可解释决策的系统

### 优缺点

| 优点 | 缺点 |
|------|------|
| 决策可解释 | 规则多后难以维护 |
| 容易调整 | 难以涌现复杂策略 |
| 性能好 | 高手容易找到规律 |

### 项目中例子

- TechVenture AI：按预算比例分配 Tech/Fit/Show 投入。
- OPS AI：按 aggressive/conservative/balanced 策略分配预算。
- 浮生记 advanced AI：规则 + 简单套利扫描。

---

## 6. 决策树（Decision Tree）

### 原理

把规则组织成树状结构，每个内部节点是一个条件判断，叶子是动作。

```
现金 > 10000?
├── 是 → 库存 > 80%?
│   ├── 是 → 卖出
│   └── 否 → 买入便宜货
└── 否 → 等待
```

### 适用场景

- 分类型决策
- 可解释 AI
- 数据驱动更新（可用决策树学习算法生成）

---

## 7. 效用系统（Utility AI）

### 原理

给每个可能动作打分，选择得分最高的。

```python
scores = {
    "attack": score_attack(),
    "heal": score_heal(),
    "flee": score_flee(),
}
action = max(scores, key=scores.get)
```

### 适用场景

- 需要在多个目标间权衡的 AI
- 复杂 NPC
- 策略游戏

### 优点

- 比规则更灵活
- 自然表达「权衡」
- 易于扩展新动作

---

## 8. 如何选择简单 AI

| 场景 | 推荐方案 |
|------|---------|
| 完全随机、占位 | 随机 AI |
| 固定行为脚本 | 查表 AI |
| 少量状态切换 | 有限状态机 |
| 模块化复杂行为 | 行为树 |
| 可解释的商业决策 | 规则 AI / 决策树 |
| 多目标权衡 | 效用系统 |

## 9. 与 AI 沟通示例

```
我要为 OPS 引擎增加一种新 AI 策略：「 opportunistic（机会主义）」。
规则：
- 若原材料成本低于基准 90%，则超量生产
- 若某城市场份额 < 5%，则降价 20% 抢份额
- 拍卖中只出价 production 类型，且不超过现金 40%
请用纯规则实现，不要引入机器学习。
```
