# 项目中的落地方案

> 本章把 POP 机制的理论映射到商识唯智平台，给出在当前赛事引擎中落地的具体路径。

## 1. 当前引擎的经济抽象层级

| 引擎 | 当前抽象 | 是否适合引入 POP |
|------|---------|-----------------|
| 浮生记 RTS | 城市池量、总消费/生产 | 中等适合 |
| TechVenture | 市场份额、消费者结构 | 较适合 |
| OPS | 总需求、总供给、市场份额 | 较适合 |

当前三个引擎都用**聚合变量**而非微观 POP。引入 POP 意味着从「总量模型」升级到「微观基础模型」。

## 2. 浮生记 RTS 的 POP 落地方案

### 2.1 现状

- 每个城市有商品的 `pools`（池量）。
- 价格由池量、生产、消费决定。
- 玩家和 AI 与城市池量交易。

### 2.2 可引入的 POP 层

把每个城市的「消费者」和「生产者」拆成 POP：

| POP 类型 | 作用 |
|----------|------|
| 城市居民 | 消费商品，提供基础需求 |
| 农村生产者 | 生产农产品 |
| 工坊工匠 | 生产手工业品 |
| 商人 | 囤货、套利 |

### 2.3 玩家行动 → POP 反馈

| 玩家行动 | POP 反馈 | 宏观涌现 |
|----------|---------|---------|
| 大量买入大米 | 城市消费者可购买量减少 → SoL 下降 | 消费者需求更刚性，价格更敏感 |
| 把低价商品运到高价城市 | 高价城市居民获得商品 → SoL 上升 | 区域价差缩小 |
| 囤积某商品 | 市场供应紧张 → 其他商人 POP 也囤货 | 价格泡沫 |

### 2.4 落地建议

**短期（Phase A）**：

- 不改变核心 RTS 机制。
- 仅在城市层面增加「居民满意度」指标，作为 flavor。
- 玩家大量买入某商品会降低该城市居民满意度，影响该城市未来需求弹性。

**中期（Phase B）**：

- 为每个城市添加消费者 POP 分组（穷人、中产、富人）。
- 不同组对价格敏感度不同。
- 玩家行为影响各组满意度，满意度影响需求和迁移。

**长期（Phase C/D）**：

- 完整 POP 驱动的城市经济。
- 引入劳动力市场、产业升级、政治反馈。

## 3. TechVenture 的 POP 落地方案

### 3.1 现状

- 每个城市有消费者结构（Geek/Pragmatic/Trendy）。
- 市场份额由 Softmax 决定。
- 三属性（Tech/Fit/Show）竞争。

### 3.2 可引入的 POP 层

把消费者从「比例结构」升级为「有收入和偏好的 POP」：

| POP 类型 | 特点 |
|----------|------|
| 普通用户 | 收入中等，注重性价比 |
| 极客用户 | 收入高，注重技术 |
| 潮流用户 | 收入波动大，注重外观 |
| 企业用户 | 批量采购，注重稳定性 |

### 3.3 玩家行动 → POP 反馈

| 玩家行动 | POP 反馈 | 宏观涌现 |
|----------|---------|---------|
| 高价高技术产品 | 极客用户购买，普通用户流失 | 市场细分 |
| 大量营销 | 潮流用户增加，但可能反感 | 品牌热度 |
| 降低价格 | 普通用户涌入 | 市场份额扩大但利润下降 |

### 3.4 落地建议

**短期（Phase A）**：

- 保留当前消费者结构。
- 为每个群体增加「收入」和「价格敏感度」参数。
- 让价格对市场份额的影响更非线性。

**中期（Phase B）**：

- 引入消费者 POP 的收入增长机制。
- 玩家决策影响消费者收入，收入影响消费能力。
- 形成「产品好 → 消费者有钱 → 买更好产品」的正反馈。

## 4. OPS 的 POP 落地方案

### 4.1 现状

- 团队生产产品，面对统一市场需求。
- 市场份额由 Softmax 决定。
- 拍卖影响产能、广告、折扣。

### 4.2 可引入的 POP 层

把市场需求拆成消费者 POP：

| POP 类型 | 特点 |
|----------|------|
| 价格敏感型 | 低价优先 |
| 品质优先型 | 愿意为高品质付高价 |
| 品牌忠诚型 | 跟随品牌 |
| 新尝新型 | 容易被营销吸引 |

### 4.3 玩家行动 → POP 反馈

| 玩家行动 | POP 反馈 | 宏观涌现 |
|----------|---------|---------|
| 降价促销 | 价格敏感型购买增加，品牌忠诚型观望 | 销量上升但品牌形象下降 |
| 提高研发 | 品质优先型购买增加 | 高端市场形成 |
| 大量广告 | 新尝新型涌入 | 短期销量爆发 |

### 4.4 落地建议

**短期（Phase A）**：

- 在 YAML 中为消费者群体增加权重和参数。
- 让玩家决策影响不同群体的得分。

**中期（Phase B）**：

- 消费者 POP 的收入会随比赛经济发展变化。
- 高端产品需求会随中产 POP 增加而上升。

## 5. 新引擎：宏观经济推演引擎

如果 POP 机制足够重要，可以考虑在 Phase B 后新建一个专门的宏观经济推演引擎。

### 5.1 设计要点

- 玩家扮演政府/央行/企业联盟。
- 目标：管理经济、降低失业、控制通胀、提高生活水平。
- 核心：大量 POP + 市场 + 政策反馈。

### 5.2 适合教学的场景

- 货币政策（利率、货币供应量）
- 财政政策（税收、政府支出、补贴）
- 劳动市场政策（最低工资、工会、培训）
- 产业政策（保护关税、技术补贴）

### 5.3 与现有平台的关系

- 新建 `games/macro_sim/` 引擎。
- 复用 Arena 生命周期。
- 独立数据库表，不污染现有引擎。

## 6. 实现路线图

### Phase C/D

- [ ] 引入劳动力市场和产业升级

## 7. 技术实现建议

### 7.1 数据结构

```python
class PopGroup:
    id: str
    pop_type: str          # worker, capitalist, consumer...
    location: str          # city / region
    size: int              # 人口数量
    income: float          # 人均收入
    wealth: float          # 总财富
    satisfaction: float    # 满意度 / SoL
    political_stance: float
    skills: dict           # 技能分布
    demands: dict          # 商品需求
```

### 7.2 更新策略

- 每回合更新一次（回合制引擎）。
- 使用聚合 POP，不要每个个体单独计算。
- 关键事件（如玩家大幅降价）可触发即时局部更新。

### 7.3 与现有结算的集成

- POP 计算在引擎内部完成。
- 宏观指标（价格指数、失业率）作为结算结果的一部分返回给 Arena。
- 前端展示宏观指标和 POP 分布。

## 8. 与 AI 沟通示例

```
我要在 OPS 引擎中试点引入消费者 POP。

目标：
让学生理解「不同消费者对价格和品质的敏感度不同」。

POP 设计：
- 价格敏感型：低价优先，收入低
- 品质优先型：高价也买，收入高
- 品牌忠诚型：跟随品牌
- 新尝新型：容易被营销吸引

集成方式：
- 不修改现有 Softmax 市场份额公式
- 在公式中增加消费者类型权重
- 玩家决策影响不同类型消费者的得分

数据：
- 每队产品有一个「品质得分」和「品牌得分」
- 每队定价影响价格敏感型消费者
- 营销投入影响新尝新型消费者

输出：
- 每回合显示各类消费者购买比例
- 显示价格指数和消费者结构变化

请给出修改方案和 YAML 配置示例。
```
