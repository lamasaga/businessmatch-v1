# 三个赛事引擎 UI 与互动差异化升级设计

> **日期**：2026-06-23
> **范围**：学生端 TechVenture 与 OPS 对战页（Trading 因美术资料不足，本次不做大改动）
> **目标**：让 TechVenture 与 OPS 的 UI、交互与核心玩法完全契合，形成一眼可辨的差异化体验；Trading 保持现有实现不变
> **改造幅度**：局部重构关键组件，保留现有页面架构与状态流

---

## 1. 背景与问题

当前三个赛事引擎（Trading、TechVenture、OPS）在视觉上都使用学生端统一的深色主题 + 金色主色，导致：

1. **辨识度不足**：学生从 UI 上难以快速判断自己正在玩哪个引擎。
2. **玩法与 UI 脱节**：Trading 的核心是地图移动和实时套利，TechVenture 的核心是战略路线和数据迭代，OPS 的核心是阶段化经营决策，但三者界面都偏向“通用深色面板”。
3. **关键组件闲置或薄弱**：TechVenture 的 SVG 战略地图组件已完成但未接入；OPS 缺少阶段时间线；Trading 的地图与深色 HUD 视觉割裂。

本次升级通过**主题叙事、色彩系统、交互范式**三个维度，为每个引擎打造与其机制高度匹配的界面。

---

## 2. 总体设计原则

| 维度 | Trading | TechVenture | OPS |
|------|---------|-------------|-----|
| **核心隐喻** | 古代商路 / 海上丝绸之路 | 科技创业 / 数据驱动的产品迭代 | 模拟公司经营 / ERP 决策台 |
| **情绪氛围** | 冒险、紧张、实时 | 理性、未来、数据 | 沉稳、流程、财务 |
| **交互范式** | 地图点击 + 实时 tick | 战略选择 + 滑块分配 + 数据仪表盘 | 阶段时间线 + 表单决策 + 财务报表 |
| **空间表达** | 海图 + 港口 + 商船 | 无地图，以数据图表为主 | 无地图，以阶段流程为主 |
| **节奏** | 实时 4 秒/游戏日 | 回合制，组织者手动推进 | 回合制，含定位、拍卖、运营多阶段 |

## 4. 各引擎详细设计

### 4.1 Trading · 航海商战

#### 4.1.1 主题包装

将“城市”重新包装为“港口”，“商品运输”包装为“商船航线”，“tick 推进”包装为“航程推进”。玩家不再是点击城市买卖，而是在海图上规划商船航线、装载货物、等待到港交易。

#### 4.1.2 页面布局

```
┌─────────────────────────────────────────────────────────────┐
│  ⚓ 当前港口：泉州   💰 现金 45,000   ⛵ 舰队 3/5   ⏱️ 3s   │  HUD 顶栏
├──────────┬───────────────────────────────┬────────────────┤
│ 邻近港口  │                               │   港口货价     │
│ · 明州   │          海图舞台              │  丝绸 买/卖   │
│ · 广州   │      （港口、航线、商船）        │  瓷器 买/卖   │
│ · 占城   │                               │  香料 买/卖   │
├──────────┴───────────────────────────────┴────────────────┤
│  船队状态                              排行榜              │
└─────────────────────────────────────────────────────────────┘
```

#### 4.1.3 关键交互

1. **港口点击**：显示该港口货物买/卖价格、库存池。
2. **货物操作**：在当前港口选择“装载”（买入）或“卸载”（卖出）。
3. **航线规划**：选择目标港口，商船进入 `transit` 状态，按 tick 航行。
4. **船队管理**：查看每艘船的航线、货物、预计到港时间。

#### 4.1.4 关键升级组件

| 组件 | 当前状态 | 升级动作 |
|------|---------|---------|
| `FushengjiMapStage.tsx` | 长三角商路地图 | 调整为海图风格：深蓝背景、港口徽章、虚线航线、季风流动效果 |
| `FushengjiFleetMarker.tsx` | 卡车标记 | 改为商船标记，增加航线进度和船帆动画 |
| HUD 顶栏 | 通用指标 | 改为航海罗盘样式，突出当前港口、舰队、风向/倒计时 |
| 物价表 | 普通表格 | 改为“港口货单”羊皮纸风格，高亮价差机会 |
| 赛后结算 | 简单排名 | 增加“航海日志”：总航程、利润最高商品、最远航线 |

#### 4.1.5 视觉元素

- 港口徽章：圆形，不同港口用不同纹章图案。
- 商船：金色描边船帆，航行时船帆摆动。
- 航线：虚线，顺风时加流动动画。
- HUD：罗盘边框、绳结装饰、航海字体标题。

### 4.2 TechVenture · 创业数据仪表盘

#### 4.2.1 主题包装

将“城市开拓”概念弱化为数据维度，强化“产品数据迭代”。玩家通过战略路线选择和产品投入分配，观察 Tech/Fit/Show/BQI 等数据指标变化，做出下一轮决策。

#### 4.2.2 页面布局

```
┌────────────────────────────────────────────────────────────────┐
│  🚀 轻语 AI   路线：TECH   💰 剩余 120k   ⏱️ R2 截止 04:32    │  HUD
├───────────────┬───────────────────────────────┬────────────────┤
│  战略选择      │                               │   市场快讯     │
│  TECH        │         数据仪表盘             │   R1 升温     │
│  USER        │  ┌─────┐ ┌─────┐ ┌─────┐     │   R2 隐私     │
│  BRAND       │  │ KPI │ │ KPI │ │ KPI │     │                │
│  PATHFINDER  │  └─────┘ └─────┘ └─────┘     │   排行榜       │
│              │                               │   1. teamA    │
│  资金分配     │      趋势图 / 雷达图           │   2. teamB    │
│  Tech 研发   │                               │                │
│  Fit 适配    │  产品宣言输入框                │                │
│  Show 声量   │                               │                │
└───────────────┴───────────────────────────────┴────────────────┘
```

#### 4.2.3 关键交互

1. **战略路线选择**：四张路线卡片，选中态发光并显示路线 tagline。
2. **资金分配滑块**：Tech/Fit/Show 三个滑块，实时显示剩余预算。
3. **数据仪表盘**：本轮决策后，KPI 卡、趋势图、雷达图同步更新。
4. **产品宣言**：60 字文本输入，可在大屏/评委端展示。

#### 4.2.4 关键升级组件

| 组件 | 当前状态 | 升级动作 |
|------|---------|---------|
| `TvHud.tsx` | 通用顶栏 | 增加轮次倒计时、提交进度条、路线徽章 |
| `TvStrategySelector.tsx` | 路线卡片 | 增加发光选中态、路线数据预览、城市开拓弱化 |
| `TvKpiCards.tsx` | 简单 KPI | 改为数据卡 + 趋势箭头 + 迷你折线图 |
| 新增数据图表区 | 无 | 引入趋势图（Tech/Fit/Show/BQI 历史）和雷达图 |
| `TvStrategyMapPanel.tsx` | 已完成但未接入 | **本次不接入**，改为数据仪表盘，避免地图叙事 |
| 产品宣言 | 简单输入框 | 增加字数提示、宣言展示卡片 |

#### 4.2.5 视觉元素

- 发光卡片：选中态有紫色霓虹描边。
- 数据图表：折线图、面积图、雷达图。
- 进度环：提交倒计时和预算使用进度。
- 快讯流：右侧像新闻 ticker。

### 4.3 OPS · 企业经营决策台

#### 4.3.1 主题包装

将 OPS 包装为“模拟经营一家公司的完整流程”：产品定位 → 拍卖获取资源 → 多轮运营决策 → 财务报表反馈。界面应像简化的 ERP 或经营决策台。

#### 4.3.2 页面布局

```
┌────────────────────────────────────────────────────────────────┐
│  定位 ●  拍卖 A ○  运营 R1-R3 ○  拍卖 B ○  运营 R4-R6 ○   💰 500k │  阶段条
├────────────────────────────────┬───────────────────────────────┤
│                                │                               │
│      当前阶段操作面板           │       财务与拍卖面板           │
│                                │                               │
│   产品定位 / 拍卖出价 /         │   💵 现金流趋势图             │
│   运营决策表单                  │   📊 损益表                   │
│                                │   📈 资产负债表               │
│                                │   🔨 下阶段拍卖预览            │
│                                │                               │
└────────────────────────────────┴───────────────────────────────┘
```

#### 4.3.3 关键交互

1. **阶段时间线**：顶部步骤条显示当前阶段和已完成阶段。
2. **阶段操作面板**：根据当前阶段渲染不同组件：
   - 定位阶段：产品名 + 品类选择 + 目标客群选择
   - 拍卖阶段：出价卡片 + 领先状态
   - 运营阶段：生产/定价/营销/研发/销售/城市表单
3. **财务反馈**：右侧实时显示现金流、损益表、资产负债表。
4. **阶段推进**：组织者推进后，步骤条自动更新，面板切换。

#### 4.3.4 关键升级组件

| 组件 | 当前状态 | 升级动作 |
|------|---------|---------|
| `OpsPlayPage.tsx` | 按阶段渲染组件 | 增加顶部阶段步骤条，统一阶段切换动画 |
| `ProductPositioningPanel.tsx` | 表单 | 增加品类/客群可视化选择卡片 |
| `AuctionHall.tsx` | 拍卖卡片 | 增加竞价氛围：倒计时、领先动画、拍卖锤 |
| `DecisionForm.tsx` | 数字表单 | 增加实时成本计算条、预算警告、城市标签 |
| `FinancialStatements.tsx` | 表格 | 增加可视化：收入/成本趋势图、关键指标卡 |
| 新增阶段条组件 | 无 | 顶部固定步骤条，支持已完成/当前/待完成状态 |

#### 4.3.5 视觉元素

- 阶段步骤条：圆点 + 标签 + 进度线，当前阶段高亮蓝色，已完成打勾。
- 拍卖卡片：橙黄边框，领先时脉冲动画。
- 财务报表：卡片式，关键数字放大，趋势图辅助。
- 经营表单：分组面板，每组有图标和预算提示。

## 5. 通用设计规范

### 5.1 字体与排版

- 标题：Inter / SF Pro Display，`letter-spacing: -0.01em`
- 数字：JetBrains Mono（金额、KPI、倒计时）
- 正文字号：12-14px，表单标签 11-12px
- 标题层级：页面标题 20-24px，面板标题 14-16px

### 5.2 组件规范

- **卡片**：统一 `rounded-xl`（12px），`border-border-subtle`，但各引擎边框色不同：
  - Trading：`#3b6978`
  - TechVenture：`#a855f7`
  - OPS：`#3b82f6`
- **按钮**：主按钮使用引擎主色，危险/警告保持全局。
- **表格**：表头小字 uppercase，行 hover 有 subtle 背景。
- **动效**：所有状态切换使用 200ms ease，数值变化使用计数动画。

### 5.3 响应式

- 桌面端：三栏或两栏布局。
- 平板端：折叠侧边栏为抽屉。
- 移动端：单列堆叠，操作按钮固定在底部。

## 7. 依赖与风险

### 7.1 新增依赖

- 图表库（建议）：`recharts` 或 `chart.js`
  - 用于 TechVenture 趋势图/雷达图
  - 用于 OPS 财务趋势图
  - Trading 城市价差热力图可用 CSS 网格或 Canvas 实现

### 7.2 风险

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| 航海素材（图标/动效）不足 | Trading 叙事感打折扣 | 先用 emoji/SVG 图标，后续可补充插画 |
| 图表库增加包体积 | 前端 chunk 增大 | 按需引入，懒加载图表组件 |
| OPS 阶段条与后端状态不同步 | 界面显示错误 | 严格映射 `gameState.phase` 到步骤条索引 |
| 色彩过多导致视觉混乱 | 各引擎风格不统一 | 每个引擎只使用 1 主色 + 1 辅色 + 全局功能色 |

## 8. 验收标准

### 8.1 功能性

- [ ] TechVenture 对战页显示数据仪表盘，提交后 KPI 卡和趋势图更新。
- [ ] OPS 对战页顶部阶段条与当前阶段一致，各阶段操作面板正确渲染。

### 8.2 视觉性

- [ ] TechVenture 与 OPS 对战页切换时，用户能在 2 秒内通过色彩和布局判断当前引擎。
- [ ] 主色调正确应用：TechVenture 紫、OPS 蓝。
- [ ] 移动端无布局崩坏，关键操作可完成。

### 8.3 性能

- [ ] 三个对战页首屏加载时间不超过当前版本 1.2 倍。
- [ ] 图表组件不阻塞主交互。
