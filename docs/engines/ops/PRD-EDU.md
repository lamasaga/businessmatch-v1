## 1. 文档定位

本文是 OPS 的教育用产品 PRD。它不替代现有 [PRD.md](./PRD.md) 中的经营赛主契约，而是在其基础上补充一套“边比赛边教学”的产品层设计。

现有 OPS 已能表达生产、定价、营销、研发、销售人员、城市市场、拍卖和财务报表等经营动作，但学生体验仍偏向“填数字、看结果、比排名”。教育版 OPS 的目标是让学生在比赛过程中持续显式思考：

```text
我为什么这样决策？
我预计会发生什么？
结果和预期哪里不同？
下一轮我该如何调整？
```

因此，教育版 OPS 的核心不是增加更多复杂变量，而是把每轮经营改造成一个清晰的学习闭环。

## 2. 产品定位

### 2.1 一句话玩法

OPS 教育版是一场以“经营一家小公司”为主线的课程化商业模拟：学生以团队形式完成产品定位、经营决策、资源选择和赛后复盘；系统在每轮要求学生写下目标、预测和理由，并在结算后给出可理解的原因解释，帮助学生把比赛结果转化为商业判断。

### 2.2 和标准 OPS 的区别

| 维度 | 标准 OPS | 教育版 OPS |
|------|----------|------------|
| 核心目标 | 自动结算经营比赛，形成排名 | 通过比赛训练经营思维和复盘能力 |
| 学生动作 | 填写经营决策并提交 | 先看情报、定目标、做预测、写理由，再提交 |
| 反馈方式 | 销量、利润、报表、排名 | 结果 + 原因解释 + 预测偏差 + 下一轮提示 |
| 教师角色 | 控场、推进、查看大屏 | 组织讨论、暂停讲评、点名复盘、评价学习过程 |
| 胜负方式 | 净资产和累计利润为主 | 经营表现 + 现金安全 + 库存管理 + 预测复盘 + 团队表达 |
| 低龄适配 | 需要教师自行降阶 | 内置 Junior 模式和低龄解释语言 |

### 2.3 目标受众

| 人群 | 推荐模式 | 说明 |
|------|----------|------|
| 12 岁左右学生 | Junior 模式 | 低复杂度、强引导、少术语 |
| 初中高年级 | Standard Edu 模式 | 保留核心经营变量，强调目标和复盘 |
| 高中商赛学生 | Advanced Edu 模式 | 增加拍卖、城市、研发、财务和战略解释 |
| 教师 / 营地导师 | Teacher Guide 模式 | 提供控场提示、讲评点和队伍复盘材料 |

## 3. 教育目标

OPS 教育版应服务以下学习目标：

| # | 学习目标 | 学生能做到什么 | 系统如何承载 |
|---|----------|----------------|--------------|
| 1 | 认识公司经营闭环 | 说清楚产品、顾客、成本、收入、利润和库存的关系 | 每轮小公司账本 / 财务报表 |
| 2 | 做有理由的经营决策 | 不只是填数字，而能说明为什么这样填 | 决策理由表单 |
| 3 | 形成预测意识 | 提交前预测销量、利润、库存和现金风险 | 决策前预测卡 |
| 4 | 理解资源约束 | 知道现金、产能、时间和资源都有限 | 预算进度、产能提示、资源卡/拍卖 |
| 5 | 学会从结果中调整 | 根据偏差决定下一轮改变什么 | 预测 vs 实际复盘 |
| 6 | 理解竞争影响 | 看到对手定价、营销、市场选择会改变自己结果 | 行业对比和竞争解释 |
| 7 | 训练团队协作 | 小队分角色讨论和提交 | 角色卡、公司会议、提交确认 |
| 8 | 训练商业表达 | 用数据解释自己的公司故事 | 经营日志和赛后报告 |

## 4. 设计原则

### 4.1 先体验，再抽象

教育版 OPS 不应先把学生扔进“价格弹性、市场份额模型、管理会计”等术语里。系统应该先让学生经历具体问题：

```text
货做多了，仓库剩很多。
价格定高了，顾客变少。
广告花多了，销量上去了，但利润被吃掉。
资源抢到了，但现金不安全。
```

然后教师再把这些体验转化为概念。

### 4.2 每轮必须有显式思考

每轮不能只要求提交经营数字。至少要让学生完成三件事：

```text
本轮目标是什么？
你预测会发生什么？
你为什么这样决策？
```

### 4.3 解释优先于公式

后端可以保留严谨公式，但学生端默认显示可理解解释。公式可放在“详情”或教师端。

### 4.4 复盘也是比赛的一部分

教育版 OPS 的胜负不能只看经营结果。能否解释自己的策略、承认预测偏差、提出下一轮改进，也应计入学习评价。

## 5. 核心学习闭环

每一轮经营应遵循如下流程：

```text
阶段说明
  ↓
经营情报
  ↓
本轮目标
  ↓
预测与风险
  ↓
经营决策
  ↓
团队确认
  ↓
结算结果
  ↓
原因解释
  ↓
预测偏差
  ↓
下一轮改进
```

### 5.1 阶段说明

系统告诉学生当前阶段要关注什么：

| 阶段 | 学生要理解的问题 |
|------|------------------|
| 产品定位 | 我们卖什么？卖给谁？ |
| R1 | 第一次试市场，先观察顾客反应 |
| R2 | 根据第一轮结果调整生产、价格和广告 |
| 拍卖/资源阶段 | 资源是否适合我们的公司，而不是看起来强就买 |
| R3-R4 | 放大优势，修正库存、现金和顾客问题 |
| 后半场 | 根据对手和市场变化做战略调整 |
| 最终复盘 | 用数据讲清楚公司经营故事 |

### 5.2 经营情报

学生每轮决策前应看到简化情报：

| 情报 | 内容 |
|------|------|
| 公司现状 | 现金、库存、上轮利润、顾客满意/产品力 |
| 市场提示 | 顾客偏好、城市/客群规模、上轮行业均价 |
| 风险提示 | 库存过高、现金紧张、价格偏离、缺货风险 |
| 对手概览 | 行业平均价格、领先队伍大致策略、市场竞争热度 |

### 5.3 本轮目标

提交前必须选择一个目标。

| 目标 key | 学生显示 | 适用场景 |
|----------|----------|----------|
| `grow_sales` | 冲销量 | 想扩大顾客数量和市场份额 |
| `protect_profit` | 保利润 | 想提高每单赚钱能力 |
| `clear_inventory` | 清库存 | 仓库剩货过多 |
| `save_cash` | 保现金 | 现金不足，下一轮选择受限 |
| `build_quality` | 提质量 | 希望后续更有竞争力 |
| `expand_market` | 扩市场 | 想进入新城市或新顾客群 |
| `defend_position` | 稳住排名 | 后半场减少冒险 |

### 5.4 预测与风险

学生至少完成以下预测：

| 字段 | 类型 | 示例 |
|------|------|------|
| `expected_sales_band` | enum | 低 / 中 / 高 |
| `expected_profit_direction` | enum | 赚钱 / 持平 / 亏损 |
| `expected_inventory_direction` | enum | 增加 / 差不多 / 减少 |
| `cash_risk` | enum | 安全 / 有点紧 / 危险 |
| `main_risk` | enum | 价格太高 / 做太多 / 做太少 / 广告无效 / 现金不足 / 对手太强 |

Junior 模式可以只保留前三项。

### 5.5 决策理由

每个关键变量旁边都应有一个轻量理由选择。

| 决策 | 理由示例 |
|------|----------|
| 生产量 | 预计需求高 / 想清库存 / 避免缺货 / 控制库存 |
| 价格 | 想提高利润 / 想吸引更多顾客 / 对手太便宜 / 产品质量更好 |
| 广告 | 让更多顾客知道 / 进入新市场 / 抢回份额 / 本轮不重点投入 |
| 研发/质量 | 提高产品力 / 服务目标客群 / 为后半场准备 / 现金不够暂缓 |
| 销售人员/城市 | 扩市场 / 提升触达 / 控制成本 / 深耕已有市场 |

### 5.6 结算解释

结算后系统应生成 3 到 5 条解释卡：

| 类型 | 示例文案 |
|------|----------|
| 价格 | 你的价格高于行业平均，顾客减少，但单件毛利更高 |
| 生产 | 本轮实际需求高于可销售数量，出现缺货，错过了一部分订单 |
| 库存 | 本轮生产多于销量，库存增加，并带来保管成本 |
| 广告 | 广告提高了展示度，但费用较高，压低了净利润 |
| 研发 | 研发让产品力提升，本轮利润下降，但后续竞争力变强 |
| 城市 | 新市场开拓产生开城费，短期拖累现金 |
| 竞争 | 多支队伍进入同一市场，份额被分散 |

### 5.7 预测偏差

系统比较学生预测与实际结果：

| 对比 | 输出 |
|------|------|
| 预计销量 vs 实际销量 | 判断预测偏高/偏低 |
| 预计盈利方向 vs 实际净利润 | 判断利润判断是否准确 |
| 预计库存方向 vs 实际库存 | 判断生产预测是否准确 |
| 现金风险 vs 实际现金 | 判断预算意识是否准确 |

系统不应只告诉学生“错了”，而应给出下一轮提示：

```text
你们高估了销量。下一轮可以考虑降低生产量、加强广告，或调整价格。
```

## 6. 赛制结构

### 6.1 Junior 模式

面向 12 岁左右学生。

| 项 | 设计 |
|----|------|
| 回合 | 3-4 轮经营 |
| 决策 | 生产数量、价格档位、广告投入 |
| 顾客 | 实用型、潮流型、科技型 |
| 资源 | 固定价格资源卡，不默认使用竞价拍卖 |
| 报表 | 小公司账本 |
| 反馈 | 解释卡 + 预测偏差 |
| 胜负 | 健康公司评分 |

### 6.2 Standard Edu 模式

面向初中高年级和商赛入门。

| 项 | 设计 |
|----|------|
| 回合 | 4-6 轮经营 |
| 决策 | 生产、价格、营销、研发、销售人员、目标城市 |
| 资源 | 一次资源卡/拍卖 |
| 报表 | 简化财务报表 + 小公司账本 |
| 反馈 | 解释卡、预测偏差、行业对比 |
| 胜负 | 经营结果 + 复盘质量 |

### 6.3 Advanced Edu 模式

面向高中商赛和进阶训练营。

| 项 | 设计 |
|----|------|
| 回合 | 6 轮经营 |
| 决策 | 完整 OPS 决策 |
| 资源 | 拍卖 A + 拍卖 B |
| 报表 | 损益表、资产表、趋势图、城市明细 |
| 反馈 | 解释卡、竞争拆解、资源 ROI、策略一致性 |
| 胜负 | 标准排名 + 策略报告 + 教师评价 |

## 7. 产品功能需求

### 7.1 学生端：阶段学习卡

每个阶段顶部展示一张学习卡。

| 字段 | 示例 |
|------|------|
| 阶段问题 | 这一轮你最想解决什么经营问题？ |
| 教学提示 | 不要只看销量，注意库存和现金 |
| 关键指标 | 现金、库存、上轮利润、顾客反馈 |
| 教师提示开关 | 教师可选择是否显示更强提示 |

### 7.2 学生端：经营情报面板

决策前展示：

| 模块 | 内容 |
|------|------|
| 我的公司 | 现金、库存、产品力、上轮利润 |
| 市场情况 | 目标顾客偏好、市场规模、行业均价 |
| 上轮提醒 | 上轮最大的一个问题 |
| 本轮风险 | 现金、库存、缺货、价格、竞争 |

### 7.3 学生端：显式思考表单

运营决策表单前增加：

```json
{
  "round_goal": "clear_inventory",
  "expected_sales_band": "medium",
  "expected_profit_direction": "profit",
  "expected_inventory_direction": "down",
  "cash_risk": "safe",
  "main_risk": "price_too_high",
  "decision_reason": "上轮库存过高，所以本轮降低生产并提高广告。"
}
```

Junior 模式中 `decision_reason` 可改为结构化选项，不要求长文本。

### 7.4 学生端：提交前确认

提交按钮前应显示一张“团队确认卡”：

| 检查项 | 示例 |
|--------|------|
| 现金是否足够 | 本轮后预计剩余现金 ¥X |
| 生产是否过量 | 计划生产 X 件，上轮销量 Y 件 |
| 目标是否一致 | 本轮目标是清库存，但生产量仍高 |
| 风险提示 | 你们使用了 92% 现金，下一轮可能受限 |

系统不强制阻止冒险，但要让学生看见自己正在冒险。

### 7.5 学生端：结算解释卡

结算页新增解释卡列表：

```json
{
  "explanation_cards": [
    {
      "kind": "inventory",
      "severity": "warning",
      "title": "库存增加",
      "body": "本轮生产 400 件，实际销售 230 件，仓库剩余 170 件。",
      "next_hint": "下轮可以减少生产或增加广告。"
    }
  ]
}
```

### 7.6 学生端：预测偏差卡

结算页新增预测结果：

| 项 | 展示 |
|----|------|
| 销量预测 | 你预测中等，实际偏低 |
| 盈利预测 | 你预测赚钱，实际亏损 |
| 库存预测 | 你预测减少，实际增加 |
| 现金风险 | 你预测安全，实际偏紧 |

### 7.7 学生端：下一轮改进

每轮结算后，进入下一轮前必须完成一条复盘：

```json
{
  "reflection": {
    "biggest_surprise": "销量比预期低",
    "main_reason": "价格太高",
    "next_adjustment": "降低价格并减少生产"
  }
}
```

Junior 模式可以用三道选择题。

### 7.8 学生端：经营日志

系统自动沉淀每轮日志：

```text
R1 目标：冲销量
预测：销量高、赚钱、库存减少
决策：生产 300、价格 120、广告 5000
结果：销量 180、亏损 2000、库存增加
解释：价格偏高、广告不足、生产过量
复盘：下轮降低价格并减少生产
```

最终用于生成团队报告。

### 7.9 教师端：讲评仪表盘

教师端应新增教学视角：

| 模块 | 教师看到什么 |
|------|--------------|
| 提交进度 | 哪些队伍完成了目标/预测/决策 |
| 风险队伍 | 现金危险、库存过高、连续亏损 |
| 教学案例 | 最典型的价格战、库存积压、拍卖过价 |
| 预测偏差 | 哪些队伍判断偏差最大 |
| 复盘质量 | 哪些队伍复盘具体、有证据 |

### 7.10 教师端：暂停讲评点

教师可在阶段间触发讲评：

| 讲评点 | 建议问题 |
|--------|----------|
| R1 后 | 哪些队伍卖得多但没赚钱？ |
| 拍卖前 | 这件资源对你们值多少钱？ |
| 拍卖后 | 有没有队伍花了太多钱？ |
| R3 后 | 哪些队伍需要改变策略？ |
| 赛后 | 你们最大一次判断偏差是什么？ |

## 8. 数据需求

### 8.1 决策提交扩展

现有运营决策 payload：

```json
{
  "production_quantity": 200,
  "unit_price": 180,
  "marketing_spend": 8000,
  "rnd_spend": 5000,
  "sales_force": 3,
  "target_cities": ["hangzhou", "nanjing"]
}
```

教育版建议扩展为：

```json
{
  "production_quantity": 200,
  "unit_price": 180,
  "marketing_spend": 8000,
  "rnd_spend": 5000,
  "sales_force": 3,
  "target_cities": ["hangzhou", "nanjing"],
  "learning": {
    "round_goal": "grow_sales",
    "expected_sales_band": "high",
    "expected_profit_direction": "profit",
    "expected_inventory_direction": "down",
    "cash_risk": "safe",
    "main_risk": "competitor_pressure",
    "reason_tags": ["price_competition", "new_city_growth"],
    "reason_note": "我们进入新城市并降低价格，希望先获得顾客。"
  }
}
```

为了兼容标准 OPS，`learning` 字段可选。标准赛可不启用，教育版配置要求启用。

### 8.2 结算快照扩展

现有 snapshot 已包含 `result` 和 `financial_statements`。教育版建议扩展：

```json
{
  "learning_result": {
    "prediction_accuracy": {
      "sales": "overestimated",
      "profit": "wrong_direction",
      "inventory": "wrong_direction",
      "cash": "accurate"
    },
    "explanation_cards": [],
    "next_round_hints": [],
    "teacher_case_tags": ["inventory_pressure", "price_too_high"]
  }
}
```

### 8.3 复盘提交

新增或复用阶段推进前的复盘结构：

```json
{
  "round_id": 12,
  "biggest_surprise": "sales_lower_than_expected",
  "main_reason": "price_too_high",
  "next_adjustment": "lower_price_reduce_production",
  "note": "我们本来以为广告足够，但价格比其他队高太多。"
}
```

### 8.4 教师端大屏扩展

`/screen` 或教育版 screen payload 建议增加：

```json
{
  "learning_summary": {
    "submitted_learning_count": 8,
    "high_cash_risk_teams": [],
    "high_inventory_teams": [],
    "prediction_gap_cases": [],
    "teacher_case_cards": []
  }
}
```

## 9. 评分与评价

教育版 OPS 建议使用双轨评分。

### 9.1 经营分

| 维度 | 建议权重 |
|------|----------|
| 净资产 | 35% |
| 累计利润 | 25% |

education_mode:

## 11. 页面结构

### 11.1 学生端工作台

建议学生端由五个区组成：

| 区域 | 内容 |
|------|------|
| 顶部状态 | 阶段、倒计时、现金、库存、排名 |
| 左侧流程 | 当前轮步骤：情报、目标、预测、决策、提交 |
| 中央操作 | 当前步骤主任务 |
| 右侧提示 | 教师提示、风险提醒、上轮问题 |
| 底部行动 | 保存草稿、提交、进入复盘、下一轮 |

### 11.2 决策页步骤化

当前决策表单应拆成步骤：

```text
1. 看上轮结果
2. 选择本轮目标
3. 做预测
4. 填经营数字
5. 说明理由
6. 团队确认并提交
```

### 11.3 结算页步骤化

结算页应拆成：

```text
1. 本轮结果
2. 为什么会这样
3. 预测哪里偏了
4. 我们下轮怎么改
5. 查看详细报表
```

## 12. 教师工作流

### 12.1 课前

教师选择：

| 配置 | 示例 |
|------|------|
| 教育模式 | Junior / Standard / Advanced |
| 主题包 | 校园新品、智能台灯、饮品小店 |
| 回合数 | 3 / 4 / 6 |
| 是否启用拍卖 | 资源商店 / 单次拍卖 / 双拍卖 |
| 是否要求复盘 | 每轮必填 / 赛后必填 / 不强制 |
| 评分方式 | 经营优先 / 学习均衡 / 低龄健康公司 |

### 12.2 课中

教师按照系统提示组织：

```text
阶段讲解
→ 学生填写目标和预测
→ 学生提交经营决策
→ 教师推进结算
→ 系统展示典型案例
→ 教师暂停 3-5 分钟讲评
→ 学生填写复盘
→ 下一轮
```

### 12.3 课后

系统导出：

| 产出 | 用途 |
|------|------|
| 团队经营日志 | 学生复盘 |
| 教师讲评摘要 | 课堂总结 |
| 预测偏差统计 | 判断能力训练 |
| 经营结果排行榜 | 比赛激励 |
| 学习分评分表 | 教学评价 |

## 13. 验收标准

### 13.1 学生显式思考

| 编号 | 验收 |
|------|------|
| EDU-1 | 教育模式开启时，运营决策提交前必须选择本轮目标 |
| EDU-2 | 教育模式开启时，运营决策提交前必须完成至少三项预测 |
| EDU-3 | 教育模式开启时，提交 payload 能保存 `learning` 字段 |
| EDU-4 | 已提交后，学生能看到自己的目标、预测和理由摘要 |

### 13.2 结算解释

| 编号 | 验收 |
|------|------|
| EDU-5 | 每轮结算后生成至少 3 条解释卡 |
| EDU-6 | 解释卡能覆盖价格、生产、库存、现金、营销、研发、竞争中的至少一种 |
| EDU-7 | 结算后显示预测与实际的差异 |
| EDU-8 | 系统给出下一轮改进提示 |

### 13.3 复盘闭环

| 编号 | 验收 |
|------|------|
| EDU-9 | 教育模式可配置“进入下一轮前必须复盘” |
| EDU-10 | 复盘内容进入经营日志 |
| EDU-11 | 赛后能按队伍导出完整经营日志 |
| EDU-12 | 学生端最终页能展示本队关键决策、偏差和改进轨迹 |

### 13.4 教师控场

| 编号 | 验收 |
|------|------|
| EDU-13 | 教师端能看到各队目标/预测/复盘提交状态 |
| EDU-14 | 教师端能看到风险队伍和典型案例 |
| EDU-15 | 教师可在阶段间开启讲评提示 |
| EDU-16 | 大屏/控场 payload 缺省时仍返回稳定数组字段 |

### 13.5 Junior 模式

| 编号 | 验收 |
|------|------|
| EDU-17 | Junior 模式能隐藏研发、销售人员、复杂城市等高级字段 |

## 14. P0 / P1 / P2 范围

### 14.1 P0：最小教育闭环

| 能力 | 说明 |
|------|------|
| 本轮目标 | 结构化选择 |
| 简单预测 | 销量、利润、库存、现金 |
| 决策理由 | 标签 + 可选短文本 |
| 解释卡 | 基于现有 result 生成规则解释 |
| 预测偏差 | 预测和实际方向对比 |
| 经营日志 | 每轮沉淀目标、预测、决策、结果、复盘 |

P0 不要求改变核心结算公式，不要求 LLM，不要求新复杂玩法。

### 14.2 P1：教师讲评与模式化配置

| 能力 | 说明 |
|------|------|
| 教师讲评仪表盘 | 风险队伍、典型案例、预测偏差 |
| Junior / Standard / Advanced | 决策字段和解释层不同 |
| 资源卡商店 | Junior 模式替代拍卖 |
| 赛后报告 | 自动生成团队经营报告 |
| 学习分 | 复盘质量和目标一致性进入评分 |

### 14.3 P2：高级教学扩展

| 能力 | 说明 |
|------|------|
| 策略一致性评分 | 判断目标、理由和决策是否一致 |
| 情境事件课 | 原材料涨价、需求冲击、政策补贴 |
| 队伍间谈判 | 合同、合作、渠道置换 |
| 路演/答辩外围 | 不进入 OPS 主结算，可作为 assignment |
| AI 助教讲评 | Phase C+，基于经营日志做自然语言点评 |

## 16. 一句话总结

教育版 OPS 的关键不是让学生多填几个字段，而是让系统每一轮都推动学生完成一次经营思考：

```text
定目标，做预测，说理由，看结果，找偏差，改策略。
```

当这个闭环成立时，OPS 才真正从“经营比赛”升级为“公司管理教学项目”。
