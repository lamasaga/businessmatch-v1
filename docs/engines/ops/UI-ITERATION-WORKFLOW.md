# OPS Edu UI 快速讨论与实现迭代流程

> **适用范围**：OPS 教育版学生端、教师端、投屏端的界面优化与原型讨论
> **最后更新**：2026-07-07

---

## 一、核心思路

OPS Edu 的 UI 迭代不应从“画一个更好看的页面”开始，而应从“这一步比赛想让学生显式思考什么”开始。每个界面优化都要同时回答三个问题：学生现在要做什么决策、他需要看到哪些信息才能做出决策、系统如何在结算前后引导他解释自己的判断。

因此，推荐采用“教学目标 -> 决策动作 -> 反馈证据 -> 界面承载”的顺序推进。这样 UI 不是单纯的视觉包装，而是课程、比赛和引导机制的共同载体。

## 二、四层迭代节奏

| 层级 | 目标 | 时间 | 产出 | 什么时候使用 |
|---|---|---:|---|---|
| L0 讨论卡 | 快速对齐问题边界 | 5-10 分钟 | 一张文字版 UI Brief | 任何新页面、新流程、新组件开始前 |
| L1 低保真结构 | 对齐信息架构和操作顺序 | 10-20 分钟 | 文本线框或 Mermaid 流程 | 还没确定页面结构时 |
| L2 静态视觉稿 | 快速判断观感、密度和教学引导 | 30-60 分钟 | SVG/PNG 单页 mockup | 需要你快速反馈“方向对不对”时 |
| L3 可运行切片 | 验证真实交互和工程可行性 | 1-3 小时 | 独立页面、组件或临时预览路由 | 页面结构已基本确定，需要进入实现前 |
| L4 正式落地 | 进入产品代码和验收 | 按范围评估 | 前端实现、接口联调、测试记录 | 方案已确认，需要交付到主应用 |

## 三、每次讨论先填 L0 UI Brief

每次 UI 优化先用下面这张短卡片对齐，不直接进入画图或写代码。

| 字段 | 要回答的问题 | 示例 |
|---|---|---|
| 场景 | 学生/教师在比赛的哪个时刻使用？ | 第 2 轮运营决策提交前 |
| 教学目标 | 这一屏要训练什么商业思维？ | 理解价格、广告、库存之间的取舍 |
| 学生动作 | 学生必须显式做出什么选择？ | 预测销量、设置价格、分配广告预算 |
| 所需信息 | 学生做判断前必须看到什么？ | 上轮库存、市场需求、竞品均价、现金余额 |
| 系统反馈 | 提交前/结算后要反馈什么？ | 预计利润、缺货风险、实际偏差原因 |
| 教师介入 | 教师是否需要暂停、提示或投屏讲评？ | 可一键展示“为什么高价没卖掉” |
| 成功标准 | 怎么判断这一版 UI 有效？ | 12 岁学生能说出自己的经营理由 |

这张卡片的价值在于压缩讨论成本。只要卡片没对齐，就先不纠结按钮颜色、卡片圆角和视觉细节。

## 四、从讨论到实现的推荐流程

### Step 1：确认页面类型

先判断当前 UI 属于哪一类，不同页面有不同的设计重点。

| 页面类型 | 设计重点 | OPS 示例 |
|---|---|---|
| 情报页 | 信息可信、少而关键、能形成判断 | 市场需求、竞品价格、新闻事件 |
| 决策页 | 操作明确、预算约束明显、后果可预测 | 价格、产量、广告、质量投入 |
| 预测页 | 让学生先表达假设 | 预计销量、预计利润、风险判断 |
| 结算页 | 解释因果，而不只是公布排名 | 为什么库存积压、为什么利润下降 |
| 复盘页 | 把比赛经验翻译成课程知识 | 成本、需求、竞争、现金流 |
| 教师页 | 控场、暂停、提问、投屏 | 本轮关键问题、班级风险分布 |

### Step 2：先做文字线框

在进入视觉稿前，先用文字描述布局。推荐格式如下：

```text
顶部：比赛名 / 当前轮次 / 倒计时 / 提交状态
左侧：本轮步骤条，标出当前处于“预测 -> 决策 -> 提交”
中间上方：经营情报，最多 4 个关键指标
中间主体：决策表单，按“产量、价格、营销、质量”分组
右侧：教学引导，包含本轮问题、风险提醒、上轮解释卡
底部：团队确认、提交按钮、教师提示状态
```

文字线框通过后，再进入静态视觉稿，能避免来回重画。

### Step 3：用 SVG 快速出一版视觉方向

静态 SVG 适合快速讨论页面密度、视觉层级、信息分区和按钮状态。它不依赖前端工程，也不会污染业务代码。适合在 30-60 分钟内给出一版“能看见的方向”。

当前已生成的 OPS Edu 工作台参考稿放在：

- [ui-mockups/ops-edu-workbench.svg](./ui-mockups/ops-edu-workbench.svg)

SVG 原型的反馈建议只讨论四类问题：

| 类型 | 反馈方式 |
|---|---|
| 保留 | 哪些区域、布局、视觉感觉可以保留 |
| 修改 | 哪些内容顺序、密度、颜色、文案需要调整 |
| 增加 | 缺少什么教学提示、经营指标或交互状态 |
| 删除 | 哪些信息会干扰 12 岁学生理解 |

### Step 4：进入可运行切片

静态稿方向确认后，再做可运行切片。切片不一定直接接入完整业务流程，可以先实现为一个独立组件、临时页面或 Storybook 类预览。

可运行切片必须验证：

| 验证点 | 要看什么 |
|---|---|
| 真实数据密度 | 字段变长、数字变化、队名变化是否撑破布局 |
| 交互状态 | 默认、悬停、禁用、已提交、错误、超时 |
| 移动/投屏适配 | 学生电脑、平板、教师大屏是否可读 |
| 教学提示 | 提示是否真的帮助学生思考，而不是变成说明书 |
| 工程边界 | 是否符合学生端/组织者端分离和 OPS 引擎边界 |

### Step 5：正式实现与验收

进入正式实现后，每次 UI 改动都要给出三类验收结果：

| 验收项 | 说明 |
|---|---|
| 视觉验收 | 桌面端、窄屏端截图；无遮挡、无溢出、按钮清晰 |
| 教学验收 | 学生是否能说出“我为什么这样决策” |
| 工程验收 | lint/build/test 或最小可行检查通过 |

## 五、OPS Edu 的固定页面清单

建议先围绕下面五个核心页面迭代，不急着铺开所有边角功能。

| 优先级 | 页面 | 学生/教师要完成的事情 | 第一版必须有 |
|---|---|---|---|
| P0 | 学生运营决策工作台 | 看情报、做预测、提交经营决策 | 情报卡、预测框、决策控件、风险提示 |
| P0 | 结算解释页 | 理解本轮结果与自己选择的关系 | 结果对比、偏差解释、下一轮建议 |
| P0 | 教师控场页 | 暂停、提示、观察全班进度 | 队伍状态、未提交名单、广播提示 |
| P1 | 投屏讲评页 | 用一屏讲清商业规律 | 班级分布、典型案例、讨论问题 |
| P1 | 赛后复盘页 | 把比赛映射到课程知识 | 决策轨迹、关键概念、反思问题 |

## 六、面向 12 岁学生的 UI 原则

| 原则 | 操作标准 |
|---|---|
| 一屏一个主任务 | 不在同一屏同时要求学生完成太多经营动作 |
| 先预测再提交 | 让学生先说出判断，再看到结果 |
| 数字必须有解释 | 不只显示“毛利率 18%”，还要说明“每卖 100 元大约赚 18 元” |
| 风险要显性化 | 缺货、现金不足、库存积压要用清晰状态提示 |
| 反馈要讲因果 | 不只说“输了”，要说明价格、需求、成本和竞争如何影响结果 |
| 教师可介入 | 每个关键节点都要有暂停、提示和投屏讲评空间 |

## 七、UI 反馈记录格式

每次你给反馈时，建议直接按这个格式写，方便我快速进入下一轮。

```text
页面：学生运营决策工作台
保留：左侧步骤条、中间决策区
修改：右侧教学提示太多，改成 3 条以内
增加：提交前显示“预计现金余额”
删除：暂时不要显示复杂毛利率公式
优先级：先做静态稿第二版，不进代码
```

如果要进入实现，则加上：

```text
实现范围：只做学生端 OpsPlayPage，不改教师端
验收方式：给我桌面截图和移动端截图
禁止：不改后端接口
```

## 八、与优秀实践的对应关系

这套流程参考了几类成熟做法，但转译成更适合商业模拟赛和低龄教学的版本。

| 外部实践 | 可借鉴点 | 在 OPS Edu 中的转译 |
|---|---|---|
| Simulation prebriefing | 先说明目标、规则和心理安全边界 | 每轮开始前明确“本轮要训练什么经营判断” |
| Embedded scaffolding | 在任务中嵌入提示、约束和分步引导 | 步骤条、预测框、风险提示、提交前检查 |
| Timely feedback | 反馈要及时、具体、和学生动作相关 | 结算页解释“你的价格/广告/产量带来了什么结果” |
| Structured debriefing | 复盘不是闲聊，而是把体验连接到概念 | 赛后把库存、现金流、竞争、需求讲回课程 |
| Business planning basics | 市场、成本、营销、运营、财务是入门主线 | OPS 的情报、预算、价格、生产、广告、利润 |

可参考来源：

- Harvard Business Publishing: [Leading an Effective Simulation Debrief](https://hbsp.harvard.edu/inspiring-minds/leading-effective-simulation-debrief-discussions)
- INACSL Standards: [Healthcare Simulation Standards of Best Practice](https://www.inacsl.org/healthcare-simulation-standards-of-best-practice-)
- SBA: [Business Guide](https://www.sba.gov/business-guide)
- SpringerOpen: [Scaffolding and feedback in simulation-based learning](https://link.springer.com/article/10.1186/s40594-024-00490-7)

## 九、推荐的下一步

建议下一轮不要直接做完整前端，而是先走一次完整小循环：

1. 用 L0 UI Brief 确认“学生运营决策工作台”的教学目标。
2. 基于当前 SVG 做第二版，重点压低信息复杂度，让 12 岁学生更容易读懂。
3. 你确认方向后，再做一个可运行切片，只实现学生端核心决策区。
4. 用截图和操作录屏验收，再决定是否接入真实 OPS 数据。
