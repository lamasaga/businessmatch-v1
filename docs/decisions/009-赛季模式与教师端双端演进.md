# ADR-009: 赛季模式与教师端双端演进

**日期**：2026-05-29  
**状态**：部分采纳（营团 P1 已落地；赛季/AOTU 仍草案）  
**触发**：M1（双端定位选型）· M3（`match_kind` 扩展规划）

---

## 上下文

　　原「组织者端」仅覆盖建赛、房间码、控场，与课堂教学场景脱节。主理人提出：教师端应升级为**课程实施端**，并以**赛季（Season）**作为一次完整教学活动容器，汇入 Career 生涯主线。

---

## 决策

1. **双端重定义**：教师端（Course Terminal）↔ 学生端（Student Terminal）；`organizer-frontend` 渐进演进而非另起第二后端。
2. **引入赛季模式**：营团（Group）→ 赛季（Season）→ 里程碑活动 → T2 班级收官赛 → `SettlementBundle` 汇入 Career。
3. **`match_kind` 产品分轨**（Phase B+ 落地）：`practice` | `official_t2` | `official_t1`；**Phase A 代码仍保持** `practice` | `official`，迁移时 `official` → `official_t2`。
4. **AOTU**：模板 + 规则为主，LLM 仅措辞增强（MVP）。

---

## 考虑过的方案

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| 维持纯「组织者控场」 | 与现网一致 | 无法承载课程叙事 | 否决 |
| 独立教师 App + 第二 API | 边界清晰 | 违反 ADR-002 单库单进程 | 否决 |
| **教师端 + 赛季 + 共用 Arena（已采纳）** | 竖切可演进 | 术语与枚举迁移成本 | 采纳 |
