# ADR-006: 学生端与组织者端双前端

**日期**：2026-05-21  
**状态**：已采纳  
**触发**：M3

---

## 上下文

　　**学生**与**组织者/教师**的页面结构、权限、路由差异大（例如控场、大屏、评委打分）。若塞进一个 React 应用的同一路由树，易出现权限漏洞、包体积膨胀、学生端误暴露控场入口。

---

## 决策

　　**两个独立 Vite 前端工程**，共用**同一后端 API**：

| 端 | 目录 | 默认端口 | 受众 |
|----|------|----------|------|
| 学生端 | `webapp/frontend/` | 5173 | 参赛、练习、生涯 |
| 组织者端 | `webapp/organizer-frontend/` | 5174 | 建赛、控场、TechVenture 组织/大屏 |

　　学生端**禁止**包含组织者控场页面；组织者能力通过 JWT 角色与 `organizer_id` 等字段由后端校验。

**落地位置**：

- `docker-compose.yml` 三服务：backend + frontend + organizer-frontend
- 文档：`02-` §五双端、`09-` 竖切流程

---

## 考虑过的方案

| 方案 | 优点 | 缺点 | 未采用原因 |
|------|------|------|------------|
| 单前端 + 角色路由 | 一份依赖 | 路由/组件混杂；易漏权限 | 已明确禁止 |
| 组织者独立后端（见 ADR-002） | — | 数据不同步 | 与单库决策冲突 |
| **双前端 + 单后端（已采纳）** | 边界清晰；可独立部署静态资源 | 类型/接口要同步 | 当前仓库结构 |

---

## 后果

### 正面

- 组织者 UI 迭代不影响学生 bundle
- `08-` 可分开列路由与功能矩阵

### 负面 / 代价

- API 类型或 OpenAPI 契约变更时需**两端**跟进（`contracts/` 待建）

### 给初学者的操作提示

- **可以做的**：改学生页只动 `frontend/`；改等待区/控场只动 `organizer-frontend/`
- **不要做的**：在学生端 `App.tsx` 加 `/organizer/control`；为组织者起第二个 FastAPI
- **相关阅读**：ADR-002、`08-` §2.6（学生路由）、组织者路由在 organizer 工程内
