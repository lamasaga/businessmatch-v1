# ADR-007: 生涯经验幂等账本

**日期**：2026-05-21  
**状态**：已采纳  
**触发**：M3、M5

---

## 上下文

　　比赛结束后要给用户加经验（XP）。若在 `games/trading` 结算里直接 `user.experience += n`，会出现：重复结算、练习/正式赛重复触发、并发请求双加，且 **career 域**无法审计「为何加了这笔 XP」。

---

## 决策

　　**career 域**拥有 XP 账本表 `xp_events`：

- 每笔发放一条事件记录，带 **`idempotency_key`**（同一 key 只入账一次）
- 赛后统一走 **`settle_match_rewards`**（或 `grant_xp`）入口，**禁止**他域直接改 `users` 上的经验字段

**落地位置**：

- `webapp/backend/app/domains/career/`
- 调用点：正式赛结束等（见 `03-ENGINEERING.md` §功能矩阵 / P0 Bug）
- 规则：`blueprint-coding.mdc` §1 career 行、§5 幂等写入

---

## 考虑过的方案

| 方案 | 优点 | 缺点 | 未采用原因 |
|------|------|------|------------|
| `users.experience` 原地加减 | 查询简单 | 无审计；难幂等 | 不符合生涯闭环设计 |
| 每场赛在 trading 表记「已发 XP」标志 | 部分防重 | 逻辑散落在各赛制 | career 域无法统一规则 |
| **`xp_events` 账本 + 幂等键（已采纳）** | 可回放；跨赛制统一 | 多一张表、多一次调用 | 已用于正式赛结束 |

---

## 后果

### 正面

- Phase B 可扩展 Quest、赛季榜而不改 trading 引擎
- 前端生涯页将来只读 API 聚合 `xp_events`

### 负面 / 代价

- 初学者容易图省事在结算里改 `user` — Code Review 须拦

### 给初学者的操作提示

- **可以做的**：在赛制结算**末尾**调用 `settle_match_rewards(event_id=…)`（参数以实际函数为准）
- **不要做的**：`current_user.experience += 10`；在 trading 里 `UPDATE users SET experience=…`
