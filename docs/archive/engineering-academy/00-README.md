# 赛事引擎工程学堂（Engineering Academy）

> 本文档面向：使用 AI 辅助编程、但对技术细节缺乏系统认知的设计者 / 策划者。
> 目标：让你在继续扩展 `arena` / `games/` / `content/` 时，能看懂代码在做什么、能与 AI 用同一套语言沟通、能判断一个需求落在哪里一层。

## 为什么需要这个文件夹

商识唯智平台把「比赛流程」和「游戏规则」拆成了两层：

- **Arena**：管报名、房间、回合推进、结算、分数、奖励（生命周期）。
- **Engine**：管 YAML 规则、经济公式、实时/回合制决策、AI 玩家（玩法内核）。

后续我们还要扩展 TechVenture、更多实时赛制、 possibly 3D / 可视化回放。每个方向都涉及前端、后端、美术、网络同步、服务器部署。作为设计者，你不需要亲手写每一行代码，但需要知道：

1. 这个概念在代码里长什么样；
2. 找 AI 实现时该用什么关键词；
3. 改这里会牵动哪些地方；
4. 美术资产规格如何与程序对接。

本文件夹就是为此准备的「翻译字典 + 学习路线图」。

## 推荐阅读顺序

1. 先读 `01-赛事引擎技术总览.md`，建立整体地图。
2. 根据你当前任务跳到对应模块：
   - 要做新界面 / 换皮 → `10-美术资产/`
   - 要做实时对战 / 多人同屏 → `20-网络对战服务器/`
   - 要新增后端逻辑 / 字段 / 奖励 → `30-服务器基础知识/`
   - 不确定怎么跟 AI 沟通时 → `40-AI辅助设计者指南/`
   - 要修改/扩展具体引擎 → `50-赛事引擎指南/`
   - 要设计/改进 AI 对手、导师、LLM 增强 → `60-游戏AI设计/`
   - 要学习 POP、社会模拟、宏观经济推演理论 → `70-POP机制与社会模拟/`
   - 要直接落地一个 POP-拟真城市引擎 → `80-POP拟真城市/`
   - 要设计 LLM + 状态机的商业生涯/NPC 剧情 → `90-LLM商业生涯与NPC剧情系统/`

## 与代码的对应关系

| 概念 | 代码位置 |
|------|---------|
| 赛事生命周期、房间、报名 | `webapp/backend/app/domains/arena/` |
| 回合制 / 实时制结算内核 | `webapp/backend/app/games/` |
| 规则配置 | `webapp/backend/content/game-configs/*.yaml` |
| 后端路由入口 | `webapp/backend/app/main.py` |
| 学生端 | `webapp/frontend/` |
| 组织者端 | `webapp/organizer-frontend/` |

## 重要原则

- **不以 `inspire/` 作为实现依据**：`inspire/` 是愿景，落到代码前要与 `03-ENGINEERING.md` 和 Phase 门控对齐。
- **Phase A 范围**：当前阶段可以扩展 TechVenture 引擎、回合制策略、RTS 调度器，但不能新建 `domains/world/` 表或跨比赛持久城市状态。
- **硬域边界**：Arena 不写 Engine 的表，Engine 不写 Arena 的表；通过 API / 事件通信。
