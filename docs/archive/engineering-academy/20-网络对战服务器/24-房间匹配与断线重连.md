# 房间匹配与断线重连

> 一场比赛需要一个「房间」把玩家关在一起。本文讲房间的概念、匹配逻辑，以及玩家掉线后怎么办。

## 1. 房间（Room/Match）

房间是一场比赛的容器：

- 有唯一 ID
- 包含参赛玩家
- 有自己的状态（等待中、进行中、已结束）
- 状态只对房间内玩家可见

## 2. 房间状态机

```
等待中（waiting）
  ↓ 人满或房主开始
进行中（running）
  ↓ 比赛结束
结算中（settling）
  ↓ 奖励发放完成
已结束（finished）
```

## 3. 匹配方式

| 方式 | 说明 | 适用 |
|------|------|------|
| 房间码 | 玩家输入房间码加入 | 课堂、夏令营 |
| 好友邀请 | 发送链接 / 邀请码 | 社交场景 |
| 自动匹配 | 系统按水平匹配 | 排位赛 |
| 练习赛 | 玩家+AI 即可开始 | 单人训练 |

当前项目 Phase A 主要支持房间码和练习赛。

## 4. 断线重连

玩家可能网络不稳定，需要支持重连：

- 服务器保留玩家在比赛中的身份
- 重连后恢复当前状态
- 如果比赛还在进行，让玩家继续
- 如果比赛已结束，显示结果

实现要点：

- 玩家 ID 与 WebSocket 连接分离
- 连接断开后不要立即踢出
- 设置一个宽限期（如 30 秒）
- 重连时发送完整状态快照

## 5. 重连补偿

如果玩家错过了几个 tick 的状态更新，重连后需要补发：

- 发送当前完整状态快照
- 或发送缺失 tick 的历史记录

对于商业模拟，通常直接发完整快照更简单可靠。

## 6. 与 AI 沟通示例

```
我要为练习赛增加断线重连。
需求：
- 玩家断开 WebSocket 后保留座位 60 秒
- 60 秒内重连恢复同一身份
- 重连后发送当前完整状态
- 超时后判定为弃权，由 AI 接管
请修改 arena 房间管理和 WebSocket 处理。
```
