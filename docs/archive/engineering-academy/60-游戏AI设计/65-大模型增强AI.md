# 大模型增强 AI

> 大语言模型（LLM）为游戏 AI 带来了新的可能性，但也带来了新的风险。本章讲如何在可控范围内引入 LLM。

## 1. LLM 能做什么

| 能力 | 游戏应用 |
|------|---------|
| 文本生成 | NPC 对话、新闻、赛后点评、任务描述 |
| 推理 | 策略建议、决策解释、玩家问题回答 |
| 角色扮演 | 有性格的 NPC、导师、对手 |
| 内容生成 | 随机事件、剧情分支、题目 |
| 摘要 | 对局复盘、学习报告 |

## 2. LLM 不能做什么

| 局限 | 说明 |
|------|------|
| 不可预测 | 相同输入可能输出不同结果 |
| 幻觉 | 可能生成不存在的信息 |
| 延迟高 | 调用 API 通常需要几百毫秒到几秒 |
| 成本高 | 按 token 计费，高频调用贵 |
| 数学不准 | 复杂计算容易出错 |
| 不可解释 | 决策过程是黑盒 |

## 3. 核心原则：规则层是底线，LLM 是增强层

在本项目 Phase 门控下：

- **Phase A**：LLM 可用于生成文本内容（新闻、赛后点评），不直接参与核心结算。
- **Phase B3/C**：LLM 可作为 Agent 的「大脑」之一，但必须有规则模板约束。
- **Phase C/D 以后**：LangGraph 编排的 NPC、导师 AI、个性化复盘。

**绝不跳过规则层直接让 LLM 决定比赛结果。**

## 4. LLM 在游戏中的落地层次

```
Level 1: 文本生成（最稳妥）
  - 新闻标题、NPC 对话、赛后点评、任务描述

Level 2: 结构化输出
  - 生成决策建议（但由规则层最终执行）
  - 生成事件参数（由引擎校验后应用）

Level 3: Agent 决策
  - LLM 作为 NPC 的大脑，选择行为
  - 需要严格的上下文、工具调用、反思机制

Level 4: 玩家建模与个性化
  - LLM 分析玩家行为，生成个性化反馈
  - 需要长期记忆、隐私保护
```

当前项目建议从 Level 1 和 Level 2 开始。

## 5. RAG：让 LLM 知道游戏规则

RAG（Retrieval-Augmented Generation）= 检索 + 生成。

### 流程

```
用户问题 → 检索相关规则文档 → 把规则作为上下文 → LLM 生成回答
```

### 例子

玩家问：「为什么我这回合利润下降了？」

1. 检索该玩家的对局数据和相关规则。
2. 把规则片段交给 LLM。
3. LLM 生成解释：「因为原材料涨价事件使你的成本上升了 15%，而你的定价没有相应调整。」

## 6. Agent：让 LLM 调用工具

Agent = LLM + 工具 + 循环。

```
LLM 观察状态 → 选择工具 → 执行 → 观察结果 → 再选择工具 → ...
```

### 工具示例

| 工具 | 功能 |
|------|------|
| `query_player_state` | 查询玩家当前状态 |
| `submit_decision` | 提交 AI 决策（需规则层校验） |
| `generate_news` | 生成新闻 |
| `evaluate_strategy` | 评估策略优劣 |

### 框架

- **LangGraph**：适合复杂多步 Agent 流程
- **Function Calling**：OpenAI/Claude 原生支持
- **ReAct**：思考-行动-观察循环

## 7. LLM 与现有引擎的结合方式

### 方式一：LLM 生成叙事包装

```
结算结果 → LLM 生成新闻标题和描述 → 前端展示
```

例子：

```
输入：{team: "星辰科技", event: "原材料涨价", impact: -15%}
输出："受国际市场波动影响，星辰科技本季度原材料成本飙升，
      利润空间被严重挤压。"
```

### 方式二：LLM 生成决策建议

```
当前状态 → LLM 生成建议 → 规则层选择是否采纳 → 执行
```

例子：

```
输入：现金 50000，库存大米 100，当前城市南京，价格...
LLM 建议："建议将大米运往上海出售，预期利润更高。"
规则层：检查上海 bid > 南京 bid + 路费，若成立则执行。
```

### 方式三：LLM 作为 NPC 导师

```
玩家表现数据 → LLM 分析 → 生成个性化建议
```

例子：

```
"你过去三回合把太多预算花在营销上，导致技术属性落后。
建议下一回合增加研发投入，提升产品竞争力。"
```

## 8. 成本控制与性能优化

| 策略 | 说明 |
|------|------|
| 缓存 | 相同输入直接返回缓存结果 |
| 批量 | 一次请求处理多个内容 |
| 小模型 | 简单任务用 Haiku/GPT-3.5 |
| 异步 | 不阻塞核心游戏循环 |
| 离线生成 | 比赛结束后异步生成复盘 |

## 9. 与 AI 沟通示例

```
我要为 TechVenture 增加一个赛后点评功能。
约束：
- 使用 LLM 根据每队每轮数据生成 100 字以内的点评
- 输入包括：三属性变化、排名变化、关键决策
- LLM 只生成文本，不参与结算
- 结果缓存，避免重复调用
- 支持中文，语气鼓励但客观
请提供 prompt 模板和调用流程。
```
