# 技术与设计的翻译表

> 设计语言和代码语言不一样。这张表帮你在两种语言之间切换。

## 1. 通用概念

| 设计说法 | 技术说法 | 含义 |
|---------|---------|------|
| 一场比赛 | match / competition event | 比赛实例 |
| 玩家 | user / participant / player | 参赛用户 |
| 队伍 | team | 多个玩家组成 |
| 回合 | round | 离散阶段 |
| tick | tick | 实时制最小时间单位 |
| 分数 | score | 比赛表现数值 |
| 排名 | ranking / leaderboard | 按分数排序 |
| 奖励 | reward / xp | 比赛后获得 |

## 2. 实时对战

| 设计说法 | 技术说法 | 含义 |
|---------|---------|------|
| 实时刷新 | WebSocket broadcast | 服务器主动推送 |
| 倒计时 | scheduler countdown | 调度器控制时间 |
| 玩家掉线 | disconnect / reconnect | 连接断开与恢复 |
| 房间 | match room | 比赛隔离空间 |
| 机器人 | AI agent / bot | 自动决策玩家 |
| 防作弊 | server authoritative | 服务器权威 |

## 3. 后端

| 设计说法 | 技术说法 | 含义 |
|---------|---------|------|
| 存起来 | persist / write to DB | 写入数据库 |
| 查一下 | query / fetch | 查询数据库 |
| 校验 | validate | 检查参数合法性 |
| 权限 | authorization | 能否做某事 |
| 登录 | authentication | 确认身份 |
| 接口 | API endpoint / route | 前后端通信入口 |
| 返回数据 | response / DTO | 后端输出 |

## 4. 前端

| 设计说法 | 技术说法 | 含义 |
|---------|---------|------|
| 页面 | page / route | 一个 URL 对应的内容 |
| 弹窗 | modal / dialog | 浮层 |
| 组件 | component | 可复用 UI 块 |
| 状态 | state / store | 页面数据 |
| 刷新 | re-render | 界面更新 |
| 路由跳转 | navigate / push | 切换页面 |
| 加载中 | loading state | 数据未返回时的状态 |

## 6. 用翻译表写提示词

**设计原话**：

"我想做一个实时交易大厅，玩家可以在里面买卖商品，价格会波动，还有 AI 商人跟玩家竞争。"

**翻译后给 AI**：

"我要在 Phase A 范围内新增一个实时制交易赛制引擎，基于现有的 `games/trading` 架构扩展。需求：

1. 后端：新增 YAML 配置，定义商品、城市、供需曲线参数；
2. 后端：新增 engine 处理玩家买入/卖出订单，每 tick 更新价格；
3. 后端：新增 AI agent，每 tick 根据价格决策；
4. 后端：通过 `rts_scheduler` 推进 tick，HTTP 只读不写；
5. 前端：实时大厅界面，通过 WebSocket 接收 tick_update；
6. 遵守硬域边界，不直接修改 arena 表。"
