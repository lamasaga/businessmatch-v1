# POP 机制的核心设计要素

> 设计一个 POP 系统，本质上是设计一个「微观社会模拟器」。本章把 POP 拆成可独立设计的模块。

## 1. POP 的属性设计

一个 POP 至少需要以下属性：

| 属性 | 说明 | 例子 |
|------|------|------|
| 规模（Size） | POP 有多少人 | 1000 |
| 职业/阶级 | 收入来源和社会角色 | 工人、资本家、农民 |
| 财富 | 当前资产 | 存款、房产 |
| 收入 | 每期获得的金钱 | 工资、利润、救济 |
| 需求 | 需要消费的商品/服务 | 食物、衣服、教育 |
| 满意度 | 对生活状态的评估 | 生活水平、幸福感 |
| 政治倾向 | 支持什么政策/党派 | 保守、自由、激进 |
| 位置 | 在哪个地区 | 城市 A、城市 B |

## 2. 收入系统

POP 的收入来源决定其行为模式：

| 职业 | 收入来源 | 对市场波动的敏感度 |
|------|---------|-------------------|
| 工人 | 工资 | 高 |
| 农民 | 农产品收入 | 中 |
| 资本家 | 投资分红 | 中 |
| 职员 | 固定工资 | 中 |
| 失业者 | 救济/无 | 极高 |

### 工资决定因素

```
工资 = f(劳动力供需, 行业利润, 最低工资政策, 工会力量)
```

- 劳动力短缺 → 工资上升
- 行业萧条 → 工资下降或失业
- 政策干预 → 工资下限

## 3. 需求系统

### 3.1 需求层级

参考 Victoria 2/3 和马斯洛需求：

| 层级 | 需求 | 未满足后果 |
|------|------|-----------|
| 生存 | 食物、水、住所 | 死亡率上升、迁移 |
| 日常 | 衣物、家具、燃料 | 满意度下降、政治意识上升 |
| 发展 | 教育、医疗、交通 | 生产力停滞、社会流动降低 |
| 享受 | 奢侈品、娱乐 | 不满情绪积累 |

### 3.2 需求弹性

不同 POP 对价格的敏感度不同：

- 穷人：食物价格上涨 10% → 大幅减少消费
- 富人：食物价格上涨 10% → 几乎不受影响

可以用 **收入弹性** 建模：

```
需求变化率 = 基础需求 × (价格变化率 ^ 价格弹性) × (收入变化率 ^ 收入弹性)
```

## 4. 迁移机制

POP 会根据「拉力」和「推力」迁移：

### 拉力（吸引迁移）

- 高工资
- 低生活成本
- 高生活水平
- 就业机会多
- 文化/宗教宽容

### 推力（促使迁出）

- 失业
- 高生活成本
- 战争/动荡
- 歧视政策
- 饥荒

### 迁移公式（简化）

```
迁移倾向 = w1×工资差 + w2×生活成本差 + w3×就业机会差 + w4×稳定性差 + 随机扰动
```

## 5. 升级与降级

POP 的职业不是固定的，可以随经济条件变化：

```
农民 ──► 工人（工业化）
工人 ──► 职员（教育提升）
职员 ──► 工程师（高技能）
工人 ──► 失业者（工厂倒闭）
```

### 升级条件

- 识字率提高
- 有足够工作岗位
- 收入水平达标
- 满足发展需求

### 降级条件

- 长期失业
- 行业衰退
- 战争
- 灾难

## 6. 政治反馈

POP 的经济状态会转化为政治行为：

| 状态 | 政治反应 |
|------|---------|
| 生活改善 | 支持政府/现状 |
| 生活恶化但和平 | 要求改革 |
| 生活恶化 + 高不满 | 激进化、支持革命 |
| 特定阶层受益 | 支持维护自身利益的党派 |

### 政治系统需要的数据

- 各阶层的政治偏好
- 关键议题（税收、工资、教育、战争）
- 事件和宣传的短期影响
- 历史记忆的长期影响

## 7. 市场反馈

POP 的行为最终回到市场：

```
POP 收入变化 → 购买力变化 → 商品需求变化 → 价格变化
                                          ↓
                                    工厂利润变化 → 投资/裁员 → POP 收入变化
```

这就是微观到宏观的闭环。

## 8. 性能设计

大量 POP 模拟可能很耗性能。常用优化：

| 技术 | 说明 |
|------|------|
| 聚合 POP | 相同属性的 POP 合并成一个组 |
| 离散事件 | 只在关键事件时更新，不用每 tick 全量计算 |
| 分区计算 | 不同城市/区域独立计算 |
| 近似公式 | 用分布函数代替逐个 POP 计算 |
| 后台批处理 | 把 POP 更新放到独立任务 |

## 9. 与 AI 沟通示例

```
我要设计一个 POP 系统，包含以下模块：
1. POP 属性：规模、职业、收入、财富、需求、满意度、政治倾向、位置
2. 收入系统：工资、分红、救济
3. 需求系统：生存/日常/发展/享受四级需求
4. 迁移系统：基于工资、生活成本、就业机会
5. 升级/降级系统：农民→工人→职员→工程师
6. 政治反馈：满意度→支持/改革/激进
7. 市场反馈：收入→需求→价格→利润→投资→就业

请给出数据结构和每轮更新流程，
并说明如何聚合相同属性 POP 以优化性能。
```
