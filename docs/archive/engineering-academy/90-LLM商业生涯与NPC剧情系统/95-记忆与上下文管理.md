# 记忆与上下文管理

> 本章设计 NPC 和商业世界的记忆系统：短期记忆、长期记忆、记忆检索、上下文压缩，以及如何让 LLM 看到正确的历史。

## 1. 为什么记忆如此重要

没有记忆的 NPC：

- 每次对话都像第一次见面。
- 不会记得玩家的承诺或背叛。
- 行为不连贯。

有记忆的 NPC：

- 能 references 过去的事件。
- 会根据历史调整态度。
- 能产生长期故事线。

## 2. 记忆类型

### 2.1 短期记忆（Short-Term Memory, STM）

- 最近几回合内发生的事件。
- 详细、具体。
- 容量有限。

例子：

```
- 上回合玩家承诺投资 50 万
- 昨天玩家挖走了我的技术总监
- 本周公司现金流紧张
```

### 2.2 长期记忆（Long-Term Memory, LTM）

- 经过多次压缩的洞察。
- 抽象、概括。
- 容量大，持久。

例子：

```
- 玩家是一个言而无信的人
- 我们曾在 2023 年合作过一个成功项目
- 云图科技喜欢通过挖角获取人才
```

### 2.3 语义记忆（Semantic Memory）

- 关于世界的一般知识。
- 不绑定具体时间。

例子：

```
- 云图科技是行业领先公司
- 张三是技术天才
- 2025 年行业发生了大洗牌
```

### 2.4 程序记忆（Procedural Memory）

- 技能和习惯。
- 影响行为方式。

例子：

```
- 张三擅长谈判
- 李四做决定很慢
```

## 3. 记忆数据结构

```python
class Memory:
    id: str
    npc_id: str
    timestamp: datetime
    type: str                    # event, insight, fact, feeling
    category: str                # business, personal, social, crisis
    
    # 内容
    raw_event: str               # 原始事件描述
    summary: str                 # 压缩摘要
    emotional_tag: str           # 正面/负面/中性
    importance: float            # 0-1
    
    # 关联
    related_npcs: list           # 相关 NPC IDs
    related_companies: list      # 相关公司 IDs
    related_topics: list         # 主题标签
    
    # 状态
    is_consolidated: bool        # 是否已压缩到 LTM
    last_accessed: datetime
    access_count: int
```

## 4. 记忆生成

### 4.1 事件记忆

每次重要交互生成一条事件记忆：

```python
def create_event_memory(npc, event):
    return Memory(
        npc_id=npc.id,
        type='event',
        raw_event=event.description,
        summary=llm_summarize(event.description, max_length=50),
        emotional_tag=event.emotional_impact,
        importance=event.importance,
        related_npcs=event.involved_npcs,
        related_companies=event.involved_companies,
        related_topics=event.topics
    )
```

## 5. 记忆压缩

### 5.1 何时压缩

- 短期记忆积累到一定数量。
- 过一回合后。
- 当 NPC 需要「反思」时。

### 5.2 如何压缩

用 LLM 把多个事件总结成洞察：

```python
def consolidate_memories(memories):
    prompt = f"""
    请根据以下事件，总结 {npc.name} 对某人的印象和态度：
    {memories}
    
    输出格式：
    - 印象：[一句话]
    - 信任度：[高/中/低]
    - 预期行为：[一句话]
    """
    return llm_generate(prompt)
```

## 6. 记忆检索

### 6.1 检索策略

当 NPC 需要与玩家对话或做决策时，检索相关记忆：

```python
def retrieve_relevant_memories(npc, context):
    # 1. 最近事件
    recent = get_recent_memories(npc, limit=10)
```

## 7. 上下文管理

### 7.1 LLM 上下文窗口有限

不能把全部记忆都塞进 prompt。需要：

- 选择最相关记忆。
- 压缩摘要。
- 分层组织。

### 7.2 上下文结构

```
【世界背景】行业、城市、当前形势
【NPC 自身】身份、性格、目标、当前状态
【与玩家关系】关系强度、信任度、共同历史摘要
【相关记忆】5-10 条关键事件
【当前情境】触发本次交互的事件
【规则约束】不能做什么
```

### 7.3 上下文长度控制

```python
MAX_CONTEXT_TOKENS = 3000

context = build_context(npc, situation)
while estimate_tokens(context) > MAX_CONTEXT_TOKENS:
    # 先压缩旧记忆
```

## 8. 遗忘机制

不是所有记忆都永久保留：

- 低重要性记忆随时间淡化。
- 高频访问记忆更持久。
- 情感强烈的记忆更难遗忘。

```python
def memory_decay(memory, current_time):
    time_passed = current_time - memory.timestamp
    decay_rate = 0.01 * time_passed.days
    
    # 情感强烈更难忘
    if abs(memory.emotional_tag) > 0.5:
        decay_rate *= 0.5
    
    # 频繁访问更难忘
    decay_rate /= (1 + memory.access_count * 0.1)
    
    memory.importance = max(0, memory.importance - decay_rate)
```
