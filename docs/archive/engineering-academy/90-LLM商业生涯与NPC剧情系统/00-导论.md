# LLM 商业生涯与 NPC 剧情系统导论

> 本文档提出一个「异步状态机 + LLM 大模型」驱动的商业生涯、公司经营、商业竞争体验系统方案。
> 目标：让玩家/学习者在与自由 NPC 的互动中，获得真实、动态、有故事感的商业世界体验。

## 1. 我们要设计什么

一个融合以下要素的系统：

- **自由 NPC**：每个 NPC 有性格、目标、记忆、关系网，不只是任务发布器。
- **异步状态机**：NPC 在玩家离线时也在运行，持续演化。
- **LLM 增强**：为 NPC 提供自然语言对话、叙事生成、情境推理能力。
- **商业生涯**：玩家从职员/创业者成长为企业家/投资人。
- **公司经营**：创办、管理、扩张公司，面对真实商业决策。
- **商业竞争**：与 NPC 公司争夺市场、人才、资源、政策。

## 2. 核心体验

### 2.1 像 CK3 一样有「人」

在 CK3 中，你不是在统治一个国家，而是在扮演一个活生生的人：

- 你有性格特质（勇敢、贪婪、忧郁）。
- 你有家庭、朋友、宿敌、情人。
- 你会被压力、秘密、阴谋驱动。
- 你的继承人会继承你的遗产，也会有不同性格。

我们要把这种「人的戏剧感」搬到商业世界：

- 你不是在经营一个抽象公司，而是在扮演一个商业人物。
- 你有导师、合伙人、竞争对手、叛徒、投资人。
- 你有压力、野心、道德困境。
- 你的职业生涯会影响后代/继任者。

### 2.2 像太吾绘卷一样有「江湖」

太吾绘卷的 NPC 有自己的目标和人生轨迹，会自主行动：

- NPC 会拜师、结婚、复仇、远走高飞。
- 世界在玩家不在时也继续演化。
- 奇遇和事件从人物关系中生长出来。

我们要让商业世界 similarly 自主运转：

- NPC 会创业、跳槽、结盟、背叛、退休。
- 公司会兴衰、并购、破产。
-  player's absence 时，NPC 也在竞争。

### 2.3 像 RimWorld/Dwarf Fortress 一样有「故事生成」

RimWorld 称自己为「故事生成器」：

- 小事件通过人物关系和系统互动放大成故事。
- 一个角色的死亡可能引发连锁反应。
- 玩家是故事的发现者和叙述者。

我们要让商业世界也产生这样的故事：

- 一次投资失败 → 合伙人反目 → 公司分裂 → 竞争对手挖角 → 整个行业格局变化。
- 一个关键员工离职 → 项目延期 → 客户流失 → 现金流危机。

## 3. 系统架构概览

```
┌─────────────────────────────────────────┐
│  前端：角色、公司、关系网、对话、事件界面  │
├─────────────────────────────────────────┤
│  API 层：状态查询、决策提交、对话接口      │
├─────────────────────────────────────────┤
│  异步状态机引擎：NPC 自主演化和事件推进    │
├─────────────────────────────────────────┤
│  LLM 层：对话生成、叙事包装、推理辅助      │
├─────────────────────────────────────────┤
│  商业模拟层：公司、市场、财务、竞争规则    │
├─────────────────────────────────────────┤
│  数据库：角色、公司、关系、记忆、事件      │
└─────────────────────────────────────────┘
```

## 4. 关键设计原则

### 4.1 状态机是骨架，LLM 是血肉

- **状态机**：保证 NPC 行为可预测、可调试、可复现。
- **LLM**：负责自然语言、情境化表达、复杂推理。

LLM 不直接决定核心商业结果，而是：

- 把状态机的输出「翻译」成自然语言。
- 根据上下文生成有性格的回应。
- 帮助包装事件，增强叙事感。

### 4.2 异步演化

NPC 和商业世界在玩家不在线时也继续运行。

实现方式：

- 后台调度器定期推进 NPC 状态。
- 玩家上线时看到「离线期间发生了什么」。
- 关键事件通过通知推送。

### 4.3 关系网驱动剧情

商业世界的故事从关系中生长：

- 信任、背叛、竞争、合作。
- 师徒、合伙人、竞争对手、投资人。
- 家族/派系/联盟。

### 4.4 可教学、可娱乐

系统既要有游戏性，也要有教育价值：

- 学生能理解商业决策的人际后果。
- 能学习谈判、领导力、商业伦理。
- 能观察市场动态和竞争策略。

## 5. 与当前项目的关系

本方案是**长期愿景**，与 Phase 门控对齐：

- **Phase A/B**：可在现有引擎中局部引入 LLM 叙事包装、赛后点评、NPC 对话。
- **Phase C/D**：引入 LangGraph Agent、长期记忆、关系网。
- **Phase E**：完整的 OPC LangGraph + MCP 商业生涯系统。

本方案为后续 Phase 提供设计蓝图。

## 7. 边界声明

本方案**不做**：

- 完全开放的 LLM 自由对话（成本、可控性、安全性问题）。
- 替代现有赛事引擎的核心结算。
- 跨 Phase 立即实现全部功能。

本方案**做**：

- 提供渐进式引入 LLM + 状态机的路线图。
- 确保每个 LLM 调用都有规则约束和回退方案。
- 优先服务于教学和叙事体验。
