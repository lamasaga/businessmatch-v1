# POP-拟真城市方案总览

> 本文档提出一个可落地的「POP-拟真城市」系统方案：用微观 POP（人群组）驱动城市经济运行，让玩家/学习者的决策通过 POP 的反馈涌现出宏观城市规律。
> 方案目标：**足够具体，能直接指导代码实现**。

## 1. 方案定位

### 1.1 我们要做什么

构建一个**以 POP 为核心的拟真城市经济模拟系统**：

- 城市由大量 POP、企业、土地、交通、政策组成。
- POP 有职业、收入、需求、位置、满意度、政治倾向。
- 玩家/学习者可以扮演政府、企业、投资者或市民领袖。
- 任何决策都会通过 POP 行为反馈，涌现出宏观结果。

### 1.2 核心体验

```
微观：每个 POP 都在做简单决策（上班、消费、搬家、投票）
    ↓
中观：社区形成、产业布局、交通拥堵、房价分化
    ↓
宏观：GDP、失业率、通胀、贫富差距、城市扩张、社会情绪
```

### 1.3 与现有项目的关系

本方案是一个**独立的拟真城市引擎**，可作为一个新的 game engine 接入平台：

- 路径：`webapp/backend/app/games/city_sim/`（建议）
- 配置文件：`content/game-configs/city-sim-v1.yaml`
- 复用 Arena 生命周期（创建、报名、回合推进、结算、奖励）
- 不污染现有 trading/techventure/ops_sim 引擎

## 2. 设计原则

### 2.1 微观规则简单，宏观涌现复杂

每个 POP 只遵循 3-5 条规则。城市复杂性来自数量和互动。

### 2.2 全链路闭环

```
玩家决策
    ↓
影响 POP 的收入、成本、机会
    ↓
POP 改变行为（消费、工作、居住、迁移、投票）
    ↓
市场/城市状态变化
    ↓
反馈给玩家下一回合决策
```

### 2.3 可解释、可教学

所有宏观指标必须能追溯到微观 POP 行为。学生能看到「因为工人收入下降，所以消费减少，所以企业裁员，所以失业上升」。

### 2.4 与 Phase 门控对齐

- **Phase A**：完成单场比赛内的拟真城市 MVP，不跨比赛持久化城市状态。
- **Phase B 以后**：考虑跨赛季的持久世界、营团城市、家园系统。

### 2.5 性能可控

通过 POP 聚合、事件驱动更新、分区计算，控制单场比赛 POP 规模在 5000-10000 以内。

## 5. 方案边界

本方案**不做**：

- 实时 3D 城市渲染（可用抽象地图）
- 精确预测真实城市
- 跨比赛持久世界（Phase A 范围）
- LLM Agent 直接决策城市政策

本方案**做**：

- 单场比赛内的拟真城市经济模拟
- 可解释的微观→宏观涌现
- 教学导向的可视化和案例
- 为后续持久世界打基础
