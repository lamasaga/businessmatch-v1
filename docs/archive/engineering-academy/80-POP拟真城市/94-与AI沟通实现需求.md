# 与 AI 沟通实现需求

> 本章提供向 AI 描述 POP-拟真城市实现需求时的模板和关键词。

## 1. 描述 POP-拟真城市需求的结构

```
【目标】这个 POP-拟真城市要实现什么教学/游戏体验
【范围】单场比赛还是持久世界；回合制还是实时制
【玩家角色】市政府、企业家、投资者、劳工领袖、市民代表
【POP 设计】类型、属性、行为规则
【空间设计】地块、区域、土地利用
【经济循环】家庭-企业-政府-银行-外部市场
【政策工具】税收、补贴、基础设施、劳动法规、zoning
【宏观指标】GDP、失业率、通胀、基尼系数、满意度
【技术约束】POP 数量、地块数量、结算时间、Phase 门控
【验收】可运行的 MVP 标准
```

## 3. 提示词模板

### 模板一：设计 POP-拟真城市 MVP

```
我要在商识唯智平台新增一个 POP-拟真城市引擎。

目标：
让学生理解「玩家决策 → POP 行为 → 宏观涌现」的过程。

范围：
- 单场比赛，10 回合，每回合 1 年
- 回合制推进
- Phase A，不跨比赛持久化城市状态

玩家角色：
- 市政府：税收、基础设施、公共服务、zoning
- 企业家：建厂、雇佣、定价、投资
- 投资者：买地、开发房地产

POP 设计：
- 类型：低技能工人、高技能工人、专业技术人员、资本家、退休人员
- 属性：收入、财富、住房、满意度、政治倾向
- 行为：消费、就业、迁移、升级

空间：
- 10×10 地块网格
- 区域：CBD、工业区、住宅区、港口区
- 土地利用由竞租决定

经济循环：
- 家庭提供劳动力，消费商品
- 企业雇佣劳动力，生产商品
- 政府收税、提供服务
- 银行提供贷款

宏观指标：
- GDP、失业率、通胀率、基尼系数、平均满意度、房价指数

技术约束：
- 聚合 POP 不超过 500 组
- 每回合结算 < 2 秒
- 使用 SQLAlchemy 2.0
- 遵守硬域边界，不跨域写入 Arena 表

请给出：
1. 目录结构
2. 数据库模型
3. YAML 配置草案
4. 结算流程伪代码
5. 与 Arena 集成的接口设计
```

## 4. 常见错误

| 错误 | 后果 | 改进 |
|------|------|------|
| "做一个真实城市模拟" | 范围无限扩大 | 明确单场比赛、10-20 回合 |
| "POP 要做到个人级别" | 性能爆炸 | 使用聚合 POP |
| "所有机制一期做完" | 无法落地 | 分 Phase 实现 |
| "只做经济不做空间" | 失去城市特色 | 必须有地块和可达性 |
| "事件随机发生无规律" | 不可教学 | 事件应有触发条件和因果链 |
| "宏观指标不可追溯" | 无法解释 | 每个指标都能追溯到 POP |
| "LLM 直接控制城市政策" | 不可控 | LLM 只生成叙事文本 |

## 5. 验收清单

### MVP 验收

- [ ] 能创建一场比赛
- [ ] 能推进回合
- [ ] POP 有基本属性
- [ ] 企业能雇佣和生产
- [ ] 市场能清算价格
- [ ] 能计算 GDP、失业率等宏观指标
- [ ] 玩家决策能影响城市状态
- [ ] 前端能展示城市地图和指标

### 完整版验收

- [ ] 所有子系统运行稳定
- [ ] 能观察到至少 3 种涌现现象
- [ ] 事件系统正常工作
- [ ] 教学案例可运行
- [ ] 性能满足目标
- [ ] 文档和测试完整
