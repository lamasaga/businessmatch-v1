# 美术工作流与工具链

> 美术不是「画完扔过去」就行，而是要有规范的交付流程。本文讲从设计到前端可用的完整工作流。

## 1. 工作流概览

```
策划需求 → 美术设计 → 内部评审 → 切图导出 → 前端对接 → 验收
```

## 2. 常用工具

| 角色 | 工具 | 用途 |
|------|------|------|
| 策划 | 飞书文档 / Notion | 写需求、贴参考图 |
| UI 设计 | Figma | 界面设计、原型、切图标注 |
| 插画/立绘 | Photoshop / Procreate | 高精度美术图 |
| 像素/序列帧 | Aseprite | 像素画、动画帧 |
| 矢量 | Illustrator / Figma | SVG 图标、UI |
| 骨骼动画 | Spine / Live2D | 角色动画 |
| 动效 | After Effects | Lottie、视频 |
| 版本管理 | Git / 坚果云 / 飞书云盘 | 文件同步 |

## 3. Figma 交付规范

Figma 是现代 UI 设计最常用的工具。交付给前端时，应包含：

- **页面结构**：Frame 命名清晰
- **组件（Component）**：按钮、输入框等做成可复用组件
- **样式变量（Variables）**：颜色、字号、间距用变量
- **自动布局（Auto Layout）**：告诉前端哪些区域是弹性伸缩
- **切图**：导出 PNG / SVG 时设置好倍数
- **标注**：间距、字号、颜色值明确

## 4. 导出设置

| 类型 | 格式 | 设置 |
|------|------|------|
| 图标 | SVG | 保留可编辑性 |
| 图标高清 | PNG | 2x |
| 按钮 | SVG / PNG | 提供 default/hover/active/disabled |
| 面板 | PNG 9-patch | 提供 slice 数据 |
| 人物 | PNG | 透明背景 |
| 动画 | Lottie JSON / Sprite Sheet | 提供帧率和循环设置 |

## 5. 版本管理

美术文件大、多，建议：

- 文件名带版本号：`ui_panel_v01.png`
- 重大版本改号：`v01` → `v02`
- 不要覆盖旧版本，保留备份
- 使用 `assets-manifest.json` 记录当前使用版本

## 6. 与程序对接

美术交付后，前端/后端需要：

1. 把资源放入正确目录
2. 在代码中引用（不要写死路径，用配置或 manifest）
3. 测试不同分辨率显示
4. 检查加载性能

## 7. 验收清单

- [ ] 尺寸和分辨率符合规范
- [ ] 透明背景正确
- [ ] 命名符合规范
- [ ] 提供了所有状态图
- [ ] 提供了 assets-manifest.json
- [ ] 文件大小在合理范围
- [ ] 在前端实际显示无错位
